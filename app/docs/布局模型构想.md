# 布局模型构想：向 HTML 借一点

> 目标不是做成浏览器，而是把「段落 / 盒子 / 容器」这三件事分清楚，
> 让宽对象、表格、将来的分栏和多图排版共用一套规则。

## 一、现有模型（起点）

```
UmeLayout::relayout()
  ├─ 逐块遍历 QTextDocument
  ├─ 普通块 → QTextLayout 一条条 line → 每列一个 Column
  └─ 宽对象（表格 / 图片）→ 一个矩形 WideItem，横跨 K 列
```

- 一「列」= 一个 `QTextLayout` 的 line，宽度 = 可用高度（竖排）；
- 列宽 = 这一列里最宽的字形 + 留白；
- 宽对象参与两件事：占位（`safeX`）与遮挡（`freeTopFor`）。

**问题**：宽对象只有「一个矩形」这一个概念。
它不知道自己内部怎么排（表格靠 `paintTableCells` 现场画），
也没法表达「盒子里再放盒子」。

## 二、要借的三个概念

### 1. 盒子模型（Box Model）

```
┌─────────────── margin ───────────────┐
│ ┌───────────── border ─────────────┐ │
│ │ ┌─────────── padding ──────────┐ │ │
│ │ │          content             │ │ │
│ │ └──────────────────────────────┘ │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

竖排下唯一的区别是**语义**：`block-start / block-end`（列方向）与
`inline-start / inline-end`（行方向），而不是物理的 left/right。

对 `writing-mode: vertical-rl`：

| CSS 写法 | 竖排含义 |
|---|---|
| `margin-block-start` | 列顶 |
| `margin-inline-start` | 列右（自右向左时） |
| `padding` | 文字与盒子边的距离 |

**收益**：现在的宽对象只支持「高度」和「跨列数」，没有内边距概念，
表格文字贴着边框画。盒子模型能一次解决这类问题。

### 2. `display: block` 与段落

竖排里 block 的推进方向是 **x（列方向）**：

```
block1  block2  block3
┌──┐    ┌──┐    ┌──┐
│文│    │文│    │文│
│字│    │字│    │字│
└──┘    └──┘    └──┘
```

这就是我们现在的「一个块 = 若干列」，已经成立。
需要补的是：**块也可以是一个容器**（不是纯文字），
此时块的高度由内容决定，宽度由容器的规则决定。

### 3. 容器：`flex` / `grid`

用户草图里的「复合盒子」：

```
┌──────────────────┐
│ ┌────┐ ┌───────┐ │   grid: 两行？
│ │ 图 │ │       │ │
│ └────┘ │  图   │ │
│ ┌────┐ │       │ │   flex: 上下叠
│ │ 图 │ └───────┘ │
│ └────┘           │
└──────────────────┘
```

两种容器足以覆盖绝大多数版面：

| 容器 | 规则 | 竖排下的方向 |
|---|---|---|
| **flex**（单行/单列） | 子项沿 inline 轴排，超出沿 block 轴换行 | 先上下排，满了往左/右换列 |
| **grid**（轨道） | 固定行列数，单元格等分或按内容 | 列 = 轨道，行 = 轨道 |

表格其实就是 **grid 的特例**（轨道等分 + 单元格各自竖排）。
现在的 `paintTableCells` 已经是「每个单元格独立跑一遍 QTextLayout」——
这正是 grid 容器需要的能力，只是还没被抽象出来。

## 三、映射到现有代码

| HTML 概念 | UME 里对应 | 现状 |
|---|---|---|
| `<p>` | 一个 `QTextBlock` + 若干 `Column` | ✅ 已有 |
| 行内文字 | `QTextLayout` 的 line | ✅ 已有 |
| 原子盒子（图片） | `WideItem{kind=Image}` | ✅ 已有 |
| `grid` 容器 | 表格 | ⚠️ 只有「等分轨道 + 单元格文字」，没有 padding / 跨格 |
| `flex` 容器 | —— | ❌ 缺 |
| 盒子模型 | —— | ❌ 缺（只有 heightPt / span） |
| `display: block` | 块推进 | ✅ 已有（列方向） |
| 嵌套容器 | —— | ❌ 缺，见下 |

## 四、难点（要诚实）

1. **文档模型**：`QTextTable` 那种层级是 Qt 内建的，
   自定义嵌套盒子没有现成载体。可选：
   - (a) 继续借用 `QTextTable`（单元格里放图片块 = 1×N 表格）—— 廉价但别扭；
   - (b) 在 `WideProps` 上挂一棵「布局树」，内容仍是段落，靠块位置引用 —— 干净，但要自己维护增删；
   - (c) 自建 `UmeBox` 文档结构 —— 最彻底，也最贵（等于重写文档层）。
2. **分页**：HTML 不关心分页；我们必须把容器切成跨页的碎片。
   表格已经这么做了（按行高切），flex 容器要同样处理。
3. **竖排的 flex/grid 语义**：CSS 的 `row`/`column` 在 `vertical-rl` 下会互换含义，
   文档里必须写清楚「inline 轴 / block 轴」，不能照抄 row/column 的名字。
4. **性能**：布局树每帧重算的成本要控制，容器内部要有自己的缓存键。

## 五、建议的推进顺序（每步都能单独验收）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0** | 宽对象加盒子模型（margin / padding / border） | 表格文字不再贴边；图片可有内边距 |
| **P1** | 抽出 `Box` 接口：`layout(constraint) → fragments` | 表格与图片都走同一接口，绘制层不再特判 |
| **P2** | `grid` 容器通用化（轨道可不等分、可跨格） | 2×3 表格 + 一张图混排 |
| **P3** | `flex` 容器（单轴、可换行） | 三张图上下叠、超出自动换列 |
| **P4** | 嵌套（容器里放容器） | 盒子套盒子，套两层还能正确分页 |

**P0 一天可完成**，且立刻能看见效果；P1 是重构，风险中等；
P2/P3 才涉及文档模型的选择；P4 视需要再决定。

## 六、不做的事

- 不做 `float`、`position: absolute`、`z-index` 这类与分页冲突的东西；
- 不做 CSS 选择器与样式表 —— 样式挂在块格式上就够了；
- 不做任意嵌套深度（先限 2 层），避免文档模型过早复杂化。
