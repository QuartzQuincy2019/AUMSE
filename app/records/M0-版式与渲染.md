# M0 版式与渲染

## 列与列之间空得像隔了一条街

**现象** 自动列距 34pt（14pt 字），列间空白过大。

**错因** 直接用了 `QFontMetricsF::height()`，它包含行距。

**修法** 取 `max(字号 × 1.7, 墨迹宽 × 1.3)`，14pt 下得 32.5 → 后来按列内容定宽后不再使用。

## 墨迹越过左侧页边距

**现象** 三支字体首列墨迹左缘都压进页边距，Noto 最严重。

**错因** 基线偏移用 `tightBoundingRect` 的紧墨迹算，但 `tightBoundingRect` 量的是
**孤立形**，实际排版用上下文形，字形更宽。Noto 实测差 8.7pt。

**修法** 基线偏移改用字体的**名义 ascent/descent**。实测三支字体墨迹左缘
58.5 / 59.5 / 60.0pt，均未越过 56.7pt 的页边距。

## 改字号后这一列不撑开，大字压到右邻列

**现象** 把几个字改到 80pt，字越界压到右边那一列上。

**错因** 两处叠加：① `mergeFormatIntoSelection()` 只重绘、**没有重排**；
② 列宽用 `tightBoundingRect`（孤立形），大字号时偏小。

**修法** 改格式后立刻 `relayout()`；列宽改用名义行高 `ascent + descent`。
实测 80pt：列宽 25 → 120，右邻列 left 94.7 → 176.7，左边界 56.7 不变。

## 行末最后一个字被推到页面底部

**现象** 一列末尾的汉字出现在很远的下方。

**错因** 最后一个字形没有「下一个字形」可用，代码退化成
`qMax(line.width(), naturalTextWidth()) - x`。`line.width()` 是**换行宽度**
（整列高 728px），拿它当槽位就把字推到列底。

**修法** 用 `line.naturalTextWidth() - x`，并再与字形自身推进量取小。

## 每列只排到 75% 就换行

**现象** 一列还没写满就换列。

**错因** `QTextLayout` 的宽度单位是 **96dpi 像素**，页面是 **pt**。
`line.setLineWidth(729)` 被当成 729px = 547pt 用。

**修法** `lineWidthPx = textHeight / (72.0/96.0)`。
实测 971.45px = 728.6pt，第 1 页墨迹纵向 57.0–772.0pt（正文区 56.7–785.3）。

## 列宽与字形的横向位置对不上（高亮在左、字在右）

见 M1「选区高亮与字形错位」——根因同一个，统一由 `columnInkLeft()` 决定。

## 宽对象右缘压在条带边界上，后面的文字整段消失

**现象** 插入一个跨 4 列的图片后，它右边的文字一个都不显示。

**错因** 对象占位按「条带」算：`s1 = stripOf(x + w)`。当 `x + w` 正好落在条带边界，
下游那一条也被标成「已占满」，接着排的文字在自己的条带里拿到 **0 高度**。

**修法** 计算右缘时减 0.01：`stripOf(x + w - 0.01)`，只占真正压住的那几条。

## 文字被画到页面外（列底之下）

**现象** 页面正文区下方、纸面之外出现一排横向叠着的文字。

**错因** 宽对象引入的「条带游标」模型假设列宽相等。实际列宽按内容变化，
一列常常跨两条带并在边界上多占一条；下游列于是读到「本条带已到列底」，
把列顶算成页面底部 —— 列高为 0，文字被画到纸外。

**修法** 丢掉条带模型，改成朴素规则：**只让宽对象把与它 x 重叠的列往下推**。

```
freeTopFor(x0, x1) = max(正文区顶, 与该 x 区间重叠的宽对象的下沿)
```

文字列不再写游标，所以列宽不等也不会互相干扰。
实测 30 段文档：墨迹 y 57.0–121.0 pt（正文区 56.7–785.3），不再越界。

## 表格（宽对象）压住正文

**现象** 表格跑到页面最左边，和正文列叠在一起。

**错因** 放置规则只做了「文字避开对象」，没做「对象避开文字」。
文档里文字在前、对象在后时，对象按当时的 `x` 落下，正好压回已经排好的列上。
（日志里同时能看到图片被拖成 `span=12`、`off=-129`，多对象还会互相重叠。）

**修法** 对象落位前先把 `x` 推到安全位置：

```cpp
safeX = max( 当前 x,
             同页所有文字列的右缘,
             同页所有宽对象的右缘 )        // 遮挡关系一律「对象往右让」
x = max(x, safeX);
```

配合原有的「文字若与对象 x 重叠，就从对象下沿开始」，两个方向都成立，
无论文档里谁在前谁在后，都不会叠在一起。

`WideItem` 也补了 `page` 字段，避让只在同一页内生效。

实测（三段文字 + 2×3 表格，表格拖到 −120pt）：
文字列 56.7 / 85.7 / 114.7，表格落在 **143.7**（= 第三列右缘），不再重叠。

## 对象/列宽超过正文区，把内容挤到第二、三页

**现象** 图片被拉宽或跨列数设得很大时，后面的内容被挤到下一页、再下一页。

**错因** 宽度只在**布局里临时**被 qBound 到正文区宽，span 本身没被限制。
于是「面板上写着 span=40」而实际只画到页宽，拖动/缩放还会继续加大，
每加一次就把后面的内容往外挤一页。

**修法** 把上限变成一处权威值 UmeView::maxSpanForPage()：

`
maxSpan = floor(正文区宽 / 最小列宽)      // 当前页 481.6 / 25 → 19
`

- pplyWideObject()、拖曳缩放、
esizeWideObject() 全部用它钳制 span；
- 排版层再把 w 与文本列宽都硬钳到正文区宽（超大字号时列可能很宽）。

实测：请求 span=40 → 实际 19；盒子 x 56.7–531.7，正文区 56.7–538.3，不越界。

## 调宽度时对象在「本页右侧」和「下一页左侧」之间反复跳

**现象** 拖动图片的宽度手柄，图片一会儿在文字右边、一会儿跑到下一页页首，来回跳。

**错因** 放置逻辑只有「放不下就换页」：宽度一越过当前列剩余空间就 
esetFlow()
换到下一页；往回拖一点又回到本页。宽度是连续变化的，于是页面来回翻。

**修法** 换成「**先就地收窄**，实在放不下才换页」：

`
remain = 正文区右缘 − 当前 x
若 w > remain 且 remain ≥ max(2 列宽, 40pt)  →  w = remain（留在本页）
否则                                        →  换页
`

配合「宽度上限 = 正文区宽」，图片永远不越出页边距，也不会因为一点点变宽就跳页。

实测：span 从 4 连续加到 18，落位恒定 x=115，宽度 100→150→…→400→**424**（到边就收窄），
页号始终为 1。

## 第二个对象被「差几个 pt」挤到下一页，来回跳

**现象** 加宽第一张图时，旁边那张小图一会儿留在本页、一会儿跳到第二页。

**错因** 「就地收窄」的准入条件是 `remain >= max(2 列宽, 40pt)`。
两张图相邻时，剩余空间常常正好卡在 40–50pt 之间：第一张宽一点点、
剩余空间掉到 40 以下，第二张就被甩到下一页；缩回去又回来。

**修法** 下限降到「一列宽或 20pt」（`max(stripW, 20)`）：只要还剩一点空间就收窄、
留在本页，不再因为几个 pt 抖动就换页。

实测：两张图并存，第一张 span 8→20 全程 `x=85.7` 不动；第二张只在
第一张占满整行（w=452.6，右缘 = 正文区右缘）时才换到下一页。

另外修了调试日志的占位符：`"snap height %.1f → %.1f"` 是 printf 写法，
`QString::arg` 不认，改成 `%1/%2` 后才打印出真实数值。

## 一长串文字不换列，直接溢出页面

**现象** 一直敲同一个字母（比如一长串 `h`），文字从页首一路画到页外，
列数始终不增加。

**错因** 我们手工 `beginLayout()` 时用的是 `QTextLayout` 的**默认** textOption，
其换行模式是 `WordWrap` —— 只在**词边界**断开。`hhhh…` 是一整「词」，
宽度再超也不断，于是全部挤在一条 line 里，最后被列裁剪吃掉或画到页外。

（`QTextDocument` 自己排版时用的是 `WrapAtWordBoundaryOrAnywhere`，
所以我们平时感觉不到这个差别。）

**修法** 排版前统一设成 `QTextOption::WrapAnywhere` ——
竖排里本来就没有「西文单词不可断」的概念：

```cpp
QTextOption opt = lay->textOption();
opt.setWrapMode(QTextOption::WrapAnywhere);
lay->setTextOption(opt);
```

单元格内的竖排排版也一并设置。

另外给绘制加了**列裁剪**兜底：坐标算错也不会画出页边距。

实测：200 个 `h`（约 1540pt，正文区高 728.6）→ 换成 3 列
（56.7 / 81.7 / 106.7），墨迹最下 774.0（≤785.3），不越界。

## 文本环绕：绕过去的列全被钉在对象下沿

**现象** 「文本环绕」时，对象右侧有一大片空白，后面的文字全挤在对象下方，
不会回到页首继续排。

**错因** 一个块的所有 line 共用了**块首**算出来的 `top`：

```cpp
const qreal top = freeTopFor(块首 x 区间);   // 块首被对象压住 → 下沿
...
c.box = QRectF(x, lineTop /* == top */, colW, ...);   // 每一列都从下沿开始
```

只有当列的 x 区间**与对象重叠**时才应该下移；一旦 x 越过对象右缘，
这一列应当回到页首。

**修法** 每条 line 各自算空闲顶部：

```cpp
const qreal lineTop = freeTopFor(x, x + colW);   // 逐列判断
```

实测（图片 x81.7–181.7、y56.7–656.7，400 个 h）：
图片右侧共 20 列，**20 列全部回到页首**（改前全部贴在 656.7 之下）。

## 多页排布与纸张方向

**需求** 默认「N 页横向排列，N=2」；视图菜单可选三种排布 + 纸张方向。

**做法** 把「页在内容坐标里的位置」抽成纯函数：

```cpp
pageRectOf(page, i, arrangement);      // 第 i 页的矩形（含页间距 24pt）
contentSizeOf(page, pageCount, arr);   // 所有页合起来多大
```

- `Horizontal`：`col = i`
- `Vertical`：`row = i`
- `RowsOfN`：`col = i % perRow`，`row = i / perRow`

画布尺寸、滚动条范围、`renderAllPages()` 全部走这两个函数，
所以显示 / 滚动 / 导出天然一致。

**纸张方向**：`PageSetup::setOrientation()` 对调纸张宽高，并**互换左右与上下页边距**
（页边距是物理四边，横竖切换时互换更符合直觉）；重复设置同方向不会来回翻。

**横排内容会宽于窗口** → 补了横向滚动条（`m_hbar` / `m_scrollX`），
`docPosFromWidget()` 同时加 `m_scrollX`。

实测：4 页 A4 → 2×2 时 `p0(0,0) p1(619,0) p2(0,866)`，内容 `1214×1708`；
无限横向 `2452×842`；无限竖向 `595×3440`；纵向 595×842 → 横向 842×595。

## 宽对象画到别的页上（第 2 页的图跑到第 1 页）

**现象** 插第二张图后，两张图挤在同一页甚至跨过页缝；光标却停在第二页左上角。

**错因** 宽对象的 `box` 存的是**页内坐标**（排版时按正文区算的），
但 `paintWideItems()`、手柄、命中都直接把它当**内容坐标**用：

```cpp
const QRectF r = item.box;      // 少了「该页原点」的偏移
```

只有一页时页原点 = (0,0)，所以一直没暴露；一进入第二页就整体错位。

**修法** 布局层提供换算，绘制/手柄/命中统一走它：

```cpp
QPointF UmeLayout::pageOrigin(int page) const;
QRectF  UmeLayout::docRect(const WideItem &item) const;   // box + 页原点
QRectF  UmeLayout::docRect(const Column &c) const;
```

- `paintWideItems()` / `paintTableCells()` / 手柄 / `hitWideItem()` 全部改用 `docRect`；
- 排版内部（`freeTopFor`、越界判断）仍用页内坐标 —— 那里比较的对象就是正文区。

实测（两张 600×400 图 + 长文本，横向纸张）：页数 2，
`#0 页0 x306.7–538.3`、`#1 页1 x700.7–1000.7`，两个盒子都包含在各自页矩形内。

## 并排两页时，第 2 页的右半边永远够不到

**现象** 默认「每行 2 页」下，窗口里只露出第 2 页的左半，右边被截断，
而且没有横向滚动条可以拖过去 —— 页面末尾根本滑不到。

**错因** 上一步加横向滚动条时，创建代码插在一条**已经不存在的语句**后面
（`m_vbar->setVisible(true)` 早被删了），脚本没报错、指针一直是 `nullptr`。
`updateScrollBars()` 里所有 `m_hbar` 都在 `if (m_hbar)` 里，于是静默失效：

```
滚动范围 X=-1   ← m_hbar 为 null
```

**修法** 在构造函数里紧跟着 `m_vbar` 创建 `m_hbar`，并接 `valueChanged`。

另外给滚轮补了横向：**触控板横滑**或 **Shift + 滚轮**。

实测（2 页并排、视图 900×600，内容 1214×842）：

| | 改前 | 改后 |
|---|---|---|
| X 范围 | **-1（没有滚动条）** | **328** ✓ |
| Y 范围 | 242 | 256 ✓ |
| 能到底 | X 不能 | X、Y 都能 ✓ |

切到「无限竖向」后内容高 1708，Y 范围 1122 ✓。

## 调第 1 页图片高度，第 2 页正文跟着上下移动

**现象** 拖动第 1 页图片的高度手柄，第 2 页的正文起点跟着动 ——
第 2 页文字顶端正好对齐图片下沿。

**错因** `freeTopFor()` 只按 **y 范围** 过滤宽对象，没看页码：

```cpp
auto freeTopFor = [&](qreal x0, qreal x1, int page) {
    for (const WideItem &it : m_wideItems) {
        if (it.box.top() < area.top() - 0.01) continue;   // 只比 y
        if (it.box.top() >= area.top() + area.height()) continue;
        ...
    }
    Q_UNUSED(page);      ← 拿到页码却没用
};
```

对象盒子是**页内坐标**，第 1 页的图 y 范围（56.7–356.7）在第 2 页同样成立，
于是第 2 页的每一列都被当成「被图压住」，统统从 356.7 起排。

**修法** 先比页码：

```cpp
for (const WideItem &it : m_wideItems) {
    if (it.page != page) continue;      // 只在同一页内比较
    ...
}
```

实测（短文字 + 高 300pt 的图 + 2400 个 h，共 3 页）：
三页「起点不在页首的列」都是 **0**（改前第 2、3 页全部下移 300pt）。

顺带给 `columnsProbe()` 加了页码与列顶坐标 —— 这类跨页问题一眼就能看出来。
