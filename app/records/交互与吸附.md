# 交互与吸附

宽对象的**操作命中**与**操作吸附**规则。与渲染无关，单独一份，便于以后加图片/表格/其他对象时复用。

## 旋转以「对象中心」为轴

设计要点（手绘推导）：

```
(a,b)  图片旋转中心（= 对象包围盒中心）
(x,y)  拖曳开始位置
(x',y') 光标当前位置
θ      旋转角 = ∠((x',y') − (a,b)) − ∠((x,y) − (a,b))
```

只看**方向差**，不看距离：`L1`、`L2` 长度再变也不影响角度。

```cpp
// UmeInteract::dragAngleDelta(center, from, to)
angleOf(to, center) - angleOf(from, center)
```

容易写错的两处：

- 用「手柄位置」当起点 × 应当用**按下时的光标位置**（手柄中心与光标未必重合）；
- 每次移动都拿「上一次的旋转角」累加 × 应当用**拖曳开始时的角度 + 本次角度差**，
  否则会漂移。

## 角度吸附

用户想停在 0/45/90/135/180…，但手不可能准。规则：

| 参数 | 值 |
|---|---|
| 吸附步长 | 45° |
| 容差 | ±8° |
| 超出容差 | 保持自由角度（不强吸） |

```cpp
UmeInteract::snapDegrees(43.5) == 45
UmeInteract::snapDegrees(20)   == 20   // 自由角度
```

实测：`0→0  3→0  20→20  43.5→45  46→45  88→90  133→135  178→180  270→270`。

## 拖曳捕获（光标不会一直停在手柄上）

按住手柄拖动时，光标一旦移动就会**离开手柄矩形**。若每次移动都重新做命中测试，
拖曳会立刻中断。所以：

1. 按下时判定一次命中，记下 `m_wideDrag` 的类别；
2. 移动时**不再做命中测试**，直接按已记录的类别应用；
3. 松开时才清空。

这也是「缩放手柄会跑」的原因：改变大小后手柄位置立刻变化，
只有捕获才能让拖曳连续。

## 手柄随对象旋转；命中要反向旋转

对象旋转后，9 个手柄跟着转（视觉位置变了）。如果命中测试还按未旋转的矩形算，
就几乎点不中。

做法：

```
视觉：  handle = rotatePoint(未旋转点, 中心, 角度)
命中：  local  = rotatePoint(光标,     中心, −角度)   // 反向转回去
        再与「未旋转手柄矩形」比较
```

再加**命中容差 5 pt**（手柄本身只有 6 pt 见方，鼠标不可能精确压住）。

## 悬停反馈：光标形状要跟着转

鼠标移到控制手柄上，光标必须换成对应的缩放/旋转光标；否则用户不知道这一格是干什么的。

难点与手柄命中相同：**光标方向也得随对象旋转**。

```
本地方向角（左上 225°、右下 45°、上 270°、右 0° …）
      + 对象旋转角
      → 归到最近的 45° 扇区
      → 扇区决定光标：0/4 水平、2/6 竖直、1/5 ↘、3/7 ↙
```

实测（`cursorProbe()`）：

| 旋转 | 四角 | 上下边 | 左右边 | 旋转手柄 |
|---|---|---|---|---|
| 0° | F B B F | V V | H H | R |
| 45° | V H H V | B B | F F | R |
| 90° | B F F B | H H | V V | R |

（F = 斜向 `SizeFDiag`，B = 另一条斜向 `SizeBDiag`，V/H = 竖/横，R = 自制旋转光标）

Qt 没有内置的旋转光标，用 `QPainter` 画了一段圆弧加箭头（`UmeIcons::rotateCursor()`），
hotspot 放在正中。

对象本体上则是 `SizeAllCursor`（可拖动），链接上是手型，其余是 I 形光标。

## 鼠标光标：竖排里要横过来

**现象** 鼠标移到正文上，光标是竖着的 I 形 —— 但这是直排，插入方向是**上下**的。

**错因** 直接用 `Qt::IBeamCursor`。系统 IBeam 是按横排设计的（竖杠 + 上下横线）。

**修法** 自制一个**转 90° 的 I 形**光标（`UmeIcons::textIBeam()`）：

- 正文悬停用它；链接上仍用系统手型；对象手柄上用缩放/旋转光标。
- 视图构造时也设成默认光标，避免鼠标刚进入时先闪一下竖 I。

形状照「**宽翼缘工字钢**」的截面画：两端是竖的**翼缘**，中间是较薄的**腹板**，
整块实心；直排时把工字钢转 90°，翼缘落在左右两侧。

```
        │▌     ▐│        ← 翼缘（厚）
        │▌━━━━━▐│        ← 腹板（薄）
        │▌     ▐│
```

| 参数 | 值 | 说明 |
|---|---|---|
| 画布 | 32 逻辑单位（2 倍屏 64px） | ≈ 24pt，与 14pt 字的一行相当 |
| 翼缘厚 | 3.2 | **必须比腹板厚**，否则看起来是「H」不是工字钢 |
| 腹板厚 | 1.9 | |
| 白描边 | 1.8 | 深色/彩色文字上都看得清 |
| 热点 | 正中心 | 指示插入位置 |

演进过程：细线版（24 画布、横线 12）→ 加长版（32、22）→ 工字钢实心版（4.6/3.0）→ **调细版（3.2/1.9）**。
细线版看起来像「小叉子」，改成实心截面后与正文行高的「一致感」才够。

### 顺序

悬停判断的顺序必须与按下时一致，否则会出现「看着是缩放光标，按下去却在拖对象」：

1. 手柄（缩放/旋转光标）
2. 对象本体（移动光标）
3. 链接（手型）
4. 文字（I 形）

## 优先级

按下时依次判断，命中即返回：

1. **手柄**（当前选中对象的 9 个手柄）
2. **对象本体**（点在包围盒里 → 选中并准备移动）
3. 文字（光标命中 / 拖曳选区）

点中对象本体时把光标也移进对象所在块，右侧「宽对象格式」面板才能读到属性。

## 限制

- 旋转角归一化到 `[0,360)`；
- 缩放后跨列数、高度、偏移都在 `applyWideObject()` 里统一钳制（见 README「限制」）；
- 拖曳中不改选区、不改光标，避免与文字拖选互相干扰。

## 旋转后的本体命中

**现象** 对象转 45° 后，点在它「看得见」的角上选不中。

**错因** 本体命中用的是**未旋转**的包围盒 `box.contains(point)`，
旋转后可见范围跑到框外去了。

**修法** 与手柄命中同一套：把光标点绕中心**反向旋转**回对象本地坐标，再判包围盒；
并且**外扩 1pt** —— 正点在角上正好落在边界，`QRectF::contains` 对右边/下边是开区间。

实测：转 45° 后点旋转后的左上角，选中索引 = 0。

## 尺寸与位置吸附

拖曳时给两档吸附，避免「差一点点对不齐」：

| 对象 | 吸附网格 | 容差 |
|---|---|---|
| 位置（上下移动） | **行高**（字号 × 1.4） | 4 pt |
| 尺寸（高度） | **4 pt 细网格** | 2 pt |

尺寸用细网格、位置用行高网格：尺寸跳动要小，否则手感很糟；位置按行对齐才自然。

实测：高度 60 拖 +25pt（=85）→ 吸到 **84**。

## 删除宽对象

选中宽对象后：

- `Delete` / `Backspace`：删掉对象（表格整张删，图片连空段落一起删）；
- `Esc`：取消选中。

这两个键必须在「删一个字符」的分支之前拦截，否则会先删掉光标处的字。
实测：块数 2 → 1，宽对象列表为空，选中索引 -1。

## 拖动把宽对象标记擦掉（整张表散架）

**现象** 插了表格、拖动它之后，表格散成十几条竖排小列：
表头「列 1 列 2 列 3 列 4」各自变成一列，表格框线也没了。

**错因** 按下时先取属性、后移光标：

```cpp
m_wideDragProps = currentWideObject();   // ← 光标还在表格外，取到空属性
setTextCursor(inside);                    // ← 之后才移进表格
```

空属性 `kind == None` 在拖动过程中被写回表格格式，
「这是一张表」的标记就被抹掉了。日志里能直接看到：

```
19:09:48.576 [wide] apply kind=0 wrap=0 span=3 h=120.0   ← 清空标记
19:09:48.588 [layout] blocks=17 … cols=17                 ← 17 段各自成列
```

**修法** 两处：

1. 按下时**先移光标、再取属性**；
2. `applyWideObject()` 拒绝写入 `kind == None`（记 `apply ignored: kind=None`），
   从根上防止「属性没取到就把标记写没」。

另外排版层加了**自愈**：只要这一块是表格的首块，就按宽对象排；
属性缺失时用默认值（跨列数 = 列数、高度 = 行数 × 28）补上。
已经散架的文档，下次重排会自动恢复成表格对象。

实测：光标移出表格（kind=0）后点表格本体拖动 8pt →
宽对象仍在，y 从 56.7 → 64.7，光标落回表格内。

## 环绕模式下点不中对象下方的文字

**现象** 「文本环绕」时，图片下方那一列明明有字，点上去却选不中；
切到「独占整列」就正常。

**错因** 上一轮加的「点对象下方空白处 → 光标跳到对象之后的段落」**抢先命中**：
它只判断「在对象 x 范围内且 y 在对象下方」，没有先看那里是不是正文。
环绕模式下对象下方恰恰就是同一列的正文，于是所有点击都被这个快捷方式吃掉。

**修法** 先做文字命中判断，只有**真正的空白处**才走跳转：

```cpp
if (!hitsAnyColumn(docPos)) {
    // 落在某个宽对象下方的空白 → 光标放到对象之后的段落
}
```

`hitsAnyColumn()` 遍历所有列的 `box`（外扩 1pt）判断包含关系。

实测（环绕模式，对象 x81.7–185.7、h=80）：

| 点击位置 | 命中列 | 结果 |
|---|---|---|
| 对象下方 20pt 处的**文字列** (96.2, 156.7) | 1 | 光标停在该文字块 ✓ |
| 对象下方**空白处**（横向不在任何列里） | 0 | 跳到对象之后的段落 ✓ |

## 选不中第 2 页的图，改的却是第 1 页

**现象** 第 2 页上的图片怎么点都选不中；点下去选中的总是第 1 页那张，
「宽对象格式」改的也是第 1 页那张。

**错因（两个叠加）**

1. **画的位置错了**：`paintWideItems()` 用页内坐标直接画，
   第 2 页的对象被画到第 1 页的位置上。
   用户看到它在第 1 页，就点第 1 页 —— 命中的自然是第 1 页的对象。
2. **选中态用数组下标**：`m_selectedWide` 是 `wideItems()` 的下标，
   而每次重排都会重建这个数组，下标会漂。

**修法**

1. 绘制/手柄/命中统一走 `m_layout.docRect(item)`（加该页原点）；
2. 选中态改为记**块位置** `m_selectedWideBlock`：

```cpp
for (const WideItem &it : m_layout.wideItems())
    if (it.block.position() == m_selectedWideBlock)
        return &it;
```

块位置在重排后不变，除非这块被删掉（那时自然返回空，选择失效但不会错位）。

顺带修了「点对象下方 → 跳到对象之后的段落」那条快捷方式：它也在用页内坐标，
跨页时会把点击认到别的页的对象上。

**实测** 两张 600×500 的图：点第 2 张 → 选中索引 1；把高度改成 200 →
`#0 高 500.0`（不变）、`#1 高 200.0` ✓。
