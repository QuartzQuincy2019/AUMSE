# M3 混排（汉字直立与标点）

## 汉字不直立，跟着英文一起躺倒

**现象** 竖排一列里，汉字横躺着。

**错因** 整行用 `QTextLine::draw()` 一次性画完，整行都套了 `rotate(90)`。

**修法** 改成逐字形绘制：蒙文/拉丁/标点随列旋转，汉字/假名/韩文直立。

## 汉字时立时躺，取决于前面有没有空格

**现象** 「monggol 成吉思汗」里汉字躺倒；换一行又正常。

**错因** 直立判定依赖 `QGlyphRun::sourceString()`，而 Qt **经常给空串**；
后来改成整段按「首字形位置」判，首字形落在空格上就整段判错。

**修法** 逐字形判定：先算槽位，再取槽位内的一点反查字符
（`line.xToCursor`），按该字符决定直立与否。

## 汉字下端被裁掉

**现象** 汉字每一笔的下缘都不见一截。

**错因** `QPainter::drawText(QRectF, …)` 会按矩形**裁剪**，
而给的格子高度是排版步进（14pt 字约 14pt），装不下 1.2em 的字身。

**修法** 改为按**基线点**绘制 `drawText(QPointF, …)`，没有矩形就没有裁剪。

## 汉字互相压叠、标点缩成米粒

**现象** 一行汉字挤在一起，句号冒号引号小得看不见。

**错因** 汉字与中文标点被**蒙文字体**排版。主字体没有这些字形，步进只有半个字宽；
而绘制时字形来自回退字体，于是字大格小，必然压叠。
字形探针实测：`runs=15`，`[SimSun 7]` 夹着 `[Noto 1 ？]`、`[Noto 3 ：""]`。

**修法** 把「用哪个字体排」与「怎么摆」分开：`isCjkLike()` 覆盖汉字与中文标点，
载入与打字时按脚本切段落到 `cjkFamily()`。实测探针变成 `runs=2 [SimSun 31]`。

## 标点比正常小一圈

**现象** 句号冒号引号明显偏小。

**错因** 直立字按「格子高度」定字号。标点也走这条路，而标点的步进比字身窄。

**修法** 用字符**自身**的字号，格子只负责定位。

## 问号叹号被转了 90°

**现象** 竖排里的 `？` 躺倒，像怪符号。

**错因** 凭印象把 `？！` 当成「竖排要转 90°」。

**修法** 查 W3C [clreq §2.1.2](https://www.w3.org/TR/clreq/#major_differences_between_horizontal_and_vertical_writing_modes)：
点号（顿号、逗号、分号、**冒号、句号、问号、叹号**）「直、横排方向一致」，
即**不旋转**；中国大陆规范要求直排时贴**字面右上角**。按此改。

## `drawGlyphRun` 离屏渲染不出墨

**现象** 换成逐字形后，纯蒙文页面**整页空白**（墨迹 0 像素）。

**错因** `QPainter::drawGlyphRun()` 在离屏平台下不落墨（诊断显示 run 正常、
9 个字形都在、`rawFont` 有效，就是画不出来）。

**修法** 旋转支改走 `QRawFont::pathForGlyph()` + `fillPath()`。

## 整页字大了 33%、位置也偏

**现象** 逐字形绘制后，字比原来大一圈。

**错因** `QTextLayout` 的字形位置与 `QRawFont` 的轮廓都是 **96dpi 像素**，
画布是 **pt**，少乘了 `72/96`。

**修法** 绘制时 `scale(kPxToPt)`；绘制、光标、选区、命中四处统一。

## 巨大黑块 / 字飞出去

**现象** 偶尔出现一个占满半页的黑块，或一个字跑到远离文本的地方。

**错因** 末字形槽位取「剩余长度」时，跨 run 会拿到整行宽度，槽位有几百 pt。

**修法** 末字形取 `min(自身推进量, 剩余长度)`，并对字号做半个字～两个字的钳制。

## 表格跨页（整行切分，单元格不拆）

**需求** 表格本身可以跨页；单元格不能跨页。

**做法** `WideItem` 增加行区间 `rowFirst / rowLast`，一张表可以被排成多个片段：

```cpp
rows   = table->rows()
rowH   = min(max(8, heightPt / rows), 可用高度)   // 行高统一，至少一行能进一页
while (r < rows) {
    fit  = floor(剩余页高 / rowH)                 // 本页能放几行
    last = min(rows-1, r + fit - 1)
    生成片段 (r .. last) → 画在 (x, top, w, (last-r+1)*rowH)
    r = last + 1
    if (r < rows) 换页继续（x 不变，保证同一列位置）
}
```

- 片段共享同一个 `item.block`，所以「选中表格」仍然按块识别；
- `applyWideObject()` 里表格的高度上限放宽到 40 页（图片仍限一页）。

**两个随之修掉的 bug**

| 现象 | 错因 |
|---|---|
| 片段只有 6 行，却画出 10 条格线、格子被压扁 | 绘制格线按**全表行数**等分片段高度 → 改用本片段 `shown` 行数 |
| 单元格里的字完全看不见 | 画页面底色时设过 `Qt::NoPen`，没恢复；纯文本没有显式颜色就用了这支「无笔」→ 绘制前显式 `setPen` |

**实测** 10 行 × 120pt（共 1200pt）：

```
片段：p0 rows 0-5 h=720.0    p1 rows 6-9 h=480.0
```

渲染图（`app/build/table-p1.png` / `table-p2.png`）确认第 1 页 6 行、第 2 页 4 行，
行列完整、无单元格被切断。

## 单元格内多列文本

**需求** 一个单元格里文字多时，应当像正文一样分成多列，而不是溢出。

**做法** 单元格内的排版本来就是「一个 `QTextLayout` + 每条 line 画一列」，
问题出在列间距用了**格子宽度**：

```cpp
line.draw(&p, QPointF(0, (cw - 4.0) * k));   // ✗ 第 2 列直接被推出格子
```

竖排里一列的宽度是**行高**（约一个字宽），不是格子宽度。改成：

```cpp
stepPx = lay->lineAt(0).height();            // px
p.translate(cellRect.right() - 2, cellRect.top() + 2);
p.rotate(90);
p.scale(kPxToPt, kPxToPt);                   // 之后按 layout 的 px 单位画
line.draw(&p, QPointF(0, stepPx * k));
```

**实测** 1×1 表格、60 个汉字、格子 100×90pt →
格子内墨迹条带数 **4**（分成了 4 列）；`app/build/table-cell.png` 可肉眼确认。

**已知限制**：单元格里的字形是**整体旋转 90°** 画的，
所以汉字在表格里是「躺着的」。正文里的逐字直立逻辑（`pathForGlyph`）
还没复用到单元格 —— 这是下一步。

## 单元格里按 Enter 逐格跳转

**需求** Enter → 右边一个单元格；没有右边就下一行第一个；已经是最后一个就跳出表格。

**做法** `keyPressEvent` 里在「宽对象选中态」之前拦截 Return：

```cpp
QTextTable *t = m_cursor.currentTable();
if (c + 1 < t->columns())      next = cellAt(r, c + 1)
else if (r + 1 < t->rows())    next = cellAt(r + 1, 0)
else                            next = 表格之后的段落（没有就先建一个）
```

**实测** 2×3 表格，连按 6 次：

```
#1 (0,1)  #2 (0,2)  #3 (1,0)  #4 (1,1)  #5 (1,2)  #6 已跳出表格 ✓
```

## 单元格字形与正文统一

把正文那段「逐字判直立/旋转、按墨迹居中、句读贴右上」的绘制抽成
`UmeView::drawVerticalLine()`，正文与单元格都调它 —— 一份规则，两处使用。

顺带解决：单元格里原本是整体旋转 90°，汉字是躺着的；现在与正文一致。

## 一次失败尝试（已回退）

想让表格宽度「按内容自适应」（内容多就把表撑宽），实现后
**拖曳选中测试失败**：`按下=11 拖到=13 → 选中 [78,78]`。
原因是撑宽后表格覆盖了正文列，命中与选择全部错位。
已回退，改用「在给定表宽内按内容比例分配列宽」——
不会破坏正文，但**内容特别多时字仍会被挤小**，这是下一步要解决的。

## 表格专用手柄：按行、按列调，不整体缩放

**需求** 表格不允许旋转、不允许用九宫格手柄整体缩放；
但支持按行、按列调整 —— 需要专用手柄。

**做法**

| 部位 | 表现 | 拖动效果 |
|---|---|---|
| 列分隔线 | 表格**上边缘**的小方块（每两条列线一个） | 该列变宽，相邻列**等量变窄**（表宽不变） |
| 行分隔线 | 表格**右边缘**的小方块（每两条行线一个） | 该行变高，相邻行等量变矮 |

- `wideHandles()` 遇到表格直接返回 `tableHandles()`，所以**不再有 9 个缩放/旋转手柄**；
- `applyWideObject()` 对表格强制 `rotation = 0`；
- 行列尺寸存进 `WideProps::colSizes / rowSizes`（序列化成逗号串放在
  `PropColSizes / PropRowSizes`），排版时归一化到表宽/页高后使用。

**踩的坑**：属性只加在**块格式**那条写入分支里，而表格走的是 `table->format()`，
于是拖动后读回来是空的。两条分支都要写 —— 这是「同一份属性两处载体」的典型陷阱。

**实测** 3×3 表格：

```
手柄数 = 4（2 条列线 + 2 条行线）
设 45° → 读回 rotation = 0.0
拖第一条列线 +12 → 列宽 37.0 / 13.0 / 25.0   ✓（相邻列等量变窄）
```

跨页切分也改成**逐行累计**（原来按统一行高算），这样用户拖过行高后仍能正确分页。
