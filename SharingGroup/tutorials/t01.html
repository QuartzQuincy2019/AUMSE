初识回鹘蒙文

为什么先上这一篇

我们做的是回鹘蒙文编辑器。如果不知道这门文字「长什么样、怎么读、 怎么转写成拉丁字母」，后面所有排版细节都会变成死记硬背。

这一篇不写代码，只建立四个概念：转写、字形与连字、 连写系统、书写方向与主流转写方案。

文中的蒙文示例不是手打的 —— 它们由 tools/cnmn.py 从官方转写方案表机械换算成码位， 所以「拉丁转写 ↔ 蒙文」的对应关系是可复现、可检验的。

1拉丁转写是什么（它不是拉丁语）

先破一个常见误解：

「拉丁转写」里的「拉丁」指字母，不指语言

拉丁字母（Latin alphabet）是 A B C … Z 这套字母。

拉丁语（Latin）是古罗马说的那种语言，今天没人当母语用了。

「把蒙古文转写成拉丁字母」= 用 ABC 这套字母去拼蒙古语的音， 跟古罗马、跟拉丁语没有任何关系。

定义

转写（transliteration / romanization）

把一种文字系统写的东西，按规则换成另一种文字系统的写法。 换成拉丁字母的就叫拉丁转写（也叫罗马化，romanization）。

两个关键性质：

  1. 有规则 —— 不是随便音译。同一个字，谁转写都得转成同一个结果。
  2. 可逆（理想情况下）—— 能从中还原回原来的文字。 这一点很重要：它意味着转写是编码，不是翻译。

它不是为了给外国人读，而是为了「能打字、能检索、能存档」

场景为什么需要转写
计算机输入 键盘只有拉丁字母。没有转写，很多文字根本打不出来
检索与排序 要在数据库里按读音查找、排序，得有一个统一的字母序列
学术引用 论文正文用拉丁字母排，引用原文时不能整段插异体字
跨系统交换 旧系统只认 ASCII，转写是老资料的唯一通路
URL 与文件名 网址里放异体字要百分号编码，转写后可直接读

不同语言各有自己的转写方案

这不是「一种转写」，而是每套文字各有若干种方案， 而且方案之间经常打架 —— 同一个音，不同方案用不同字母。

文字方案举例
汉语汉语拼音 北京 → Beijing
汉语威妥玛拼音（Wade–Giles） 北京 → Pei-ching　← 老英文书里常见
日语罗马字（Rōmaji） 東京 → Tōkyō
俄语西里尔字母的拉丁转写 Москва → Moskva
阿拉伯语多种学术转写 القاهرة → al-Qāhira
梵语IAST（国际梵语转写标准） धर्म → dharma
顺便说：汉语拼音本身也是一种拉丁转写

「北京」写成 Beijing，这就是把汉字转写成拉丁字母。 威妥玛拼音是更早的一套，所以老地图上写 Peking、 Tsingtao（青岛）。

同一个「青岛」，两套方案给出两种拼法 —— 这正是「方案不同、结果不同」的最好例子。

带特殊符号的转写 ≠ 不专业

你会看到 š、č、ǰ、ö、 ü、ë 这类带符号的字母。它们不是装饰 ——

是有意造出来的新字母，用来表示「26 个基本字母不够用」的那些音。 这跟汉语拼音用 ü 表示「鱼」的音是同一个思路。

2字形、连字与连写：三个容易混的概念

先说清三层

概念英文是什么
字符character 语义单位。你在键盘上输入、在码表里查到的那个
字形glyph 画出来的具体形状。同一个字符可以有多个字形
连字ligature 几个字符合成一个字形画出来
一句话记住字形与字符的关系

字符是「什么」，字形是「怎么画」。

同一个字符「a」，在正体里长一个样、在斜体里长另一个样 —— 这就是一个字符、两个字形。字体文件里存的是字形，不是字符。

连字的经典例子

① fi 连字 —— 拉丁字母里最常见的

在多数排版良好的西文字体里，f 和 i 挨在一起时， 不会画成「f 然后 i」，而是画成一个合并的字形：

为什么 f 和 i 必须合并复制
f 的右上角有个伸出来的钩子 ──┐
                              ↓
f + i  →  钩子会撞到 i 上面的点

合并之后：
   f i    →    ﬁ      （一个字形，钩子和点合二为一）

Unicode 里这两个都有独立码位：
  U+FB01  LATIN SMALL LIGATURE FI
  U+FB02  LATIN SMALL LIGATURE FL
f + l 同理

f 的钩子会撞到 l 的上端，所以也有 fl 连字（U+FB02）。

在浏览器里搜「fi」，多数情况仍能搜到 ﬁ —— 因为排版软件做了「连字也算匹配」的处理。这也是连字不能随便做的原因： 做多了会影响检索。

② 招财进宝 —— 汉字里的「多字合一」

这是一个民间合体字，把四个字挤进一个字的位置：

招财进宝与 fi 的关键差别

fi 连字是为了让字不打架，属于「技术必需」。

招财进宝是为了好看、图吉利，属于「装饰」。

但两者在技术上是同一件事：多个字符 → 一个字形。 字体文件不关心你为什么合并，它只管「按规则换字形」。

现在说「连写」—— 它和连字不是一回事

最容易混的一点
连字 Ligature连写 Cursive joining
是什么 几个字符合并成一个字形 相邻字母的笔画相互衔接，但仍是各自独立的字形
字形个数 N 个字符 → 1 个字形 N 个字符 → N 个字形（只是形状变了）
能不能拆 拆开就读不出来或很难读 拆开仍然认识，只是「断开了」
典型 fi　fl　招财进宝 阿拉伯字母　蒙文

换个说法：

用一句话区分复制
连字：两个字符变成了「一个字」。
       像两个人结婚 —— 成为一个新的整体。

连写：每个字母还在，但手拉着手。
       像一排人牵手 —— 人数没变，只是连起来了。
连写里字母会「换衣服」

连写文字系统里，同一个字母在词首 / 词中 / 词尾 / 单独 四个位置，往往有四种不同形状。

这四种形状在 OpenType 字体里对应四个特性： init / medi / fina / isol。 我们的字体文件里就有这四个（详见 T03）。

3初识连写文字系统

世界上的文字，按「字母之间要不要连」大致分三类：

类型代表特点
不连写拉丁字母　西里尔　希腊 字母各自独立，一个一个分开写
连写阿拉伯字母　蒙文　叙利亚文 字母按位置变形并相互衔接
（另一维度）音节文字汉字　日文假名 一个符号一个音节，不涉及字母连接

阿拉伯字母：最广为人知的连写系统

阿拉伯字母的四个位置形复制
以字母 b（ب）为例：

  单独  بـ      词首（连后面）
  词中  ـبـ     两边都连
  词尾  ـب      连前面
  单独  ب       两边都不连

读法方向：从右往左

关键：连不连会改变词义，不只是好看不好看。
为什么「连写」是刚需而不是风格

在连写系统里，「连起来」本身携带信息。 比如阿拉伯语里，有些词只靠「哪里连、哪里断」来区分。

所以排版引擎必须自动做上下文判断。 这也是为什么这类文字的字体里， 「换字形」的表（字形替换表，GSUB）比「摆位置」的表（字形定位表，GPOS）大得多。

回鹘蒙文：竖着写的连写系统

蒙文比阿拉伯字母还多一层难度 —— 它是竖排的。

阿拉伯字母回鹘蒙文
书写方向横向，从右往左 纵向，从上往下
行的推进一行一行往下 一列一列往左（本编辑器用往右排列，见下）
连写有，四位置形有，四位置形
字母表来源闪米特字母 源自粟特字母，再上溯到阿拉米字母
「列往左还是往右」是个实际问题

传统蒙文典籍是列自左向右排的（和汉字竖排相反）。 我们的编辑器用 writing-mode: vertical-lr， 其中 lr 就是「列从左往右」。

CSS 里另有一个值 vertical-rl，那是汉字/日文竖排用的 （列从右往左）。两者绝不能混 —— 混了之后文字仍然竖着，但列的顺序整个反过来，读起来就错了。

而且必须显式写 direction: ltr， 否则继承到 rtl 会再次反转列序。这个坑我们踩过，记在 web/UMCompos.js 的注释里。

4书写系统与主流转写方案

书写系统的几个层次

层次说明
文字类型音素文字（字母表），且连写
书写方向纵向，自上而下；列自左向右
字母表源自粟特字母 → 阿拉米字母 → 腓尼基字母
字母数量 Unicode 蒙文区（U+1800–U+18AF）共 155 个码位有转写对应， 其中字母 131 个（含元音、辅音、异体）
元音 7 个基本元音： a e i o u ö ü （另有 ë，主要用于借词）
位置变形 词首 / 词中 / 词尾 / 单独，四个位置形
音节连写 以音节为单位连写，不是逐字母 —— 详见 T03 里「字形名里的音节」一节

主流转写方案

本篇采用：中国—蒙古国联合蒙文转写

全称中国－蒙古国联合蒙文转写， 是用来把蒙古文（传统蒙古文、托忒文、满文、锡伯文， 以及达斡尔文、鄂温克文）转写成拉丁字母的一套方案。

时间事件
1997 年 8 月 中国、蒙古国、德国共同向 ISO 提出一套方案， 想替代过时的鲍培式方案；错过申报期限，未果 （即 ISO/CD 14522《蒙古文拉丁转写方案》）
2005 年 7 月 中国、蒙古国再次共同向 ISO 提出（ISO/TC 46/WG 3）。 这套方案直接与 Unicode 挂钩， 是完全无损的转写 —— 即本篇所用方案

「无损」是关键：每个码位都有确定的转写， 反过来也能唯一还原。鲍培式方案做不到这一点（它更接近标音，不是编码）。

方案表里两个容易看错的细节
  1. 一个码位可能转写成两个字母：U+1829 写作 ng。 反过来换算时要先匹配长的，否则 ng 会被拆成 n + g 两个码位。 （tools/cnmn.py 里就是按长度倒序匹配的。）
  2. 同一个音在不同文字里用不同字母：U+1834 的通用转写是 č，但托忒文那列写 z、满文那列写 c。 选错列就会转错 —— 所以引用时必须说清用的是哪一列。

变体选择符：转写表里最特殊的一行

方案表里还有四个不对应可见字母的码位：

名称码位 转写作用
FVS1U+180B' 自由变体选择符（Free Variation Selector）： 在同一个字母的多个候选字形里，指定用哪一个。 有些字母的元音 a / e 长得一样，靠 FVS 区分
FVS2U+180C"
FVS3U+180D`
FVS4U+180F（表内未列）
MVSU+180E_ 元音分隔符（Mongolian Vowel Separator）： 隔开两个本该连写的元音
为什么这四个码位对我们特别重要

FVS / MVS 不是独立的字母，它们修饰前一个字母。

但字体文件给它们的 advance 是 770 单位（跟普通字母差不多，见 T03）。 这意味着：如果排版时把它们当成独立字符，它们会各占一格， 整词就散架了。

所以我们必须按字素簇处理 —— 让 FVS / MVS 黏附到前一个字素上。这正是 UMCompos 里 UAX #29 那段代码在做的事。

5一页速查

概念一句话
拉丁转写 用 ABC 字母拼别的语言。「拉丁」指字母，不指拉丁语
转写的性质 有规则、可逆 —— 是编码，不是翻译
字符 vs 字形 字符是「什么」，字形是「怎么画」。一个字符可有多个字形
连字 Ligature N 个字符 → 1 个字形。fi　fl　招财进宝
连写 Cursive N 个字符 → N 个字形，但笔画相接。 阿拉伯字母　蒙文
一句话区分 连字是结婚（成了新整体）；连写是牵手（人数没变）
位置形 词首 init / 词中 medi / 词尾 fina / 单独 isol
蒙文书写方向 纵向自上而下，列自左向右 （CSS: vertical-lr + 显式 direction:ltr）
蒙文元音 7 个：a e i o u ö ü（另有 ë 用于借词）
本篇转写方案 中国—蒙古国联合蒙文转写（2005 年向 ISO 提出， 与 Unicode 挂钩，无损）
为什么要换掉鲍培式 鲍培式更接近标音，做不到与码位一一对应； 联合方案是可逆编码
FVS1-4 自由变体选择符，修饰前一个字母，不是独立字母
MVS 元音分隔符，隔开本该连写的两个元音
对我们代码的影响 FVS/MVS 必须黏附前一字素，否则整词散架
这一篇要记住的五句话
  1. 拉丁转写 = 用拉丁字母拼别的语言，与拉丁语无关。 它是可逆的编码，不是翻译。
  2. 字符是语义、字形是形状。连字把 N 个字符合成 1 个字形； 连写让 N 个字符形状变化但仍各自独立。
  3. 回鹘蒙文是竖排的连写系统： 纵向自上而下、列自左向右，字母有四个位置形。
  4. 本篇用「中国—蒙古国联合蒙文转写」 —— 与 Unicode 挂钩、无损、可逆；鲍培式已被它取代。
  5. FVS / MVS 是修饰符不是字母，排版时必须黏附前一字素。
