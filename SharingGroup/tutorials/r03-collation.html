字典序、自然序与 QCollator

UME 项目组内部教程 · R03（Related） · 字符串怎么比大小，中文怎么排才对

1字符串是怎么比大小的

数字比大小很直观：3 < 5。但字符串呢？ "apple" 和 "banana" 谁大？

规则叫字典序（也叫词典序），思路和查字典完全一样：

字典序的三条规则
  1. 从头逐位比，第一个不同的字符决定大小；
  2. 如果一个是另一个的前缀，短的更小 （"ab" < "abc"，就像字典里「ab」在「abc」前面）；
  3. 全部相同就是相等。

用代码验证一下最直观 —— C++ 的 < 对 std::string 用的就是字典序：

lex1.cpp —— 字典序长什么样复制
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>

int main() {
    std::vector<std::string> v{"banana", "apple", "app",
                               "Apple", "apples", "App"};
    std::sort(v.begin(), v.end());
    for (const auto& s : v) std::cout << s << '\n';
}
输出
App
Apple
app
apple
apples
banana

注意结果里 大写全部排在小写前面 —— App、Apple 跑到了 app 前面。 这不是 bug，原因在下一节。

2关键：比的是字符序，不是「字典」

上一节说「和查字典一样」，但真实的字典里 Apple 和 app 是混在一起的，不会先把大写挑出来。 差别就在这里：

「字典序」这个说法其实不完整

字典序只规定了怎么逐位比，没规定字符之间谁大谁小。 后者叫字符序（collation），是可以换的：

字符序依据结果
码位序Unicode 码点数值 Z(U+005A) < a(U+0061)，大写全在前
字节序UTF-8 编码后的字节 UTF-8 下与码位序一致（这是它的设计优点）
区域整理序各语言的词典习惯 瑞典语 ö 排在 z 之后

所以「按字典序排」这句话必须问清是哪种字符序， 否则换个语言结果就变了。

std::string 用的是最朴素的字节序（等价于码位序）， 所以大写字母在前。它不认语言 —— 这对中文是灾难性的，见第 5 节。

3自然序：给「人类」看的排序

码位序还有一个反直觉的地方，跟大小写无关：

文件名排序的经典问题复制
输入:  file1.txt   file2.txt   file10.txt   file20.txt

字典序（逐字符比）:  file1.txt   file10.txt   file2.txt   file20.txt
                                  ↑ 10 排到了 2 前面，因为 '1' < '2'

自然序（数字当数值）: file1.txt   file2.txt   file10.txt   file20.txt
                                  ↑ 符合人的直觉 ✓
自然序 = 字典序 + 「数字段按数值比」

规则很简单：遇到连续的数字串，不逐字符比，而是当成一个整数比。

所以：

比较字典序自然序
"file9" vs "file10"file10 在前file9 在前 ✓
"v1.9" vs "v1.10"v1.10 在前v1.9 在前 ✓
"a2" vs "a10"a10 在前a2 在前 ✓

文件管理器、ls -v、sort -V、Windows 资源管理器 用的都是自然序 —— 因为它符合人的直觉。

自然序不是「一个」严格的顺序

朴素实现会遇到说不清的边界：

  • "a1" 和 "a01" —— 数值一样大，算相等吗？
  • "1.2" 和 "1.10" —— 是版本号，还是两个数字段？
  • "a" 和 "a0" —— "a" 有数字段吗？

所以正规实现必须补规则（比如「数值相同时前导零少的优先」）， 才能保证排序结果稳定、可预测。 这也是自然序没有进 C++ 标准库的原因之一 —— 它不够「标准」。

4中文排序：为什么默认结果是错的

把 std::sort 直接用在中文上，结果会让人莫名其妙：

zh1.cpp —— 按字节序排中文复制
#include <iostream>
#include <string>
#include <vector>
#include <algorithm>

int main() {
    std::vector<std::string> v{"张三", "李四", "王五", "赵六"};
    std::sort(v.begin(), v.end());
    for (const auto& s : v) std::cout << s << '\n';
}
输出（按 UTF-8 字节序）
张三
李四
王五
赵六

看着好像没问题？但这只是巧合。它的真实依据是这几个字的 Unicode 码位：

上面结果的真正原因复制
张  U+5F20
李  U+674E
王  U+738B
赵  U+8D75
        ↑ 恰好是按码位递增，所以看着「对」

换一批字就露馅了：

再试一批复制
输入:  陈(Chen)  安(An)  周(Zhou)  白(Bai)

码位序结果:  安  白  周  陈      ← 按码位
拼音序应该是: 安(An)  白(Bai)  陈(Chen)  周(Zhou)
                    ↑ 周 和 陈 的位置反了
结论：std::sort 排中文 = 按码位排 = 没有意义

中文世界里「排好序」通常指下面几种之一：

排法依据用途
拼音序读音的拉丁字母通讯录、名单（最常用）
笔画序笔画数，少的在前字典、索引
部首序部首 + 笔画字典
码位序Unicode 码点只适合做「稳定、可复现」的内部排序

码位序不属于任何一种「中文排序」 —— 它只是碰巧有时候看着对。

5QCollator：让 Qt 帮你按语言排

要按拼音排，你得知道每个字的读音、变调规则、多音字…… 自己写不现实。正确做法是用现成的整理（collation）实现， Qt 里就是 QCollator。

QCollator 是什么

QCollator 是 Qt 对区域感知字符串比较的封装 —— 底层是 ICU（Unicode 的整理算法实现）。 你告诉它「按中文排」，它就知道拼音、笔画该按什么顺序。

三个常用开关：

  • setLocale() —— 按哪个语言/地区的习惯排；
  • setCaseSensitivity() —— 大小写敏不敏感；
  • setNumericMode(true) —— 打开就是自然序（数字按数值比）。

先看它怎么用：

qcollator1.cpp —— 按中文拼音排序复制
#include <QCoreApplication>
#include <QCollator>
#include <QLocale>
#include <QStringList>
#include <QDebug>
#include <algorithm>

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);

    QStringList names{u"陈明"_s, u"安然"_s,
                      u"周涛"_s, u"白露"_s};

    QCollator coll;
    coll.setLocale(QLocale(QLocale::Chinese, QLocale::China));   // 按中文习惯
    coll.setCaseSensitivity(Qt::CaseInsensitive);

    std::sort(names.begin(), names.end(),
              [&coll](const QString& a, const QString& b) {
                  return coll.compare(a, b) < 0;              // 用 collator 当比较器
              });

    for (const QString& s : names) qDebug() << s;
}
输出（按拼音：An Bai Chen Zhou）
"安然"
"白露"
"陈明"
"周涛"
关键写法：coll.compare(a, b) < 0

QCollator::compare() 返回负数 / 0 / 正数， 含义和 strcmp 一样（小于 / 等于 / 大于）。 把它包成 < 0 就能直接喂给 std::sort 的第三个参数 —— 这是把「语言排序」接进「通用算法」的标准手法。

6用 QCollator 做自然序

前面说过自然序是「数字按数值比」。QCollator 只要开一个开关就有了 —— 这就是 setNumericMode：

qcollator2.cpp —— 自然序 / 字典序对比复制
#include <QCoreApplication>
#include <QCollator>
#include <QStringList>
#include <QDebug>
#include <algorithm>

static QStringList sorted(QStringList v, bool numeric) {
    QCollator c;
    c.setLocale(QLocale::system());
    c.setNumericMode(numeric);        // ← 只有这一行之差
    std::sort(v.begin(), v.end(),
              [&c](const QString& a, const QString& b) {
                  return c.compare(a, b) < 0;
              });
    return v;
}

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);
    QStringList files{"file10.txt"_s, "file2.txt"_s,
                      "file1.txt"_s,  "file20.txt"_s};

    qDebug() << "字典序:" << sorted(files, false);
    qDebug() << "自然序:" << sorted(files, true);
}
输出
字典序: ("file1.txt", "file10.txt", "file2.txt", "file20.txt")
自然序: ("file1.txt", "file2.txt", "file10.txt", "file20.txt")

只差一个 setNumericMode(true)， 就从「10 排在 2 前面」变成符合直觉的顺序。 这是 Qt 里实现自然序最省事的办法 —— 不用自己写数字段扫描。

7一个真实场景：文件列表

把前面的东西拼起来。这是「按文件名列出目录」的实际代码 —— 同时用到自然序（数字按数值）和区域整理（中文按拼音）：

filelist.cpp —— 文件列表排序复制
#include <QCoreApplication>
#include <QDir>
#include <QCollator>
#include <QFileInfo>
#include <QDebug>
#include <algorithm>

// ① 排序规则集中在一处，便于以后调整
static QCollator makeCollator() {
    QCollator c;
    c.setLocale(QLocale::system());   // 跟随系统语言（中文系统 → 拼音序）
    c.setCaseSensitivity(Qt::CaseInsensitive);
    c.setNumericMode(true);            // 自然序：file2 在 file10 前
    return c;
}

int main(int argc, char** argv) {
    QCoreApplication app(argc, argv);

    // ② 只列文件名，不要路径
    QDir dir(QStringLiteral("D:/Path/To/UME"));
    QFileInfoList list = dir.entryInfoList(
        QDir::Files | QDir::Dirs | QDir::NoDotAndDotDot,
        QDir::NoSort);                // ③ 关键：不让 QDir 先排一遍

    QCollator coll = makeCollator();
    std::sort(list.begin(), list.end(),
              [&coll](const QFileInfo& a, const QFileInfo& b) {
                  // ④ 先按「目录在前」分组，同组内再按名字
                  if (a.isDir() != b.isDir()) return a.isDir();
                  return coll.compare(a.fileName(), b.fileName()) < 0;
              });

    for (const QFileInfo& fi : list) {
        qDebug().noquote() << (fi.isDir() ? "[D] " : "[F] ") << fi.fileName();
    }
}
输出示例（目录在前，文件按自然序）
[D] assets
[D] src
[F] readme.md
[F] step2.txt
[F] step10.txt
[F] 说明.txt
④ 那个「先分目录再比名字」的写法值得记住

这是多关键字排序的常见形态：

结构复制
if (第一关键字不同) return 第一关键字比较;
if (第二关键字不同) return 第二关键字比较;
return 第三关键字比较;

写成「一层层往下退」的形式，既可以给 std::sort 用 （注意：比较函数必须是严格弱序，别写出 <=）， 也比串成一长串三元表达式好读得多。

8常见错误

写法问题
QString::operator< 排中文 那是码位序，不是拼音序 —— 要用 QCollator
coll.compare(a,b) 直接当 bool 返回的是负数/0/正数，必须写 < 0
比较器里写 <= 不满足严格弱序，std::sort 可能越界崩溃
每次比较都新建 QCollator 构造有开销（要载入整理规则），应在循环外建一次
用 QLocale() 而不是 QLocale::system() QLocale() 是「C 语言环境」，等于没设语言
忘了 QDir::NoSort QDir 会先按自己的规则排一遍，你的排序是白做的（结果倒是对的，只是多一次无用功）
分区大小写敏感时开 setNumericMode 没问题，两者互不影响 —— 但要注意它只影响数字串
注意：std::sort 不稳定

如果两条记录比较结果相等，std::sort 不保证保持它们原来的次序。 要稳定就换 std::stable_sort（R02 讲过）。 对「按名字排同名文件」这种场景，稳定性是有意义的。

9一页速查

概念一句话例子
字典序逐位比，第一个不同者定大小"ab" < "abc"
字符序决定「哪个字符更小」码位序 / 区域整理序
自然序数字段按数值比file2 在 file10 前
拼音序中文按读音排安 → 白 → 陈 → 周
QCollatorQt 的区域感知比较器底层是 ICU 的整理算法
setNumericMode(true)打开就是自然序一行实现 file2 < file10
setLocale()按哪个语言排QLocale::system() 跟随系统
照抄这一段就能用复制
#include <QCollator>
#include <algorithm>

// 中文按拼音 + 数字按数值 —— 大多数中文项目的默认选择
QCollator coll;
coll.setLocale(QLocale::system());
coll.setCaseSensitivity(Qt::CaseInsensitive);
coll.setNumericMode(true);

std::sort(v.begin(), v.end(),
          [&coll](const QString& a, const QString& b) {
              return coll.compare(a, b) < 0;      // 别忘了 < 0
          });
一句话记住区别： 字典序是「一个字符一个字符比」； 自然序是「数字当成数字比」； 区域整理序是「按某个语言的词典习惯比」。 C++ 的 std::string 只给你第一种，而且是最粗糙的字节序 —— 碰到中文或带数字的名字，就该换 QCollator 了。
