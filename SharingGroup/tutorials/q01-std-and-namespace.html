std 与命名空间初步

UME 项目组内部教程 · Q01（Qt） · 从这里开始进入 C++

本讲：命名空间 + C++ 入门

这一讲是个分界线

01~08 讲的是 C。从这一讲起，全面转向 C++ —— 因为 UME 实际用的 Qt 是 C++ 框架，我们必须跨过这一步。

好消息是：C++ 基本包含 C。你前面学的指针、数组、结构体、 作用域，在 C++ 里全都算数，不会白学。

而「入门 C++ 要跨的第一道坎」就是命名空间 —— 它解释了为什么到处都写着 std::， 以及那句 using namespace std; 到底在干什么。

文中所有输出与报错，均使用 g++ 13.1.0（-std=c++17）实际编译运行核对。

1为什么需要命名空间

C 有一个绕不过去的老问题：全局名字只有一层，很容易撞车。

设想两个人都给项目写了工具函数，都叫 hello：

C 里的重名问题复制
/* 小明的文件 utils_a.c */
void hello(void) { printf("我是小明的 hello\n"); }

/* 小红的文件 utils_b.c */
void hello(void) { printf("我是小红的 hello\n"); }

/* 链接时：两个 hello，撞了 → multiple definition */

更麻烦的是第三方库。你用了两个库，它们内部都有个 init，你根本没法改别人的代码。

C 时代的办法是靠命名约定手工避开：

C 的做法问题
ume_hello()得记住前缀，漏写就撞
UME_Init()同上
font_init()模块多了前缀越来越长
命名空间解决的正是这件事

命名空间（namespace）给名字加了一层「姓」。

你叫 hello，他叫 hello，但你们姓不同 —— 小明::hello 和 小红::hello， 从此互不打扰。

它和「文件夹」是一个道理：两台电脑上都可以有 readme.txt，只要放在不同文件夹里就不会混。

C++ 的写法复制
#include <iostream>

namespace ume {                  // 开一个命名空间
    int version = 10;
    void hello() { std::cout << "ume::hello() 被调用\n"; }
}

namespace other {
    int version = 99;              // 同名，但不冲突
    void hello() { std::cout << "other::hello() 被调用\n"; }
}

int main() {
    std::cout << "ume::version   = " << ume::version   << "\n";
    std::cout << "other::version = " << other::version << "\n";
    ume::hello();
    other::hello();
    return 0;
}
运行结果
ume::version   = 10
other::version = 99
ume::hello() 被调用
other::hello() 被调用
:: 这个符号怎么读

:: 叫作用域解析运算符（scope resolution operator）， 口语里念「双冒号」或者「的」。

ume::version 读成「ume 的 version」， 意思一目了然：那个命名空间里的那个名字。

C 里没有这个符号，它是 C++ 的。

2std 是什么

你已经见过很多次了：std::cout、 std::string、std::vector。 std 就是一个命名空间 —— 而且是标准库的那个。

一句话

std = 「standard（标准）」的缩写， 是 C++ 标准库所有东西所在的命名空间。

它不是关键字，就是个普通命名空间的名字，只不过标准规定必须叫这个。

所以那些写法的含义就清楚了：

写法读作是什么
std::coutstd 的 cout标准库的输出流
std::stringstd 的 string标准库的字符串类型
std::vector<int>std 的 vector 标准库的动态数组（09 讲学过）
为什么标准库要套一层 std？

因为它东西太多了 —— 上千个名字：cout、 string、vector、sort、 max、swap……

如果这些直接摊在全局，你自己的变量叫 max、 函数叫 sort 就会撞车。套一层之后， 你的 max 和 std::max 可以同时存在。

顺带一提：std:: 后面还可以继续套， 比如 std::chrono::seconds —— 那是标准库内部的子命名空间。

3四种写法与它们的代价

用标准库里的东西，有四种写法。按「写起来多省事」和「有多危险」排序：

① 完全限定名 —— 最啰嗦，但最安全

每次都写全复制
std::cout << "hi" << std::endl;
int m = std::max(3, 5);

永远不会有歧义。库的头文件里必须这么写（下面会讲为什么）。

② using namespace std; —— 最省事，也最容易出事

把 std 整个「打开」复制
using namespace std;      // 放在文件开头

cout << "hi" << endl;      // std:: 可以省了
int m = max(3, 5);

这就是网上教程里最常见的那一行。它把 std 里上千个名字全部倒进全局作用域， 于是下面的问题就来了。

③ using std::cout; —— 只引入一个，折中

精确引入复制
using std::cout;
using std::string;

cout << "hi";              // 只有这两个能省 std::
int m = std::max(3, 5); // max 没引入，还得写全

这叫 using 声明，只把指定的那一个名字拉进来。 风险小得多，是很多团队的实际选择。

④ 在函数内部 using —— 影响范围最小

只在这个函数里生效复制
void report() {
    using namespace std;   // 出了这个函数就失效
    cout << "只在 report 里能这么写" << endl;
}
四种写法对照
写法作用范围建议
std::cout— 推荐 头文件里必须这样
using namespace std;整个文件 避免 大项目里会撞车
using std::cout;整个文件，但只有一个名字 可以 小而具体
函数内 using namespace std;那个函数 可以 影响面小

为什么 using namespace std; 会出事

因为 std 里有成百上千个名字，你在不知情的情况下 就和它们撞上了。举个真实的例子：

撞车示例复制
using namespace std;

// 你自己写了一个 count（std 里也有 std::count）
int count(int a) { return a * 2; }

int main() {
    int n = count(5);      // 编译器要在 std::count 和 ::count 之间挑
    cout << n;
}
更隐蔽的一种：变量名撞上类型名

这是最坑的一类。std 里有 string、vector、 list、count、distance…… 很多人习惯把变量命名为 string 或 count。

平时没事，直到某天你 #include 了一个新头文件 —— 编译突然报一堆看不懂的错。这就是「using namespace std; 的 惩罚：错误来得晚，且难定位」。

那为什么教程里都写这一行？

因为教学示例短，写全 std:: 会占掉半屏， 分散注意力。所以入门教程（包括本系列的前几讲）都用了它。

但要养成习惯：一旦开始写正式代码（尤其是头文件）， 就回到 std:: 全限定写法。

本讲之后的内容，我们会尽量两种都示范， 让你看清什么时候可以省、什么时候不能省。

4嵌套命名空间

命名空间可以套命名空间，像文件夹套文件夹。

套两层复制
namespace ume {
    namespace font {                // 套在 ume 里面
        int count = 42;
        void info() {
            std::cout << "ume::font::info()，字体数 = " << count << "\n";
        }
    }
}

// 用的时候一层层写下去
ume::font::info();
运行结果
ume::font::info()，字体数 = 42

C++17 起有更短的写法，把多层用 :: 连起来：

C++17 的简写复制
// 以前要写三层
namespace a { namespace b { namespace c {
    int deep = 7;
}}}

// C++17 起可以一行写完
namespace a::b::c {
    int deep = 7;
}

// 用的时候
int x = a::b::c::deep;
运行结果
a::b::c::deep = 7
为什么要嵌套

因为一个项目里「ume」这个名字下也可能有很多东西： 字体、排版、界面…… 分层之后各归各位：

ume::font::load()
ume::font::count
ume::layout::measure()
ume::ui::Window

5匿名命名空间

还有一种没有名字的命名空间：

匿名命名空间复制
namespace {                    // 注意：没有名字
    int hidden = 123;
    void onlyHere() { std::cout << "匿名命名空间里的函数\n"; }
}

int main() {
    std::cout << hidden << "\n";   // 不用加前缀，直接用
    onlyHere();
}
运行结果
123
匿名命名空间里的函数

它看起来「什么都没做」，其实有明确用途：

匿名命名空间 = 「只在本文档里可见」

里面的东西只有当前这个 .cpp 能用， 别的 .cpp 看不到、也链接不到。

这在 C 里是用 static 实现的：

C 的写法C++ 的写法
static int hidden = 123; namespace { int hidden = 123; }
static void helper(void) {…} namespace { void helper() {…} }

好处：可以一次把一堆辅助函数都圈成「内部使用」， 不用逐个加 static。

什么时候用

写一个 .cpp 时，总有些只给自己用的辅助函数 （比如打印调试信息、做一次性的格式转换）。

把它们放进匿名命名空间，就不会和别的文件里的同名函数撞车， 也不会污染链接器。

6同一个程序：C 写法 vs C++ 写法

前面都是铺垫。现在看同一个程序两种写法， 你就知道 C++ 到底带来了什么。

需求：三个玩家，各扣 30 点血，然后打印。

C 写法复制
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

struct CPlayer {
    char name[32];            // 得先想好够不够长
    int  hp;
};

// 函数只能放外面，第一个参数得自己传指针
void c_player_init(CPlayer *p, const char *n, int hp) {
    strncpy(p->name, n, sizeof(p->name) - 1);
    p->name[sizeof(p->name) - 1] = '\0';   // 别忘了收尾
    p->hp = hp;
}
void c_player_hit(CPlayer *p, int d) {
    p->hp -= d;
    if (p->hp < 0) p->hp = 0;
}
void c_player_show(const CPlayer *p) {
    printf("  [C ] %s HP=%d\n", p->name, p->hp);
}

int main(void) {
    int n = 3;
    // 数组得 malloc，还得自己算字节数
    CPlayer *team = (CPlayer *)malloc(sizeof(CPlayer) * n);
    if (team == NULL) return 1;      // 还得判空

    c_player_init(&team[0], "Archer", 100);
    c_player_init(&team[1], "Mage",   80);
    c_player_init(&team[2], "Knight", 150);

    for (int i = 0; i < n; i++) c_player_hit(&team[i], 30);
    for (int i = 0; i < n; i++) c_player_show(&team[i]);

    free(team);                    // 忘了这行就泄漏
    return 0;
}
C++ 写法C++复制
#include <iostream>
#include <string>
#include <vector>

namespace ume {
    struct Player {
        std::string name;        // 不用管长度
        int hp = 100;            // 有默认值

        // 函数就放在类型里
        void hit(int d) {
            hp -= d;
            if (hp < 0) hp = 0;
        }
        void show() const {
            std::cout << "  [C++] " << name << " HP=" << hp << "\n";
        }
    };
}

int main() {
    // 会自动增长的数组，不用 malloc / free
    std::vector<ume::Player> team;

    team.push_back({"Archer", 100});
    team.push_back({"Mage",   80});
    team.push_back({"Knight", 150});

    for (auto &p : team) p.hit(30);          // 范围 for + 引用
    for (const auto &p : team) p.show();
    return 0;
}
两份代码运行结果完全一样
  [C ] Archer HP=70
  [C ] Mage HP=50
  [C ] Knight HP=120

  [C++] Archer HP=70
  [C++] Mage HP=50
  [C++] Knight HP=120
C++ 版少了什么
C 版必须做的事C++ 版
malloc 算字节数不用，vector 自己管
判断 NULL不用
记住写 free不用，自动
char name[32] 想长度std::string 自动伸缩
strncpy + 手动补 '\0'直接赋值
函数放外面、传指针方法放在类型里
手写循环下标范围 for
%s / %d 格式串<< 自动认类型
C++ 也不是全是好处

<< 输出比 printf 慢一些 （不过日常足够用）；编译错误信息更长更难读； 语言本身也大得多。

但换来的是更少的内存错误和更少的样板代码 —— 对一个要长期维护的项目，这笔账是划算的。

最该先习惯的三个
  1. std::string 代替 char[] —— 从此不用想长度、不用担心 '\0'、能直接 + 和 ==。
  2. std::vector 代替 malloc —— 不用 free，不会泄漏。
  3. std::cout 代替 printf —— 不用记 %d / %s，类型自动认。

这三个能立刻消掉你之前踩过的大半坑。

好消息：C 的东西还能用

printf、malloc、char* 在 C++ 里依然能用（头文件写 <cstdio> 或 <cstdlib>），只是不推荐。

你甚至可以在 C++ 里写纯 C 的代码 —— 这正是前面 01~08 讲的代码能在 g++ 下编译的原因。

9:: 作用域解析运算符

前面你一直在写 std::cout，但一直没细看中间那两个冒号。 它是 C++ 里最不起眼、出现频率却最高的运算符之一 —— Qt 的代码里几乎每一行都有它。

一句话

:: = 「左边的名字里，找右边那个名字」。

左边的名字可以是全局、命名空间、类，或者什么都不写。 所以它只有两种读法，记住这两个就够：

  • 有左操作数：A::b —— 读作「A 里的 b」
  • 没左操作数：::b —— 读作「全局的 b」（强制点名外层的那个）

下面把它的四种用法一次讲完，每种都配「什么情况下非用不可」。

① 定位命名空间里的东西

这是最常见的一种，你早就在用了：

定位命名空间复制
std::cout << "你好" << std::endl;
std::string s = "UME";
std::vector<int> v{1, 2, 3};

QString name = "Uyghur";      // 没写 ::
Qt::AlignCenter;                          // 写了 ::，因为 AlignCenter 住在 Qt 里
编译器看到的
std::cout        →  标准库命名空间 std 里的 cout
Qt::AlignCenter  →  命名空间 Qt 里的 AlignCenter（一个枚举值）

② 访问类的静态成员

类的静态成员属于类本身，不属于某个对象，所以不能用 obj.成员， 只能用 类名::成员：

静态成员复制
class Counter {
public:
    static int total;          // 静态成员变量：所有对象共用一份
    static int get() { return total; }   // 静态成员函数
};

int Counter::total = 0;      // 类外定义，必须写 Counter::

int main() {
    Counter::total = 5;       // 用类名访问，不写 Counter:: 会编译错
    int n = Counter::get();
    std::cout << n << "\n";
}
输出
5
Qt 里到处都是这种写法

Qt 的常量、枚举、单例几乎都靠 类名::成员 取：

写法是什么
Qt::AlignCenter对齐方式枚举值
Qt::red预定义颜色枚举
Qt::Horizontal水平方向
QIODevice::ReadOnly打开文件的模式
QIODevice::WriteOnly打开文件的模式
QMessageBox::warning(...)静态函数，直接弹一个警告框
QMessageBox::Yes按钮返回值
QFont::Bold字重
QPainter::Antialiasing抗锯齿渲染提示

QFileInfo::exists(...)判断文件是否存在
QDateTime::currentDateTime()取当前时间

看出来了吗 —— 这些全都不用先创建对象。 :: 就是在告诉你：「这个名字挂在类上，不在某个具体对象上」。

③ 定义类自己的成员函数（类名::函数名）

函数如果在类里只声明、在类外写实现，实现处必须加 类名::， 否则编译器认为那是个普通全局函数：

类外实现复制
// widget.h —— 只声明
class Widget {
public:
    void show();
    int  width() const;
};

// widget.cpp —— 写实现，必须写 Widget::
void Widget::show() {          // ← 少了 Widget:: 就成了全局函数
    std::cout << "显示" << "\n";
}

int Widget::width() const {   // const 写在参数表后面
    return 100;
}
输出
显示
这就是 Qt 项目「头文件 / 源文件」成对出现的原因

你在 F03 学过头文件。Qt 的每个类基本都是这样一套：

文件内容
mainwindow.hclass MainWindow { ... }; 只声明
mainwindow.cppMainWindow::MainWindow(...)、MainWindow::onClicked() 等实现

看到 MainWindow::onClicked() 就知道：这是 MainWindow 类的成员函数。 没有 :: 的就是全局函数或者别的类的 —— 一眼就能分辨。

④ 前面什么都不写：::name 强制用外层的那个

当局部变量把全局变量挡住了（名字冲突），写 :: 就能点名要外层的：

名字被挡住时复制
int count = 100;              // 全局

int main() {
    int count = 7;            // 局部，把全局的挡住了

    std::cout << count   << "\n";   // 就近原则 → 局部的 7
    std::cout << ::count << "\n";   // :: 强制点名 → 全局的 100
}
输出
7
100

类里的成员名和全局名撞了也一样，用 :: 表示「全局的那个」：

成员与全局同名复制
int size = 10;

class Box {
public:
    int size = 20;
    int total() {
        return size + ::size;   // 20 + 10
    }
};

int main() { std::cout << Box().total() << "\n"; }
输出
30
别说 using namespace std; —— 你会失去 :: 的保护

第 3 节讲过 using namespace std; 的代价。这里再补一条更具体的：

一旦写了它，count 到底是你的还是 std::count 就说不清了； 而 ::count 永远指全局， std::count 永远指标准库 —— 只有老老实实写 ::，名字才没有歧义。

Qt 真实代码里的 :: 长什么样

把上面四种用法放到真实的 Qt 代码里，你会发现它无处不在：

一段典型 Qt 代码复制
#include <QApplication>
#include <QMessageBox>

// ① 类外实现成员函数：MainWindow::
MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent)                // ② 调用基类构造：QMainWindow::
{
    // ③ 类的静态函数：QMessageBox::question
    auto r = QMessageBox::question(
        this,
        QStringLiteral("确认"),
        QStringLiteral("要保存吗？"),
        QMessageBox::Yes | QMessageBox::No);   // ④ 类里的枚举值

    if (r == QMessageBox::Yes)
        save();
}
这四个 :: 分别是
MainWindow::MainWindow    →  ③ 定义类自己的成员函数
QMainWindow(parent)       →  ① 定位基类的构造函数
QMessageBox::question     →  ② 类的静态成员函数（不用 new 就能调）
QMessageBox::Yes          →  ② 类的静态枚举值

再看几个 Qt 里高频的：

用法例子含义
信号槽connect(btn, &QPushButton::clicked, this, &MainWindow::onClicked)取成员函数指针，必须带类名
继承class MainWindow : public QMainWindow冒号不是 ::，别混（见下方提醒）
基类调用QWidget::paintEvent(e)显式调用基类的实现
嵌套类QList<QString>::const_iterator类里再定义的类，一层层往里点
模板里的类型QVector<int>::size_type模板类内部的类型名
全局函数qApp、qDebug()这些是全局的，不带 ::
别把 :: 和继承的 : 弄混

两个冒号是作用域，一个冒号是继承 / 初始化列表：

写法含义
class Dog : public AnimalDog 继承 Animal（一个冒号）
Animal::eat()Animal 里的 eat（两个冒号）
Dog::Dog() : Animal()前后各一个：定义 Dog 的构造函数，并初始化基类

最后一行最典型 —— 一行里两个冒号的意思完全不同。 记住：:: 是「谁的」，: 是「是什么的」。

一个坑：:: 不总是作用域运算符

它还能当「拼接符号」用

C 语言里 :: 根本没有意义，所以有些老代码拿它当标记使， 预处理器会把整个 X::Y 换掉。比如 Windows 头文件里：

当记号用复制
// 某些库的自定义标记，展开后 :: 会消失
GUI_EXPORT::QWidget        // 展开后是 __declspec(dllexport) QWidget

所以看到 A::B 一时想不通时，先确认一下 A 到底是不是个命名空间或类 —— 不是的话，多半是宏。

一页速查

写法读作什么时候用
std::coutstd 里的 cout用标准库
Qt::AlignCenterQt 里的 AlignCenter用 Qt 的枚举 / 常量
Counter::totalCounter 里的 total访问静态成员
Widget::show()Widget 里的 show类外定义成员函数
::count全局的 count局部变量挡住了全局变量
QMessageBox::question()QMessageBox 里的 question调类的静态函数，不用建对象
Outer::InnerOuter 里的 Inner嵌套类 / 模板里的类型
口诀：:: 读作「的」。 std::cout 是「std 的 cout」， Widget::show 是「Widget 的 show」， ::count 是「全局的 count」。 句子读得通，写法就对了。

10常见错误

错误 1 · 忘了写命名空间前缀

对比复制
namespace ume { int version = 10; }

int main() {
    std::cout << version;        // ❌ 找不到 version
    std::cout << ume::version;   // ✅
}
真实报错（g++ 13.1.0）
error: 'version' was not declared in this scope;
       did you mean 'ume::version'?
note:  'ume::version' declared here

注意那句 did you mean 'ume::version'? —— 现代编译器会直接告诉你答案。看到 was not declared in this scope， 第一反应就该是「我是不是漏了 某某::？」

错误 2 · 两个命名空间都 using，导致二义性

对比复制
namespace A { void hello(); }
namespace B { void hello(); }

using namespace A;
using namespace B;

hello();                     // ❌ 到底要哪个？
A::hello();                  // ✅ 说清楚
真实报错（g++ 13.1.0）
error: call of overloaded 'hello()' is ambiguous
note:  candidate: 'void A::hello()'
note:  candidate: 'void B::hello()'

ambiguous 就是「有歧义」。 报错里把两个候选都列出来了 —— 看清楚你要哪个，然后写上前缀。

错误 3 · 头文件里写 using namespace

对比复制
/* ❌ mylib.h —— 把头文件写成这样，会污染所有包含它的文件 */
#pragma once
using namespace std;
void report(string s);

/* ✅ 头文件里一律写全 */
#pragma once
#include <string>
void report(std::string s);

这是硬规矩：头文件会被别人 #include， 你在里面 using namespace std; 等于替别人做了这个危险决定。

错误 4 · 命名空间只写了开没写闭

对比复制
namespace ume {
    int a = 1;
// ❌ 忘了 }

// 后果：后面所有东西都被「吃」进 ume 里，报错位置离真正的问题很远

namespace ume {
    int a = 1;
}                          // ✅

和M05「结构体忘了分号」是同一类问题： 漏一个符号，报错却出现在很远的地方。

错误 5 · 在 .cpp 里定义、忘了也在命名空间里

对比复制
/* mylib.h */
namespace ume { void hello(); }

/* mylib.cpp */
void hello() { }                 // ❌ 这是全局的 hello，不是 ume::hello

namespace ume {
    void hello() { }             // ✅
}
// 或者写成
void ume::hello() { }          // ✅ 也可以用 :: 限定

症状：编译能过，链接时报 undefined reference to `ume::hello()' —— 因为你定义的其实是另一个函数。这正是 F03 讲过的链接错误。

11一页速查

想做的事写法
定义命名空间namespace ume { ... }
嵌套（C++17 起）namespace ume::font { ... }
匿名命名空间（仅本文件可见）namespace { ... }
用里面的东西ume::version
标准库的东西std::cout  std::string  std::vector
只引入一个名字using std::cout;
引入整个命名空间（慎用）using namespace std;
头文件里该怎么做一律写全 std::，不要 using
:: 读作「的」—— ume::font = ume 的 font
C 的 static 函数改用匿名命名空间
这一讲要记住的五句话
  1. 命名空间给名字加了一层「姓」，解决全局重名 —— 像文件夹之于文件。
  2. std 是标准库的命名空间， std::cout 读作「std 的 cout」。
  3. using namespace std; 图省事但有风险； using std::cout; 更精确； 头文件里一律写全名。
  4. 匿名命名空间 = 只在本文档可见， 相当于一堆 static。
  5. 看到 was not declared in this scope， 先想「是不是漏了 ::」； 看到 ambiguous，就是两个命名空间撞了。
