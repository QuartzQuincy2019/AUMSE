命名空间 C++ 入门

C++ 本讲：命名空间

前八讲讲的是 C。从这一讲起转向 C++ —— 而 C++ 代码里第一个让人不习惯的东西，就是一堆双冒号： std::cout、std::string、Qt::AlignCenter。

它们都和同一个概念有关：命名空间。这一篇只讲三件事 —— 为什么要它、「谁的谁」怎么读、那个 :: 是什么。

★1为什么需要命名空间

C 有一个绕不过去的老问题：全局名字只有一层，很容易撞车。

设想两个人都给项目写了工具函数，都叫 hello：

C 里的重名问题复制
/* 小明的文件 utils_a.c */
void hello(void) { printf("我是小明的 hello\n"); }

/* 小红的文件 utils_b.c */
void hello(void) { printf("我是小红的 hello\n"); }

/* 链接时：两个 hello，撞了 → multiple definition */

更麻烦的是第三方库。你用了两个库，它们内部都有个 init，你根本没法改别人的代码。

C 时代的办法是靠命名约定手工避开：

C 的做法问题
ume_hello()得记住前缀，漏写就撞
UME_Init()同上
font_init()模块多了前缀越来越长
命名空间解决的正是这件事

命名空间（namespace）给名字加了一层「姓」。

你叫 hello，他叫 hello，但你们姓不同 —— 小明::hello 和 小红::hello， 从此互不打扰。

它和「文件夹」是一个道理：两台电脑上都可以有 readme.txt，只要放在不同文件夹里就不会混。

C++ 的写法复制
#include <iostream>

namespace ume {                  // 开一个命名空间
    int version = 10;
    void hello() { std::cout << "ume::hello() 被调用\n"; }
}

namespace other {
    int version = 99;              // 同名，但不冲突
    void hello() { std::cout << "other::hello() 被调用\n"; }
}

int main() {
    std::cout << "ume::version   = " << ume::version   << "\n";
    std::cout << "other::version = " << other::version << "\n";
    ume::hello();
    other::hello();
    return 0;
}
运行结果
ume::version   = 10
other::version = 99
ume::hello() 被调用
other::hello() 被调用
:: 这个符号怎么读

:: 叫作用域解析运算符（scope resolution operator）， 口语里念「双冒号」或者「的」。

ume::version 读成「ume 的 version」， 意思一目了然：那个命名空间里的那个名字。

C 里没有这个符号，它是 C++ 的。

★2谁的谁：给名字加上「姓」

命名空间的效果，一句话就能说清： 它给名字加了一层「姓」，从此每个名字都归属于某个「谁」。

把 :: 读作「的」

A::b 读成「A 的 b」。句子读得通，写法就对了。

写法读作是谁的
std::coutstd 的 cout标准库
ume::versionume 的 versionume 这个命名空间
other::versionother 的 versionother 这个命名空间
::count全局的 count不属于任何命名空间

同名不怕：ume::version 和 other::version 可以同时存在，因为它们的「谁」不同。

回到开头那段代码，现在读起来应该没有障碍了 —— 两个 version、两个 hello，各归各的：

C++ 的写法复制
#include <iostream>

namespace ume {                  // 开一个命名空间
    int version = 10;
    void hello() { std::cout << "ume::hello() 被调用\n"; }
}

namespace other {
    int version = 99;              // 同名，但不冲突
    void hello() { std::cout << "other::hello() 被调用\n"; }
}

int main() {
    std::cout << "ume::version   = " << ume::version   << "\n";
    std::cout << "other::version = " << other::version << "\n";
    ume::hello();
    other::hello();
    return 0;
}
运行结果
ume::version   = 10
other::version = 99
ume::hello() 被调用
other::hello() 被调用
「谁的谁」这个读法为什么值得养成

因为它把「这个名字从哪来」变成了看一眼就知道的事。

读 QMessageBox::warning(...) 时，你不需要知道 QMessageBox 内部长什么样，就知道 这个函数是它家的；读 ::count 就知道 这是全局那个，不是某个局部的同名变量。

以后看别人的代码，先看 :: 左边是谁， 一半的疑问就没了。

★3:: 作用域解析运算符

你已经一直在写 std::cout，但可能没细看中间那两个冒号。 它叫 作用域解析运算符（scope resolution operator）， 是 C++ 里最不起眼、出现频率却最高的运算符之一。

它只有两种读法，记住这两个就够：

一句话

:: = 「左边的名字里，找右边那个名字」。

左边的名字可以是全局、命名空间、类，或者什么都不写。 所以它只有两种读法，记住这两个就够：

  • 有左操作数：A::b —— 读作「A 里的 b」
  • 没左操作数：::b —— 读作「全局的 b」（强制点名外层的那个）

① 定位命名空间里的东西

这是最常见的一种，你早就在用了：

定位命名空间复制
std::cout << "你好" << std::endl;
std::string s = "UME";
std::vector<int> v{1, 2, 3};

QString name = "Uyghur";      // 没写 ::
Qt::AlignCenter;                          // 写了 ::，因为 AlignCenter 住在 Qt 里
编译器看到的
std::cout        →  标准库命名空间 std 里的 cout
Qt::AlignCenter  →  命名空间 Qt 里的 AlignCenter（一个枚举值）

④ 前面什么都不写：::name 强制用外层的那个

当局部变量把全局变量挡住了（名字冲突），写 :: 就能点名要外层的：

名字被挡住时复制
int count = 100;              // 全局

int main() {
    int count = 7;            // 局部，把全局的挡住了

    std::cout << count   << "\n";   // 就近原则 → 局部的 7
    std::cout << ::count << "\n";   // :: 强制点名 → 全局的 100
}
输出
7
100

类里的成员名和全局名撞了也一样，用 :: 表示「全局的那个」：

成员与全局同名复制
int size = 10;

class Box {
public:
    int size = 20;
    int total() {
        return size + ::size;   // 20 + 10
    }
};

int main() { std::cout << Box().total() << "\n"; }
输出
30
别说 using namespace std; —— 你会失去 :: 的保护

第 3 节讲过 using namespace std; 的代价。这里再补一条更具体的：

一旦写了它，count 到底是你的还是 std::count 就说不清了； 而 ::count 永远指全局， std::count 永远指标准库 —— 只有老老实实写 ::，名字才没有歧义。

4std 是什么

你已经见过很多次了：std::cout、 std::string、std::vector。 std 就是一个命名空间 —— 而且是标准库的那个。

一句话

std = 「standard（标准）」的缩写， 是 C++ 标准库所有东西所在的命名空间。

它不是关键字，就是个普通命名空间的名字，只不过标准规定必须叫这个。

所以那些写法的含义就清楚了：

写法读作是什么
std::coutstd 的 cout标准库的输出流
std::stringstd 的 string标准库的字符串类型
std::vector<int>std 的 vector 标准库的动态数组（09 讲学过）
为什么标准库要套一层 std？

因为它东西太多了 —— 上千个名字：cout、 string、vector、sort、 max、swap……

如果这些直接摊在全局，你自己的变量叫 max、 函数叫 sort 就会撞车。套一层之后， 你的 max 和 std::max 可以同时存在。

顺带一提：std:: 后面还可以继续套， 比如 std::chrono::seconds —— 那是标准库内部的子命名空间。
