UME 项目组内部教程 · Q04（Q） · 接口是什么、为什么要它、常见的几种用途

接口与实现的分界 Actor 的 public 区

C++

Q03 的 Actor 里，名字和地址是 private 的 —— 外部代码碰不到。可是玩家总要改名、换地图，怎么办？

答案是走接口。这一篇就讲清楚接口是什么、为什么每个类都要有它。

一句话

接口 = 一个类对外开放的那组函数 —— 外界能做哪些事、每件事怎么调用、要传什么参数、会得到什么结果。

它不关心你怎么实现，只规定怎么用。 数据成员被藏在里面，操作只能从这几个口子进去。

1先看问题：数据藏起来了，外面怎么改

接着 Q03 的类往下写。这一篇要用的还是它：

Actor.h复制
#include <string>

class Actor {
private:
    std::string full_name;   // 全名
    std::string nickname;    // 昵称
    std::string address;     // 所在地图
    int maxLevel;            // 等级上限

public:
    int hp;                  // 当前血量
    int maxHp;               // 血量上限
    int atk;                 // 攻击力
    int def;                 // 防御力
    int mp;                  // 当前法力
    int maxMp;               // 法力上限
    int agi;                 // 敏捷
    int luk;                 // 幸运
};

几个 private 成员意味着：在类外面写不出 hero.full_name = "…" —— 编译器直接报错。

main.cpp —— 碰壁复制
int main() {
    Actor hero;
    hero.full_name = "灰羽·夜行者";   // ❌ 编译错误：'full_name' is private
    hero.maxLevel  = 60;                       // ❌ 同样是 private

    hero.hp = 80;                              // ✅ 这个可以，hp 是 public
}
编译器报错
error: 'full_name' is a private member of 'Actor'
error: 'maxLevel' is a private member of 'Actor'

于是就有了需求：既要藏住数据，又要让外面能改。办法就是开几个口子 —— 那几个口子就是接口。

2接口长什么样：六个成员函数

在 public 区里加上这六个函数：

Actor.h —— 补上接口复制
#include <string>

class Actor {
private:
    std::string full_name;
    std::string nickname;
    std::string address;
    int maxLevel;

public:
    int hp, maxHp, atk, def, mp, maxMp, agi, luk;

    // ---------- 改名换地图 ----------
    void changeName(std::string& newValue)      { full_name = newValue; }
    void changeNickname(std::string& newValue)  { nickname  = newValue; }
    void changeAddress(std::string& newValue)   { address   = newValue; }

    // ---------- 几个上限 ----------
    void setLevel(int newValue)   { maxLevel = newValue; }
    void setMaxHp(int newValue)   { maxHp    = newValue; }
    void setMaxMp(int newValue)   { maxMp    = newValue; }
};
读一遍这六行，接口的三件事就出来了
  1. 名字告诉你能做什么 —— changeName、setLevel， 看名字就知道意图，不用去翻实现。
  2. 参数列表告诉你调用时得给什么 —— 前三个给 std::string&，后三个给 int。
  3. 返回类型告诉你有没有回话 —— 六个都是 void， 调用完就结束，不返回东西。

注意参数用的是 Q03 刚学过的按引用传递： std::string& newValue。一个字都不复制 —— 名字可能有几十字节，按值传每次都要拷一遍；按引用只递地址。

对外：接口（public）
  • changeName(std::string&)
  • changeNickname(std::string&)
  • changeAddress(std::string&)
  • setLevel(int)
  • setMaxHp(int)
  • setMaxMp(int)
  • hp / mp / atk …（数值属性）
对内：实现（private）
  • full_name
  • nickname
  • address
  • maxLevel
  • （以及接口函数体里怎么写）

左边这一栏就是接口。外面的人只能站在左边， 右边怎么存、叫什么名字，他们看不见也管不着。

3怎么用：从外面改一个私有成员

main.cpp —— 通过接口改名、调上限复制
#include <iostream>
#include "Actor.h"

int main() {
    Actor hero;
    hero.hp = 80;
    hero.maxHp = 100;
    hero.mp = 30;
    hero.maxMp = 50;

    // ① 要改私有成员，先准备一个变量
    std::string n = "灰羽·夜行者";
    hero.changeName(n);            // 传进去的是 n 的引用

    std::string nick = "小灰";
    hero.changeNickname(nick);

    std::string where = "北境·霜牙岭";
    hero.changeAddress(where);

    // ② 数值上限直接给
    hero.setMaxHp(200);
    hero.setMaxMp(120);
    hero.setLevel(60);

    std::cout << "maxHp = " << hero.maxHp << "\n";
    std::cout << "maxMp = " << hero.maxMp << "\n";
}
输出
maxHp = 200
maxMp = 120
为什么前三个要先写一个变量

因为它们要的是 std::string& —— 引用必须绑一个真实存在的对象 （Q02 讲过的三条铁律之一）。

所以 hero.changeName("灰羽") 这种写法编译不过： 字符串字面量是个临时值，绑不到普通引用上。得先把它放进一个变量。

后三个要的是 int，hero.setMaxHp(200) 直接写就行。

接口调用者看到的只有那六行

写 hero.changeName(n) 的人不需要知道 full_name 这个名字、不需要知道它是不是 std::string、 更不需要知道赋值发生在函数体哪一行。

他只需要知道：有个叫 changeName 的函数，给一个字符串引用，名字就改了。 这就是接口的全部意义。

4为什么要接口：把「怎么改」收进类里

如果数据是公开的，改一个值就只是「赋个值」。可真实项目里， 很多属性不能随便赋。收进接口之后，规则就写在类里面。

三个最实用的理由
  1. 可以加检查。setLevel 里能挡住不合理的值 —— 外面传 -5 也进不来。
  2. 可以维持关系。血量和血量上限是有关联的： 改了上限，当前血量往往要跟着处理。
  3. 可以改内部实现。以后把 full_name 拆成 「姓 + 名」两个成员，调用处一个字都不用改。

例一：加检查

数据公开时
hero.maxLevel = -5;   // 编译通过
                      // 游戏里等级上限成了负数
                      // 出错的地方离这里很远
收进接口后
void setLevel(int v) {
    if (v < 1)   return;   // 挡掉
    if (v > 200) return;   // 挡掉
    maxLevel = v;
}

// 调用处
hero.setLevel(-5);    // 什么也没发生

例二：维持关系

血量上限一提，当前血量不能还超着。这件事只能由类自己管 —— 外面同时改两个公开成员，很难保证不出岔子：

关系写在接口里复制
void setMaxHp(int newValue) {
    if (newValue < 1) newValue = 1;
    maxHp = newValue;
    if (hp > maxHp) hp = maxHp;   // 顺手把当前血量收回来
}

void setMaxMp(int newValue) {
    if (newValue < 0) newValue = 0;
    maxMp = newValue;
    if (mp > maxMp) mp = maxMp;
}
效果复制
Actor hero;
hero.hp    = 180;
hero.maxHp = 200;

hero.setMaxHp(100);          // 上限降到 100
std::cout << hero.hp;         // 100 —— 自动被收回来了，不会出现 hp=180/maxHp=100

hero.setMaxHp(-50);          // 不合法 → 夹到 1（不是「忽略」）

例三：内部换实现，外面不动

今天 内部只有一个 std::string full_name， changeName 直接赋值
明天 想改成「姓」「名」两个成员，或者加一个「名字修改次数」计数 —— 只要 changeName 的签名不变，所有调用处都不用动
核心：接口把「能不能改、怎么改」从调用处收进了类里。 外面只说「我要改名」，至于名字怎么存、要检查什么、要不要连带处理别的字段， 都由类自己决定。

5接口的常见用途

用途做法 例子
校验进来先检查范围 setLevel：挡掉 <1 或 >200
维持不变式改一个，顺手修正相关的 setMaxHp：hp 超过新上限就收回来
隐藏表示内部怎么存外面不知道 full_name 以后可以拆成姓 + 名
只读暴露给一个读的函数，不给写的 getName() 返回副本或 const 引用
连带动作改完顺带做别的事 改名时记一条日志、刷新界面上的名牌
批量操作把一组相关的改动合成一个函数 levelUp()：升一级，同时加 hp / atk / maxHp
约束调用顺序不该调的调不动 没装备武器时 setAtk 不生效
一句话记住这些用途的共同点

全都是「光赋值做不到、或者不该由调用方操心」的事。

如果某个属性确实怎么改都行、改完也不用管别的， 那它直接 public 就够了 —— Actor 里的 hp、atk、luk 就属于这一类，所以它们没有 set 函数。

6接口和实现的分界：private 与 public

接口不是单独写在哪里的东西 —— 它就是 public 区那部分。 两个关键字正好划出这条线：

区谁能碰 放什么
public任何代码 接口：成员函数 + 少数确实随便改的属性
private只有本类的函数 实现：数据成员、内部辅助函数
判据很简单

「外面直接改它会不会出问题？」

  • 会 → 放 private，再开一个接口函数
  • 不会 → 放 public 就行，不用多写一层

Actor 就是这么分的：三个名字 + maxLevel 走接口， 其余数值属性直接公开。

习惯写法：数据在上，接口在下复制
class Actor {
private:                       // ① 实现（别人不用看）
    std::string full_name;
    std::string nickname;
    std::string address;
    int maxLevel;

public:                        // ② 接口（别人只看这里）
    int hp, maxHp, atk, def, mp, maxMp, agi, luk;

    void changeName(std::string& newValue);
    void changeNickname(std::string& newValue);
    void changeAddress(std::string& newValue);
    void setLevel(int newValue);
    void setMaxHp(int newValue);
    void setMaxMp(int newValue);
};

注意这里把声明和定义分开了：类里只写函数头（; 结尾）， 函数体写在外面。人读这个类的时候，看到的就是一份接口清单 —— 想知道这个类能干什么，扫一遍 public 区就够了。

Actor.cpp —— 函数体写在类外面复制
#include "Actor.h"

// Actor:: 说明这几个函数属于 Actor 这个类
void Actor::changeName(std::string& newValue) {
    full_name = newValue;
}

void Actor::setLevel(int newValue) {
    if (newValue < 1)   return;
    if (newValue > 200) return;
    maxLevel = newValue;
}

void Actor::setMaxHp(int newValue) {
    if (newValue < 1) newValue = 1;
    maxHp = newValue;
    if (hp > maxHp) hp = maxHp;
}
写在类里还是类外

两种都可以。函数很短（就一两行）时，直接写在类里更方便； 逻辑一多，就挪到 .cpp 去，让头文件保持清爽 —— 头文件是给读代码的人看接口的，不该被大段实现淹没。

7一页速查

本篇的六个接口函数

函数参数 作用
changeName(std::string&)字符串引用改全名
changeNickname(std::string&)字符串引用改昵称
changeAddress(std::string&)字符串引用改所在地图
setLevel(int)整数改等级上限
setMaxHp(int)整数改血量上限（并收回超出的 hp）
setMaxMp(int)整数改法力上限（并收回超出的 mp）

三句话

① 接口 = 类的 public 那部分 —— 外界能做的事、每件事怎么调用。
② 数据藏起来（private），改动走接口（public 函数） —— 这样「能不能改、怎么改」的规则才收得进类里。
③ 参数优先按引用传 —— std::string& 不复制； 但引用必须绑真实对象，所以调用前要先有一个变量。

什么时候该开一个接口函数

1外面直接改会出问题吗 不会 → 直接 public，不用包一层
2会 放 private，写一个 set… / change…
3改完要连带做什么 校验、修正关联字段、记日志 —— 都写进这个函数里
一句话

接口是这个类的「使用说明书」。 想知道一个类能干什么，只看它的 public 区； 想知道它怎么做到的，去看 private 和函数体。
