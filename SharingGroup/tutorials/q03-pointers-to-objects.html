指针进阶：指向对象的指针与引用*

UME 项目组内部教程 · Q03（Q） · 按引用传递的必要性：一个游戏角色省下 93.9% 的内存开销

指针与引用的分工 内存开销

C++

上一篇（Q02）把「引用」本身讲清楚了：它是语法上的别名、实现上的指针。

这一篇换个角度 —— 看它在真实项目里省下多少内存，以及 「传递指针」和「传递引用」到底差在哪。

背景换成游戏。游戏里最典型的对象就是「角色」，而角色恰好是一个 又大又经常被传来传去的东西 —— 拿它当例子，代价一眼就能看见。

这一篇的主线

传对象这件事，本质是在「搬内存」还是「递地址」之间选。

一个角色对象有一百多字节，一场战斗里每秒要被传几千次。 按值传 = 每次都搬一整份；按引用 / 指针传 = 每次只递 8 字节的地址。 这就是本篇要论证的「大幅减少内存开销」。

前置

Q02 讲的是引用本身（别名、绑定不可改）。这一篇假设你已经读过 Q02， 或者至少知道 T& 是「别名」的意思。M04 讲指针、 M06 讲类与结构体，也都会用到。

1例子：一个游戏角色

先看这一篇要反复用到的类。它就是最普通的写法 —— 一堆属性， 没有任何花招：

Actor.h —— 游戏角色复制
#include <string>

class Actor {
private:
    std::string full_name;   // 全名，比如「忘情牛肉面」
    std::string nickname;    // 昵称，比如「奶蛙」
    std::string address;     // 所在地图坐标名，比如「University of Naiwa」
    int maxLevel;            // 等级上限

public:
    int hp;                  // 当前血量
    int maxHp;               // 血量上限
    int atk;                 // 攻击力
    int def;                 // 防御力
    int mp;                  // 当前法力
    int maxMp;               // 法力上限
    int agi;                 // 敏捷
    int luk;                 // 幸运
};

这样的类在实际项目里满地都是：几个字符串 + 一堆数值属性。 它有两个特点，这一篇全靠它们展开：

它不小 三个 std::string 加九个 int， 一个对象就上百字节
它很忙 战斗系统每帧都要读它的属性、算伤害、回血 —— 同一帧里被传进传出十几次很正常
为什么 private / public 这么分

名字和地址是建立后就不该随便改的东西 —— 改名要走改名卡， 换地图要走传送。而血量、法力这些每帧都在变，所以放开。

这个划分正好对应第 5 节要讲的：只读的用 const T&， 要改的用 T&。

2它到底占多少内存

要谈「省了多少」，先得知道「原来是多少」。把成员一个个加起来：

成员类型 大小说明
full_namestd::string32 指针 + 长度 + 16 字节小缓冲
nicknamestd::string32 同上
addressstd::string32 同上
maxLevel, hp, maxHp, atk, def,
mp, maxMp, agi, luk		 int × 936 每个 4 字节
合计—132 96 + 36，正好 4 的倍数，不用补空隙
这三个 32 是怎么来的（以及为什么我没有写死）

多数 64 位编译器上 sizeof(std::string) 是 32： 一个指针（8）+ 一个长度（8）+ 16 字节的小字符串缓冲区。 那 16 字节是短字符串优化（SSO） —— 短名字直接存在对象里， 不长的时候才去堆上分配。

但这是实现细节，标准没规定。换了标准库或平台，数字会变。 所以：别记我这张表，去量你自己的。

size.cpp —— 数字要自己量复制
#include <iostream>
#include <string>
#include "Actor.h"

int main() {
    std::cout << "sizeof(std::string) = " << sizeof(std::string) << "\n";
    std::cout << "sizeof(Actor)       = " << sizeof(Actor)       << "\n";
    std::cout << "sizeof(Actor*)      = " << sizeof(Actor*)      << "\n";
}
输出（64 位，libstdc++）
sizeof(std::string) = 32
sizeof(Actor)       = 132
sizeof(Actor*)      = 8
关键的一个数字：一个 Actor 是 132 字节， 而它的地址只有 8 字节 —— 16.5 倍。 记住这个比例，下面全都由它推出来。

3按值传递：每帧搬几千份角色

先看最容易写出来的那种函数 —— 参数直接写类型：

battle.cpp —— 按值传递复制
#include <iostream>
#include "Actor.h"

// 只读：看一眼攻击力，不改任何东西
int damageOf(Actor a) {
    return a.atk * 2;
}

// 要改：加血
void heal(Actor a, int amount) {
    a.hp += amount;
    if (a.hp > a.maxHp) a.hp = a.maxHp;
}

int main() {
    Actor hero;
    hero.atk = 120;
    hero.hp  = 50;
    hero.maxHp = 200;

    std::cout << "伤害 = " << damageOf(hero) << "\n";

    heal(hero, 30);
    std::cout << "治疗后 hp = " << hero.hp << "\n";
}
输出
伤害 = 240
治疗后 hp = 50
两件事同时发生了 —— 一件浪费，一件是 bug
  1. 浪费：damageOf(hero) 只是要读一个 atk， 却把整个 132 字节复制了一遍。
  2. bug：heal 改的是副本， 所以 hero.hp 还是 50 —— 治疗完全没生效。

两件事是同一个原因：函数里的 a 不是 hero， 而是它的一份拷贝。

浪费有多少：算一遍

假设一场战斗里有 100 个角色，跑在 60 帧/秒， 每个角色每帧要被这类函数调用 3 次（算伤害、算治疗、刷新状态）：

按值传递（void heal(Actor a, int n)）
每次调用拷贝
132 B
= sizeof(Actor)
调用次数
18 000 / 秒
100 角色 × 3 次 × 60 帧
每秒搬运
约 2.3 MB
18000 × 132 B

而且这还只是「按值拷贝对象本身」。那三个 std::string 如果内容较长（超过 16 字节的小缓冲），拷贝时还要去堆上各分配一块内存 —— 一次调用就是三次 malloc 加三次 free。

名字短（走 SSO）
Actor a;              // 132 B
a.full_name = "奶蛙";  // 3 字符
a.nickname  = "牛肉面";  // 2 字符

heal(a, 30);
// 拷贝 132 B，无堆分配
名字长（走堆）
Actor a;
a.full_name = "忘情牛肉面·第三形态";
a.nickname  = "Naiwa 大学城的守望者";

heal(a, 30);
// 拷贝 132 B + 3 次 malloc + 3 次 free
结论：按值传递的代价是 「对象多大就搬多大」×「调用多频繁」。 角色越大、战斗越激烈，这个数字涨得越快 —— 而它完全没必要。

4按引用传递：只递一个地址

把参数类型后面加一个 &，别的都不动：

battle2.cpp —— 按引用传递复制
#include <iostream>
#include "Actor.h"

// 要改：加血 —— 这里的 a 就是外面那个角色本人
void heal(Actor& a, int amount) {
    a.hp += amount;
    if (a.hp > a.maxHp) a.hp = a.maxHp;
}

int main() {
    Actor hero;
    hero.hp = 50;
    hero.maxHp = 200;

    heal(hero, 30);
    std::cout << "治疗后 hp = " << hero.hp << "\n";

    heal(hero, 999);
    std::cout << "再治一次 hp = " << hero.hp << "\n";
}
输出
治疗后 hp = 80
再治一次 hp = 200

两件事一起变好了：

治疗生效了 函数里的 a 就是 hero， 改它等于改本体
不再搬 132 字节 只递了一个地址进去，对象本身一动没动

省下多少

按引用传递（void heal(Actor& a, int n)）
每次调用传递
8 B
一个地址而已
调用次数
18 000 / 秒
与上面同一场景
每秒传递
约 0.14 MB
18000 × 8 B
两个数字并排看
写法每次 每秒相对

void heal(Actor& a, int n)8 B 0.14 MB省掉 93.9%

2.3 MB 看着不多 —— 但那是每秒、而且只是这一个函数。 战斗系统里这类函数有几十个，再加技能、增益、AI 判定， 数字很快就上到几百 MB。

更关键的是：这 93.9% 是白拿的。改动只是加了一个 &。

顺带解决的：字符串也不复制了

按引用传递时，函数里的 a.full_name 直接就是原来那个 std::string —— 一次堆分配都不会发生。

所以上面说的「3 次 malloc + 3 次 free」也一起省掉了。 这部分开销不体现在 132 字节里，但往往比拷贝本身更贵。

5只读的场合：const 引用

上一节的 heal(Actor& a, …) 是要改的角色，所以用 Actor& 是对的。但「只读」的那些函数呢？

它们只想要第一个好处（不拷贝），不想要第二个（能被改）：

readonly.cpp —— 只读就该锁住复制
// ❌ 只是看一眼，却能被改 —— 读代码的人无法确定它会不会动 hero
int damageOf(Actor& a) {
    // a.hp = 0;      ← 这行居然合法！一个「查询」函数能秒杀角色
    return a.atk * 2;
}

// ✅ 不拷贝，同时明确「我绝不改它」
int damageOf(const Actor& a) {
    // a.hp = 0;      ← 这一行编译不过，正合我意
    return a.atk * 2;
}
const Actor& 把两件事同时给你
写法拷贝? 能改?
Actor a拷 132 B能（但改的是副本）
Actor& a不拷能改本体
const Actor& a不拷不能改

「只读 + 大对象」就写 const T&。 这是 C++ 里最常用的一种参数写法，也是最该先养成习惯的。

full.cpp —— 完整的战斗小例复制
#include <iostream>
#include <string>

class Actor {
private:
    std::string full_name, nickname, address;
    int maxLevel;
public:
    int hp, maxHp, atk, def, mp, maxMp, agi, luk;
};

// 只读 → const 引用
int  damageOf(const Actor& a)  { return a.atk * 2; }

// 要改 → 普通引用
void heal(Actor& a, int n) {
    a.hp += n;
    if (a.hp > a.maxHp) a.hp = a.maxHp;
}

// 要改，且「没目标」是正常情况 → 指针（见下一节）
void attack(Actor& from, Actor* target) {
    if (!target) return;              // 没有目标就跳过
    int dmg = damageOf(from) - target->def;
    if (dmg < 1) dmg = 1;              // 至少扣 1 点
    target->hp -= dmg;
    if (target->hp < 0) target->hp = 0;
}

int main() {
    Actor hero;  hero.atk = 120; hero.hp = 50;  hero.maxHp = 200; hero.def = 0;
    Actor slime; slime.def = 20; slime.hp = 300; slime.maxHp = 300;

    // ① 只读：看一眼
    std::cout << "英雄伤害 = " << damageOf(hero) << "\n";

    // ② 要改：治疗
    heal(hero, 30);
    std::cout << "治疗后英雄 hp = " << hero.hp << "\n";

    // ③ 打怪（传的是怪物的地址）
    attack(hero, &slime);
    std::cout << "怪物 hp = " << slime.hp << "\n";

    // ④ 没有目标：传 nullptr，函数自己跳过
    attack(hero, nullptr);
    std::cout << "空目标时英雄 hp = " << hero.hp << "\n";
}
输出
英雄伤害 = 240
治疗后英雄 hp = 80
怪物 hp = 80
空目标时英雄 hp = 80

这四行调用正好把三种写法都用上了 —— 注释里标了每一处为什么这么选。 第 ④ 行是第 6 节的重点：nullptr 能当参数传进去， 而引用做不到这件事。

6传递指针 vs 传递引用

两种都能避免拷贝，那该用哪个？先看同一个函数的两副样子：

传指针
void heal(Actor* a, int n) {
    if (!a) return;        // 必须防
    a->hp += n;            // 用 -> 访问
    if (a->hp > a->maxHp)
        a->hp = a->maxHp;
}

// 调用处要写 &
heal(&hero, 30);
传引用
void heal(Actor& a, int n) {
    // 不用防，没有「空引用」
    a.hp += n;             // 用 . 访问
    if (a.hp > a.maxHp)
        a.hp = a.maxHp;
}

// 调用处直接传对象
heal(hero, 30);

语法上的差别就这四处。但真正的区别只有一条：

唯一的决定性问题：这个参数可以「没有」吗？
情况能表达「没有」 该用
一定有目标不需要T& / const T&
可能没有目标（搜索失败、可选参数） 只有指针能T*

引用不能为空。要表达「没有」，只能用指针传 nullptr。 这是两者最本质的分工。

逐项对照

对比项指针 Actor* 引用 Actor&
能否为空能（nullptr）不能
调用处写法heal(&hero, 30)heal(hero, 30)
函数内访问a->hpa.hp
要不要判空要：if (!a) return;不用
能否改指向能：a = &other;不能，绑定不可改
传递的字节数88（实现上也是地址）
能否指向数组做算术能：a + 1不能
典型用途可选对象、遍历、容器参数传递的主力
「传递的字节数」这一行值得单独说

两者都是 8 字节 —— 引用在实现上就是地址。 所以省内存这件事上，指针和引用完全等价， 选哪个只看语义（能不能为空、要不要改指向），不看性能。

很多人以为「引用比指针快」，其实不会；它只是更安全、更短。

游戏里的具体选法

治疗、加 buff void heal(Actor& a, int n) —— 一定有目标，而且要改它 → 引用
查询属性 int hpOf(const Actor& a) —— 一定有、且只读 → const 引用
攻击目标 void attack(Actor& from, Actor* target) —— 可能没有目标 → 目标用指针
遍历全部怪物 for (Actor* m : monsters) —— 容器里存的就是指针，天然用指针
目标可能已死 用指针并传 nullptr，或者约定 「查不到就传 nullptr」—— 别用「一个特殊的空角色」来凑
一条容易走偏的思路

有人为了「避免判空」，就干脆全用引用。结果遇到「可能没有目标」时， 只能造一个假的空角色传进去 —— 那比传 nullptr 更难查、更危险（假对象的属性是什么？会不会被误伤？）。

该用指针的地方就用指针。判空那一行不是负担，是在把 「可能没有」这件事写进代码。

7指向对象的指针：从对象内部指出去

前面讲的都是把对象当参数传。对象内部也可以存指针或引用， 用来表示「我关联着另一个对象」。游戏里到处都是这种关系：

relation.cpp —— 角色之间的关联复制
class Actor;

class Skill {
private:
    std::string name;
public:
    int power;
    // 这个技能属于谁 —— 建立后不会变，用引用
    Actor& owner;
    Skill(Actor& o) : owner(o) {}
};

class Actor {
private:
    std::string full_name, nickname, address;
    int maxLevel;
public:
    int hp, maxHp, atk, def, mp, maxMp, agi, luk;

    // 当前锁定的目标 —— 可能没有，而且会随时改 → 指针
    Actor* target = nullptr;

    // 当前正在施放的技能 —— 可能没有 → 指针
    Skill* casting = nullptr;
};
成员该怎么选，看两个问题
  1. 它可能「不存在」吗？可能 → 指针（初值 nullptr）； 不可能 → 引用。
  2. 它会「换一个」吗？会（换目标、换技能）→ 指针； 不会（技能属于谁）→ 引用。

两个问题都是「否」才用引用。上面 owner 两问都否， target / casting 两问都是「是」。

成员用引用有个硬约束

引用必须在构造时就绑定，所以含引用的类不能默认构造， 赋值运算符也会被隐式删掉。上面 Skill 就不得不写 Skill(Actor& o) : owner(o) {}。

如果这个类还需要「先建后设」，那 owner 也得改成指针。 这是语法逼你做的选择，不是风格问题。

返回指针还是引用

return.cpp —— 查找类函数的两种返回复制
#include <vector>
#include <string>

class Actor {
private:
    std::string full_name, nickname, address;
    int maxLevel;
public:
    int hp = 100, maxHp = 100, atk = 10, def = 0;
    int mp = 0, maxMp = 0, agi = 0, luk = 0;
    const std::string& name() const { return full_name; }
};

// ① 一定找得到 → 返回引用（不拷贝）
Actor& leaderOf(std::vector<Actor>& team) {
    return team[0];
}

// ② 可能找不到 → 返回指针，找不到给 nullptr
Actor* findByName(std::vector<Actor>& team, const std::string& n) {
    for (Actor& a : team) {
        if (a.name() == n) return &a;
    }
    return nullptr;
}

这两者的分工和参数完全一致：「一定找得到」用引用，「可能找不到」用指针。 调用处也一眼能看出来：

调用处的区别复制
leaderOf(team).hp = 999;         // 引用：直接用，不用判

Actor* p = findByName(team, "奶蛙");
if (p) {                          // 指针：必须判
    p->hp = 999;
} else {
    std::cout << "队伍里没有叫奶蛙的\n";
}
绝不要返回局部对象的引用或指针

函数里的局部对象在返回时就销毁了，返回它的地址就是返回一块 已失效的内存。这一条 Q02 已经讲过（悬空引用），这里再强调一次， 因为「返回引用」这个手法很诱人。

安全的情形只有：返回的是参数传进来的对象， 或生命周期比函数长的对象（成员、容器元素）。

8常见错误

写法 / 想法问题
void heal(Actor a, int n) 拷 132 B，而且改的是副本 —— 治疗不生效
int damageOf(Actor& a) 只是查询却能改本体；读代码的人无法确定
读只读参数也写 Actor& 该写 const Actor& —— 少一个字，多一层保护
void attack(Actor& target) 却要表达「没目标」 引用不能为空；这种情况用 Actor* + nullptr
为了不判空而造一个「空角色」传进去 假对象比 nullptr 更难查、更危险
用 == 比较两个 Actor 比较的是成员逐个相等，不是「同一个对象」； 要判断「是不是同一个」应比地址
成员写成 Actor& target; 引用成员必须构造时绑定，且类会失去默认构造与赋值； 会变的关联要用指针
返回局部对象的 Actor& 悬空引用；只能返回参数或成员的引用
以为「引用比指针快」 两者传的都是 8 字节地址，性能上等价； 区别在语义（能不能为空、能不能改指向）
按值传 int 也想改成引用 int 只有 4 字节，比地址还小 —— 直接传值更好

9一页速查

三种参数写法

写法拷贝 能改本体什么时候用
T v整个对象不能（改副本） 小类型（int、double）
const T& v不拷不能 大对象 + 只读 —— 最常用
T& v不拷能 大对象 + 要改
T* v不拷能（还能改指向） 可能为空，或需要改指向

本篇的五个数字

① sizeof(std::string) = 32（64 位常见实现）
② sizeof(Actor) = 132 = 三个 string 96 + 九个 int 36
③ sizeof(Actor*) = 8 —— 地址就是 8 字节
④ 132 ÷ 8 ≈ 16.5 倍 —— 按值 vs 按引用，单次差这么多
⑤ 省掉 93.9% —— 100 角色 × 3 次 × 60 帧的场景下，2.3 MB/s → 0.14 MB/s

选择流程

1类型大吗？ 小（int 之类）→ 直接传值，收工
2可能没有吗？ 可能 → T*，传 nullptr
3要改它吗？ 要改 → T&
4只读 → const T&
一句话

大对象一律不要按值传。要改就 T&， 只读就 const T&，可能为空才用 T*。

这不会让代码变复杂 —— 大多数时候只是多一个 &， 换来的是九成以上的内存开销消失。

接下来看什么

这一篇讲的是「怎么把对象递出去不花钱」。顺着往下还有两件事值得单独看：

  • 右值引用与移动语义（T&&）—— 连「一定要转移所有权」的那一次拷贝也省掉；
  • 智能指针（std::unique_ptr / QSharedPointer）—— 指针用得多了， 「谁负责释放」就成了新问题，它就是这个问题的答案。
