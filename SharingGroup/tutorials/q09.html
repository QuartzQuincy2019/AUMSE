UME 项目组内部教程 · Q09（Q） · 函数指针与成员函数指针；Qt connect 那一句的四个参数

C++ 函数指针 成员函数指针

Q03 讲的是「指向对象的指针」。这一篇讲另一种指针 —— 指向函数的指针。

它本身不难，难的是一句话：Qt 的 connect 就是靠它工作的。 这一篇前半段把函数指针讲清，后半段只用一句话把它落到 Qt 的 connect 上。

1函数的地址

M04 讲过：变量住在编了号的房间里，& 能问出房间号。 函数也一样 —— 它同样是一段指令，占着一块内存，有一个首地址。

一句话区分「调用」和「取地址」

函数名后面加括号，是调用它；不加括号，它就代表它的地址。

同一个名字，两种用法复制
int add(int a, int b) { return a + b; }

add(3, 4);        /* ← 加括号：调用它，得到 7 */
&add            /* ← 不加括号：取它的地址，得到 int(*)(int,int) */

既然地址能取出来，就能存进一个变量 —— 这个变量就叫函数指针。 它和 M04 讲的指针是同一类东西：内容是一个地址。 只是它指向的不是数据，而是一段「能被调用的代码」。

2指向函数的指针：声明形式与括号的作用

函数的类型里带着「参数是什么、返回什么」。所以声明一个函数指针， 也要把这些都写出来。而写法上有一个非常容易错的点：

✅ 指向函数的指针
int (*fp)(int, int);

fp 外面有一对括号。
读作「fp 是一个指针，指向一个 收两个 int、返回 int 的函数」。

❌ 这是「函数」，不是指针
int *fp(int, int);

少了那对括号。
读作「fp 是一个函数，收两个 int、 返回 int*」—— fp 根本不是一个变量。

读法（从里往外）：先看 fp 紧挨着什么 ——
紧挨着 * 且带括号 → 它是指针；
紧挨着 ( → 它是函数。
那对括号的作用，就是把 * 和 fp 绑在一起。

下面这段只用 static_assert 让编译器替我们确认两者的类型：

让编译器自己说：一个是指针，一个是函数复制
#include <cstdio>
#include <type_traits>

int plus1(int a) { return a + 1; }

int (*fp1)(int);      /* 指针 */
int* fp2(int);        /* 这是函数声明！ */

static_assert(std::is_pointer_v<decltype(fp1)>);
static_assert(std::is_function_v<std::remove_pointer_t<decltype(fp2)>>);

int* fp2(int v) { static int x; x = v; return &x; }

int main() {
    fp1 = plus1;
    std::printf("fp1(41)     = %d\n", fp1(41));
    std::printf("*fp2(7)     = %d\n", *fp2(7));
    std::printf("sizeof(fp1) = %d\n", (int)sizeof(fp1));
    return 0;
}
运行结果（已核对）
fp1(41)     = 42
*fp2(7)     = 7
sizeof(fp1) = 8

两条 static_assert 都过了 —— 这就证明了： int (*fp1)(int) 是指针，int* fp2(int) 是函数。

类型别名：typedef 与 using

函数指针的类型写起来很长，可以先起个名字再反复用。两种写法等价， 新的那种（using）更好读：

typedef 与 using复制
typedef int (*BinOp)(int, int);   /* 老写法：名字夹在中间 */
using BinOp = int (*)(int, int);   /* 新写法：名字在等号左边，一眼看清 */

3函数指针的调用与回调

两种等价的调用写法

fp(a,b) 与 (*fp)(a,b) 是同一件事复制
#include <cstdio>
int add(int a, int b) { return a + b; }

int main() {
    int (*fp)(int, int) = add;            /* 函数名 → 地址 */
    std::printf("fp(3,4)     = %d\n", fp(3, 4));
    std::printf("(*fp)(3,4)  = %d\n", (*fp)(3, 4));
    return 0;
}
运行结果（已核对）
fp(3,4)     = 7
(*fp)(3,4)  = 7
给普通函数取地址，加不加 & 都一样

int (*fp)(int,int) = add; 与 … = &add; 是等价的， 两种都行。平时建议写 &add —— 一眼能看出「这里取的是地址」， 而不是漏写了括号的调用。

但这一条只对普通函数成立。指向成员函数时必须写 &， 下面第 4 节会看到编译器直接拒绝。

用途：把函数作为参数传入（回调）

函数指针最大的用处，是让一个函数把「具体做什么」交给调用方决定。 下面这个 apply 不知道自己要算什么，它只知道 「你会给我一个能收两个 int 的东西」：

同一个 apply，两种行为复制
#include <cstdio>

using BinOp = int (*)(int, int);   /* 给类型起名 */

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int apply(BinOp op, int a, int b) {    /* 参数就是一个「函数」 */
    return op(a, b);
}

int main() {
    std::printf("apply(add, 3, 4) = %d\n", apply(add, 3, 4));
    std::printf("apply(mul, 3, 4) = %d\n", apply(mul, 3, 4));
    return 0;
}
运行结果（已核对）
apply(add, 3, 4) = 7
apply(mul, 3, 4) = 12

同一个 apply，传 add 就是加，传 mul 就是乘 —— 代码没有改，行为变了。这种「把函数当参数传」的用法叫回调（callback）。

打个比方

apply 像一台「只会按按钮的机器」：你给它一个按钮， 它就在该按的时候按下去，但它不在乎那个按钮会触发什么。

至于是「加法按钮」还是「乘法按钮」，是你在外面装上去的。

4指向成员函数的指针：类作用域与对象绑定

到这里是普通函数。类里的成员函数有个额外的麻烦： 它不属于某一个对象，而属于整个类。所以它的指针也得多带一样东西 —— 「这是哪个类的成员」。

多出来的那一截 MyButton::复制
struct MyButton {
    void clicked()    { /* … */ }
    void testSignal() { /* … */ }
};

void (*pf)()           = &普通函数;          /* 普通函数指针 */
void (MyButton::*pmf)() = &MyButton::clicked;  /* 成员函数指针 */
/*   ^^^^^^^^^^^^^ 这一截就是「哪个类的成员」 */
普通函数指针成员函数指针
声明void (*pf)() void (MyButton::*pmf)()
类型里带什么参数 + 返回 参数 + 返回 + 属于哪个类
怎么调用pf() (obj.*pmf)()
(ptr->*pmf)()
要不要对象不要 要 —— 它自己不知道 this 是谁
必须配一个对象，才能调复制
#include <cstdio>

struct MyButton {
    void clicked()    { std::printf("clicked 被调用\n"); }
    void testSignal() { std::printf("testSignal 被调用\n"); }
};

int main() {
    void (MyButton::*pmf)() = &MyButton::clicked;
    std::printf("sizeof(成员函数指针) = %d\n", (int)sizeof(pmf));

    MyButton b;
    (b.*pmf)();                 /* 用对象调 */

    MyButton* p = &b;
    (p->*pmf)();                /* 用指针调 */
    return 0;
}
运行结果（已核对，MSVC 14.51 x64）
sizeof(成员函数指针) = 8
clicked 被调用
clicked 被调用
「一样大」不等于「一样」

这台机器上成员函数指针也是 8 字节，和普通函数指针一样大。 但类型完全不同 —— 把后者赋给前者，编译器直接拦下来：

实机报错（已核对）
error C2440: “初始化”: 无法从“void (__cdecl MyButton::* )(void)”
              转换为“void (__cdecl *)(void)”

看清楚报错里那两种写法：一个有 MyButton::、 一个没有。编译器分得清清楚楚，别被 sizeof 骗了。

5重载函数怎么取地址

前面几节默认「这个函数名只对应一个函数」。一旦有重载 （同名、参数不同），情况就变了。

先记住这一句

重载之后，函数名不再代表「一个函数」，而是一组候选。

所以 &show 单独拿出来是没有确定类型的 —— 必须有「目标类型」帮编译器挑出其中一个。 挑不出来就是编译错误，不会替你猜。

自由函数：靠左边的声明挑

技巧很简单：你把它赋给什么类型的指针，就取哪个重载。

目标类型决定取哪一个复制
void show(int x);
void show(double x);

/* 左边是 void(*)(int)，所以取 show(int) */
void (*fp)(int)    = show;

/* 左边是 void(*)(double)，所以取 show(double) */
void (*fd)(double) = show;

fp(7);
fd(7.0);
运行结果（已核对）
show(int)     7
show(double)  7.0

同一个 show，被两次赋给不同类型，取到了两个不同的函数。 决定权完全在左边那个类型上。

没有目标类型就挑不出来

用 auto 时左边没有类型可参考，编译器就无从下手：

取不出来复制
auto p = show;                 /* ✗ 不知道要哪一个 */
auto m = &Actor::damage;       /* ✗ 成员函数重载同样不行 */
实机报错（已核对）
error C3535: 无法推导“auto”的类型(依据“overloaded-function”)

注意报错里那个词：overloaded-function （重载函数）。看到它就知道是「没给目标类型」，不是别的问题。

写明白：static_cast

靠左边的声明来挑，能工作，但读代码的人得先看一眼左边。 想让人一眼看出选了哪个，就显式写出来：

显式指定复制
auto f = static_cast<void (*)(int)>(show);
f(8);
运行结果（已核对）
show(int)     8
什么时候该写 static_cast
  • 只有一行、类型就写在左边 → 直接用「靠左边挑」的写法，简洁。
  • 要传进别的函数、或者类型很长 → 写 static_cast， 否则读者要在两处之间来回找。

两种写法结果完全一样，差别只在可读性。

成员函数：规则一模一样

第 4 节说过，成员函数指针要多带一个「属于哪个类」。 遇到重载时，它同样靠目标类型挑 —— 只是那个类型长一点：

成员函数重载复制
struct Actor {
    int hp = 100;
    void damage(int n);       /* 扣固定点数 */
    void damage(double r);    /* 扣百分比 */
    int  read() const;          /* 只读 */
};

/* 目标类型是「Actor 的、参数是 int 的成员函数」→ 取 damage(int) */
void (Actor::*p1)(int)    = &Actor::damage;

/* 目标类型换成 double → 取 damage(double) */
void (Actor::*p2)(double) = &Actor::damage;

/* 注意末尾的 const：它也是类型的一部分 */
int  (Actor::*pr)() const = &Actor::read;

Actor a;
(a.*p1)(10);                       /* hp: 100 → 90 */
(a.*p2)(0.5);                      /* hp: 90 → 45 */
std::printf("read() via object = %d\n", (a.*pr)());

Actor* pa = &a;                    /* 换用对象指针，同一套指针照样能用 */
(pa->*p2)(0.2);                    /* hp: 45 → 36 */
std::printf("read() via ptr    = %d\n", (pa->*pr)());
运行结果（已核对）
damage(int)     hp=90
damage(double)  hp=45
read() via object = 45
damage(double)  hp=36
read() via ptr    = 36

三件事都对上了：

  • 两个重载各取一个：p1 扣固定 10 点，p2 扣 50%，血量 100 → 90 → 45。
  • const 是类型的一部分：read 是 int (Actor::*)() const，漏掉 const 就赋不过去。
  • 同一套指针，换对象照样用：(a.*p2) 与 (pa->*p2) 效果一样 —— 这正是第 4 节说的 「指针不知道自己属于哪个对象」。
别把成员函数指针赋给普通函数指针
类型不同复制
void (*bad)(int) = &Actor::damage;   /* ✗ 少了「属于哪个类」 */
实机报错（已核对）
error C2440: “初始化”: 无法从“overloaded-function”转换为“void (__cdecl *)(int)”

这两种指针不是一回事：普通函数指针就是一个地址； 成员函数指针还要知道「哪个对象」。所以不能互转。

三种写法的对照

写法结果说明
void (*p)(int) = show; ✅最常用：靠左边的声明挑重载
auto p = static_cast<void(*)(int)>(show); ✅把选择写在明面上，可读性最好
auto p = show; ❌ C3535没有目标类型，挑不出来
void (*p)(int) = &Actor::damage; ❌ C2440成员函数指针 ≠ 普通函数指针
这一节一句话

重载的取地址 = 「用目标类型做选择」。 自由函数和成员函数是同一套规则，只是成员函数那个类型里 多带一个「属于哪个类」和可能的 const。

6Qt connect 的四个参数

前面都是铺垫。Qt 里那句最常见的 connect，就是把 两个成员函数指针当参数传进去：

Qt 里把一个成员函数接到另一个成员函数上复制
connect(this, &MyButton::clicked, this, &MyButton::testSignal);

四个参数，两组「对象 + 成员函数」

#写的是什么类型
1this 第一个对象：谁先动 QObject*
（这里就是 MyButton*）
2&MyButton::clicked 第一个成员函数
（Qt 里的说法是「信号」）		 指向成员函数的指针
3this 第二个对象：谁跟着动 QObject*
4&MyButton::testSignal 第二个成员函数
（这里也是一个信号）		 指向成员函数的指针

写成一句话：当（1）的（2）发生，就去触发（3）的（4）。

这一句里，两个都是信号

testSignal 名字里就带着 Signal，这不是巧合 —— 它在 Qt 里确实是一个信号。而第 4 个位置允许填信号： 信号可以连信号。

所以这一句的效果是：clicked 一响，testSignal 跟着响 —— 等于把 clicked 转发成 testSignal。 这样外部只需要关心 testSignal 一个名字。

至于「信号」和「槽」在 Qt 里各是什么、内部怎么工作 —— 那要等学到 Qt 才讲，本篇不展开。这里只需要记住一件事： 第 2、4 个位置填的都是「指向成员函数的指针」。

与第 4 节的结论对应：对象由参数给出

回看第 4 节的结论：成员函数指针自己不知道 this 是谁， 必须配一个对象才能调。

而 connect 的第 1、3 个参数，给的正好就是那两个对象。 换句话说：

connect 的作用：把指针与对象配对

你交了两只「指向成员函数的指针」（第 2、4 个参数）， 再交两个对象（第 1、3 个参数）——

connect 把「指针 + 对象」配成两对收下。等第一个真的被触发， 它就照着配对去调第二个。

所以那一句里的 this 不能省：没有对象，成员函数指针就调不动。

要点确认

& 的必要性 &MyButton::clicked 里那个 & 是取地址，不是调用。不加会被编译器拒绝 —— 见下面第 8 节的实机报错。
不能写成 clicked() 加括号就是调用它了，得到的不是地址。 而且非静态成员函数也不能凭空调用（它要 this），编译器同样会拦。
两个 this 的含义 这两个成员函数都属于同一个对象。 第 1、3 个参数都填它，正好说明「谁和谁配成一对」—— 换了对象，就是另外一对。
这两个函数的性质 就只是 MyButton 的两个普通成员函数。 Qt 给它们起了「信号」「槽」这样的名字，属于 Qt 的约定 —— 但类型上没什么特别：都是「指向成员函数的指针」。
我实际验证到了哪一步

本机没有装 Qt，所以 connect 本身没法编译。 下面这些是实机验证过的（用 MSVC 14.51，配一个形状相同的模板函数）：

  • &MyButton::clicked 的类型确实是 void (MyButton::*)()（static_assert 通过）
  • 它和 &MyButton::testSignal 类型相同 —— 所以同一个模板参数吃得下这两个实参
  • 这一句的四个实参，能按这个顺序传进一个收 「对象指针、成员函数指针、对象指针、成员函数指针」的模板函数

至于 Qt 内部怎么存、怎么在触发时回调，属于 Qt 的实现细节， 本篇不靠推测展开。

7字符串式连接与成员函数指针式连接

Qt4 时代的写法是把函数名写成字符串：

旧写法：字符串复制
connect(btn, SIGNAL(clicked()), this, SLOT(testSignal()));   /* Qt4 */
旧：SIGNAL / SLOT 宏新：&类名::函数名
传的是什么一段字符串一个成员函数指针
名字打错照样编译过，运行时才发现连接没生效 编译期就报错：没有这个成员
签名对不上运行时才发现编译期就报错
改了函数名字符串不会跟着改，运行时悄悄失效 跟着一起改，改漏了编译不过

一句话：旧的把错误推到运行时，新的把错误拉到编译期。 这也是为什么现在的 Qt 代码几乎都用 &类名::函数名。

8常见错误

错误 1 · 漏写括号，把指针声明写成函数声明

手滑复制
int (*fp)(int);   /* ✅ 指针 */
int *fp(int);    /* ❌ 这是函数声明 */

如果还想给它赋初值，编译器会直接懵：

实机报错（已核对）
error C2061: 语法错误: 标识符“add”
error C2610: “int *fp(int)”: 不是可默认为的特殊成员函数或比较运算符

第二条报错看着莫名其妙 —— 因为它把你的话当成了「声明一个函数」。 看到这类奇怪的报错，先回头数括号。

错误 2 · 未绑定对象就调用成员函数指针

少了一个对象复制
void (MyButton::*pmf)() = &MyButton::clicked;
pmf();          /* ❌ 它不知道 this 是谁 */
(b.*pmf)();     /* ✅ 配上对象才行 */
实机报错（已核对）
error C2064: 项不会计算为接受 0 个参数的函数

错误 3 · 漏写取址运算符 &

成员函数必须写 &复制
connect(this, MyButton::clicked, this, MyButton::testSignal);   /* ❌ 少了 & */
实机报错（已核对）
error C3867: “MyButton::clicked”: 非标准语法；请使用 "&" 来创建指向成员的指针
error C3867: “MyButton::testSignal”: 非标准语法；请使用 "&" 来创建指向成员的指针

编译器把该怎么做都写在报错里了 ——「请使用 & 来创建指向成员的指针」。

错误 4 · 误把调用当成取址

括号是调用复制
connect(this, &MyButton::clicked(), this, &MyButton::testSignal);
/*                          ↑ 括号 = 调用，不是取地址 */
实机报错（已核对）
error C2352: “MyButton::clicked”: 调用非静态成员函数需要一个对象

错误 5 · 误以为大小相同即可互转

两者 sizeof 都是 8，但类型不同，赋不过去（回看第 4 节那张 C2440）。sizeof 相同不代表能互换 —— 类型系统认的是类型。

9一页速查

想做的事写法
声明一个函数指针 int (*fp)(int, int);
指向一个普通函数 fp = add;  或  fp = &add;

本讲要记住的四句话
  1. 函数名不加括号，就是它的地址。加了括号是调用。
  2. int (*fp)(int) 是指针，int *fp(int) 是函数。 区别就在那对括号。
  3. 成员函数指针多一层「属于哪个类」，所以必须配一个对象才能调用。
  4. connect 的四个参数，就是「两只指针 + 两个对象」 —— 它替你把这些配成对。
