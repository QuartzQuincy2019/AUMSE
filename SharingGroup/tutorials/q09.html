指针进阶：函数指针*

UME 项目组内部教程 · Q09（Q） · 函数也有地址；最后落到 Qt 的 connect 那一句

C++ 指针 Qt 信号与槽

Q03 讲的是「指向对象的指针」。这一篇讲另一种指针 —— 指向函数的指针。

它本身不难，难的是一句话：Qt 的 connect 就是靠它工作的。 这一篇前半段把函数指针讲清，后半段只用一句话把它落到 Qt 的信号与槽上。

1函数也有地址

M04 讲过：变量住在编了号的房间里，& 能问出房间号。 函数也一样 —— 它同样是一段指令，占着一块内存，有一个首地址。

一句话区分「调用」和「取地址」

函数名后面加括号，是调用它；不加括号，它就代表它的地址。

同一个名字，两种用法复制
int add(int a, int b) { return a + b; }

add(3, 4);        /* ← 加括号：调用它，得到 7 */
&add            /* ← 不加括号：取它的地址，得到 int(*)(int,int) */

既然地址能取出来，就能存进一个变量 —— 这个变量就叫函数指针。 它和 M04 讲的指针是同一类东西：内容是一个地址。 只是它指向的不是数据，而是一段「能被调用的代码」。

2指向函数的指针：括号的位置是关键

函数的类型里带着「参数是什么、返回什么」。所以声明一个函数指针， 也要把这些都写出来。而写法上有一个非常容易错的点：

✅ 指向函数的指针
int (*fp)(int, int);

fp 外面有一对括号。
读作「fp 是一个指针，指向一个 收两个 int、返回 int 的函数」。

❌ 这是「函数」，不是指针
int *fp(int, int);

少了那对括号。
读作「fp 是一个函数，收两个 int、 返回 int*」—— fp 根本不是一个变量。

读法（从里往外）：先看 fp 紧挨着什么 ——
紧挨着 * 且带括号 → 它是指针；
紧挨着 ( → 它是函数。
那对括号的作用，就是把 * 和 fp 绑在一起。

下面这段只用 static_assert 让编译器替我们确认两者的类型：

让编译器自己说：一个是指针，一个是函数复制
#include <cstdio>
#include <type_traits>

int plus1(int a) { return a + 1; }

int (*fp1)(int);      /* 指针 */
int* fp2(int);        /* 这是函数声明！ */

static_assert(std::is_pointer_v<decltype(fp1)>);
static_assert(std::is_function_v<std::remove_pointer_t<decltype(fp2)>>);

int* fp2(int v) { static int x; x = v; return &x; }

int main() {
    fp1 = plus1;
    std::printf("fp1(41)     = %d\n", fp1(41));
    std::printf("*fp2(7)     = %d\n", *fp2(7));
    std::printf("sizeof(fp1) = %d\n", (int)sizeof(fp1));
    return 0;
}
运行结果（已核对）
fp1(41)     = 42
*fp2(7)     = 7
sizeof(fp1) = 8

两条 static_assert 都过了 —— 这就证明了： int (*fp1)(int) 是指针，int* fp2(int) 是函数。

给这个类型起个名字

函数指针的类型写起来很长，可以先起个名字再反复用。两种写法等价， 新的那种（using）更好读：

typedef 与 using复制
typedef int (*BinOp)(int, int);   /* 老写法：名字夹在中间 */
using BinOp = int (*)(int, int);   /* 新写法：名字在等号左边，一眼看清 */

3怎么调用，它有什么用

两种调用写法，完全等价

fp(a,b) 与 (*fp)(a,b) 是同一件事复制
#include <cstdio>
int add(int a, int b) { return a + b; }

int main() {
    int (*fp)(int, int) = add;            /* 函数名 → 地址 */
    std::printf("fp(3,4)     = %d\n", fp(3, 4));
    std::printf("(*fp)(3,4)  = %d\n", (*fp)(3, 4));
    return 0;
}
运行结果（已核对）
fp(3,4)     = 7
(*fp)(3,4)  = 7
给普通函数取地址，加不加 & 都一样

int (*fp)(int,int) = add; 与 … = &add; 是等价的， 两种都行。平时建议写 &add —— 一眼能看出「这里取的是地址」， 而不是漏写了括号的调用。

但这一条只对普通函数成立。指向成员函数时必须写 &， 下面第 4 节会看到编译器直接拒绝。

它到底有什么用：把「要做的事」当参数传

函数指针最大的用处，是让一个函数把「具体做什么」交给调用方决定。 下面这个 apply 不知道自己要算什么，它只知道 「你会给我一个能收两个 int 的东西」：

同一个 apply，两种行为复制
#include <cstdio>

using BinOp = int (*)(int, int);   /* 给类型起名 */

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int apply(BinOp op, int a, int b) {    /* 参数就是一个「函数」 */
    return op(a, b);
}

int main() {
    std::printf("apply(add, 3, 4) = %d\n", apply(add, 3, 4));
    std::printf("apply(mul, 3, 4) = %d\n", apply(mul, 3, 4));
    return 0;
}
运行结果（已核对）
apply(add, 3, 4) = 7
apply(mul, 3, 4) = 12

同一个 apply，传 add 就是加，传 mul 就是乘 —— 代码没有改，行为变了。这种「把函数当参数传」的用法叫回调（callback）。

打个比方

apply 像一台「只会按按钮的机器」：你给它一个按钮， 它就在该按的时候按下去，但它不在乎那个按钮会触发什么。

至于是「加法按钮」还是「乘法按钮」，是你在外面装上去的。

4指向成员函数的指针：多一个「哪个对象」

到这里是普通函数。类里的成员函数有个额外的麻烦： 它不属于某一个对象，而属于整个类。所以它的指针也得多带一样东西 —— 「这是哪个类的成员」。

多出来的那一截 MyButton::复制
struct MyButton {
    void clicked()    { /* … */ }
    void testSignal() { /* … */ }
};

void (*pf)()           = &普通函数;          /* 普通函数指针 */
void (MyButton::*pmf)() = &MyButton::clicked;  /* 成员函数指针 */
/*   ^^^^^^^^^^^^^ 这一截就是「哪个类的成员」 */
普通函数指针成员函数指针
声明void (*pf)() void (MyButton::*pmf)()
类型里带什么参数 + 返回 参数 + 返回 + 属于哪个类
怎么调用pf() (obj.*pmf)()
(ptr->*pmf)()
要不要对象不要 要 —— 它自己不知道 this 是谁
必须配一个对象，才能调复制
#include <cstdio>

struct MyButton {
    void clicked()    { std::printf("clicked 被调用\n"); }
    void testSignal() { std::printf("testSignal 被调用\n"); }
};

int main() {
    void (MyButton::*pmf)() = &MyButton::clicked;
    std::printf("sizeof(成员函数指针) = %d\n", (int)sizeof(pmf));

    MyButton b;
    (b.*pmf)();                 /* 用对象调 */

    MyButton* p = &b;
    (p->*pmf)();                /* 用指针调 */
    return 0;
}
运行结果（已核对，MSVC 14.51 x64）
sizeof(成员函数指针) = 8
clicked 被调用
clicked 被调用
「一样大」不等于「一样」

这台机器上成员函数指针也是 8 字节，和普通函数指针一样大。 但类型完全不同 —— 把后者赋给前者，编译器直接拦下来：

实机报错（已核对）
error C2440: “初始化”: 无法从“void (__cdecl MyButton::* )(void)”
              转换为“void (__cdecl *)(void)”

看清楚报错里那两种写法：一个有 MyButton::、 一个没有。编译器分得清清楚楚，别被 sizeof 骗了。

5Qt 的 connect：这一句到底传了什么

前面都是铺垫。Qt 里那句最常见的 connect，就是把 两个成员函数指针当参数传进去：

Qt 的信号与槽连接复制
connect(this, &MyButton::clicked, this, &MyButton::testSignal);

四个参数，两对

#写的是什么类型
1this 发送者：谁发出信号 QObject*
（这里就是 MyButton*）
2&MyButton::clicked 信号：发出什么 指向成员函数的指针
3this 接收者：谁来处理 QObject*
4&MyButton::testSignal 槽：用什么函数处理 指向成员函数的指针

读成一句话就是：

当（第 1 个参数那个对象）的（第 2 个参数那个函数）被发出时，
就调用（第 3 个参数那个对象）的（第 4 个参数那个函数）。

这就是第 4 节说的「多一个哪个对象」

回看第 4 节的结论：成员函数指针自己不知道 this 是谁， 必须配一个对象才能调。

而 connect 的第 1、3 个参数，给的正好就是那两个对象。 换句话说：

connect 干的事，就是替你「配对」

你交了两只「指向成员函数的指针」（第 2、4 个参数）， 再交两个对象（第 1、3 个参数）——

connect 把「指针 + 对象」配成两对存起来。 等信号真的发出，它就照着配对去调槽。

所以那一句里的 this 不能省：没有对象，成员函数指针就调不动。

逐项确认这几件事

为什么要写 & &MyButton::clicked 里那个 & 是取地址，不是调用。不加会被编译器拒绝 —— 见下面第 7 节的实机报错。
为什么不是 clicked() 加括号就是调用它了，得到的不是地址。 而且非静态成员函数也不能凭空调用（它要 this），编译器同样会拦。
信号和槽是什么 都只是普通的成员函数。区别只在写法约定： 信号一般只声明、实现由 Qt 的元对象机制生成；槽则和普通函数一样自己写。
为什么两个 this 这句写在 MyButton 自己的成员函数里， 所以发送者和接收者都是自己 —— 「我自己的信号，接到我自己的槽上」。 两个 this 恰好说明「哪两个配对」。
我实际验证到了哪一步

本机没有装 Qt，所以 connect 本身没法编译。 下面这些是实机验证过的（用 MSVC 14.51，配一个形状相同的模板函数）：

  • &MyButton::clicked 的类型确实是 void (MyButton::*)()（static_assert 通过）
  • 它和 &MyButton::testSignal 类型相同 —— 所以同一个模板参数吃得下这两个实参
  • 这一句的四个实参，能按这个顺序传进一个收 「对象指针、成员函数指针、对象指针、成员函数指针」的模板函数

至于 Qt 内部怎么存、怎么在信号发出时回调，属于 Qt 的实现细节， 本篇不靠推测展开。

6为什么现在都这么写

Qt4 时代的写法是把函数名写成字符串：

旧写法：字符串复制
connect(btn, SIGNAL(clicked()), this, SLOT(testSignal()));   /* Qt4 */
旧：SIGNAL / SLOT 宏新：&类名::函数名
传的是什么一段字符串一个成员函数指针
名字打错照样编译过，运行时才发现槽没被调用 编译期就报错：没有这个成员
签名对不上运行时才发现编译期就报错
改了函数名字符串不会跟着改，运行时悄悄失效 跟着一起改，改漏了编译不过

一句话：旧的把错误推到运行时，新的把错误拉到编译期。 这也是为什么现在的 Qt 代码几乎都用 &类名::函数名。

7常见错误

错误 1 · 少写括号，把指针写成了函数

手滑复制
int (*fp)(int);   /* ✅ 指针 */
int *fp(int);    /* ❌ 这是函数声明 */

如果还想给它赋初值，编译器会直接懵：

实机报错（已核对）
error C2061: 语法错误: 标识符“add”
error C2610: “int *fp(int)”: 不是可默认为的特殊成员函数或比较运算符

第二条报错看着莫名其妙 —— 因为它把你的话当成了「声明一个函数」。 看到这类奇怪的报错，先回头数括号。

错误 2 · 成员函数指针没配对象就想调

少了一个对象复制
void (MyButton::*pmf)() = &MyButton::clicked;
pmf();          /* ❌ 它不知道 this 是谁 */
(b.*pmf)();     /* ✅ 配上对象才行 */
实机报错（已核对）
error C2064: 项不会计算为接受 0 个参数的函数

错误 3 · 忘了写 &

成员函数必须写 &复制
connect(this, MyButton::clicked, this, MyButton::testSignal);   /* ❌ 少了 & */
实机报错（已核对）
error C3867: “MyButton::clicked”: 非标准语法；请使用 "&" 来创建指向成员的指针
error C3867: “MyButton::testSignal”: 非标准语法；请使用 "&" 来创建指向成员的指针

编译器把该怎么做都写在报错里了 ——「请使用 & 来创建指向成员的指针」。

错误 4 · 加括号当成了取地址

括号是调用复制
connect(this, &MyButton::clicked(), this, &MyButton::testSignal);
/*                          ↑ 括号 = 调用，不是取地址 */
实机报错（已核对）
error C2352: “MyButton::clicked”: 调用非静态成员函数需要一个对象

错误 5 · 以为「大小一样」就能互转

两者 sizeof 都是 8，但类型不同，赋不过去（回看第 4 节那张 C2440）。sizeof 相同不代表能互换 —— 类型系统认的是类型。

8一页速查

想做的事写法
声明一个函数指针 int (*fp)(int, int);
指向一个普通函数 fp = add;  或  fp = &add;
调用它 fp(a, b)  或  (*fp)(a, b)
给类型起名 using BinOp = int (*)(int, int);
把「做什么」当参数传 int apply(BinOp op, int a, int b)
声明一个成员函数指针 void (MyButton::*pmf)();
指向一个成员函数（必须带 &） pmf = &MyButton::clicked;
调用成员函数指针 (obj.*pmf)()  或  (ptr->*pmf)()
Qt 连接信号与槽 connect(发送者, &发送者类::信号,
        接收者, &接收者类::槽);
本讲要记住的四句话
  1. 函数名不加括号，就是它的地址。加了括号是调用。
  2. int (*fp)(int) 是指针，int *fp(int) 是函数。 区别就在那对括号。
  3. 成员函数指针多一层「属于哪个类」，所以必须配一个对象才能调用。
  4. connect 的四个参数，就是「两只指针 + 两个对象」 —— 它替你把这些配成对。
