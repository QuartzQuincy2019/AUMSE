冒泡排序与算法复杂度

UME 项目组内部教程 · R02（Related） · 从「把一排数字排好」说起

C++ 本讲：冒泡排序怎么排、复杂度怎么看

1先把「排序」当成一个正经需求

你大概会觉得排序是个老掉牙的话题。但在真实项目里，它是最常被写错、 也最容易写慢的一类代码。先看几个具体场景：

场景要排什么
文件列表按名字 / 按修改时间列出来字符串、时间戳
通讯录按拼音首字母分组几百到几千条
把一批字形按码位顺序整理整数（码位）
日志按时间排序后找出连续异常可能几十万条
搜索结果按相关度从高到低带权重的条目

这些需求的共同点是：数据量差别极大。 通讯录几千条怎么排都行；日志几十万条，选错算法就要等好几秒。

本篇要回答的问题
  1. 「排序」到底是怎么排的 —— 用一个最简单的算法把它拆开看；
  2. 「算法复杂度」这个词到底在说什么 —— 为什么它比「跑一遍看看多快」更有用。

只用冒泡排序这一个例子讲透，不铺开讲十种排序。

2冒泡排序：最直白的想法

把一排数字排成从小到大，最不需要动脑子的做法是：

核心想法

从左到右，每次只比相邻的两个；如果左边比右边大，就交换它们。

这样走完一趟，最大的那个数一定会被「推」到最右边 —— 就像气泡从水底浮上来，所以叫冒泡。

先手动走一遍，比看代码有用。数组 [5, 3, 8, 1]，走第一趟：

第一趟：目标是把最大的 8 送到最右边复制
起点            [5, 3, 8, 1]
比 5 和 3 → 换   [3, 5, 8, 1]     5 > 3，交换
比 5 和 8 → 不换 [3, 5, 8, 1]     5 < 8，不动
比 8 和 1 → 换   [3, 5, 1, 8]     8 > 1，交换
                └──────────┘
                 8 已经到最右边 ✓

第二趟对前三个数做同样的事，把 5 推到倒数第二位：

后续趟数复制
第二趟  [3, 5, 1, 8] → [3, 1, 5, 8]     5 到倒数第二 ✓
第三趟  [3, 1, 5, 8] → [1, 3, 5, 8]     3 到倒数第三 ✓
第四趟  [1, 3, 5, 8] → 没有交换，已是终态
5
3
8
1

初始状态 [5, 3, 8, 1]（柱高代表数值大小）

3写成 C++ 代码

把刚才的手工过程翻译成代码，最朴素的一版：

bubble_v1.cpp —— 朴素版复制
#include <iostream>
#include <vector>

void bubble(std::vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {          // 一共走 n-1 趟
        for (int j = 0; j < n - 1; ++j) {      // 每趟从头比到尾
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
            }
        }
    }
}

void print(const std::vector<int>& a) {
    for (int x : a) std::cout << x << ' ';
    std::cout << '\n';
}

int main() {
    std::vector<int> a{5, 3, 8, 1};
    bubble(a);
    print(a);
}
输出
1 3 5 8

能跑，但这一版很浪费。看两个问题：

朴素版的两个浪费
  1. 内层每次都比到末尾。 但第 1 趟结束后，最右边的 8 一定已经是最大的 —— 第 2 趟根本不需要再比它。每趟都能少比一个。
  2. 数据本来就排好了，还是要走完全部 n−1 趟。 上面例子里第 4 趟一个交换都没发生，说明已经有序， 但代码仍然老老实实跑完剩下的循环。

4两次优化：让冒泡快一个数量级

针对上面两个浪费，各改一处：

bubble_v2.cpp —— 优化版复制
void bubble(std::vector<int>& a) {
    int n = (int)a.size();

    for (int i = 0; i < n - 1; ++i) {
        bool swapped = false;            // 优化②：记录本趟有没有交换

        // 优化①：末尾 i 个已经排好，不必再比 —— 上界是 n-1-i
        for (int j = 0; j < n - 1 - i; ++j) {
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
                swapped = true;
            }
        }

        if (!swapped) break;             // 一趟没交换 → 已经有序，提前收工
    }
}

两处改动各解决一个问题：

改动改了什么省下多少
优化①内层上界从 n-1 改成 n-1-i 比较次数从 n² 量级降到约 一半（n(n−1)/2）
优化②本趟没发生交换就 break 对已经有序或接近有序的数据，从 n² 降到 n
优化②的效果有多大？

如果输入本来就是 [1, 2, 3, 4, 5]：

  • 朴素版：仍然老老实实跑 4 趟，比较 4×4 = 16 次；
  • 优化版：第 1 趟比 4 次，一次没换，break —— 总共 4 次。

数据越大，差距越悬殊：n = 10000 时是 1 亿次 vs 1 万次， 也就是「跑几十秒」和「瞬间」的区别。

5算法复杂度：不看秒表，看增长

「这段代码快不快」不能靠在你这台电脑上掐表 —— 换台机器、换个编译器、数据规模一变，结论就全变了。 所以人们换一个问法：

换一个问法

当数据量 n 变大时，运行时间按什么速度涨？

这就是「算法复杂度」。它描述的是增长趋势，不是具体秒数。

拿冒泡排序数一数。朴素版是两层循环，每层各走约 n 次，所以比较次数是：

比较次数复制
朴素版:   (n-1) × (n-1) ≈ n²
优化①后:  (n-1) + (n-2) + ... + 1 = n(n-1)/2 ≈ n²/2

两者都是「n 的平方」这个量级 → 记作 O(n²)

O(n²) 里的那个 O 读作「大 O」， 意思是「数量级是」。常数系数（比如上面的 1/2）被丢掉了 —— 因为 n 足够大时，决定快慢的是指数（平方、立方），不是系数。

n（数据量）O(n²) 比较次数O(n log n) 比较次数相差
10100333 倍
10010,00066415 倍
1,0001,000,0009,966100 倍
10,000100,000,000132,877753 倍
100,00010,000,000,0001,660,9646020 倍

n 每涨 10 倍，O(n²) 的代价涨 100 倍，而 O(n log n) 只涨约 11～13 倍。 这就是为什么「数据小的时候什么都不用管， 数据一大就必须换算法」。

常见误区

误区一：O(n²) 就一定慢。 不一定。n = 20 时 O(n²) 只要 400 次比较，比任何「高级算法」的启动开销都小。 复杂度只在 n 足够大时才有意义。

误区二：O(n log n) 一定比 O(n²) 快。 同上的道理 —— 渐进复杂度忽略的常数，在小 n 时可能占主导。

6为什么实际项目里不写冒泡

既然冒泡能排对，为什么标准库不给你一个 std::bubble_sort？

因为存在同一量级但常数小得多的算法。看一个实际对比：

sort_race.cpp —— 冒泡 vs std::sort复制
#include <iostream>
#include <vector>
#include <algorithm>
#include <chrono>
#include <random>

using Clock = std::chrono::steady_clock;

void bubble(std::vector<int>& a) {
    int n = (int)a.size();
    for (int i = 0; i < n - 1; ++i) {
        bool sw = false;
        for (int j = 0; j < n - 1 - i; ++j)
            if (a[j] > a[j + 1]) { std::swap(a[j], a[j + 1]); sw = true; }
        if (!sw) break;
    }
}

int main() {
    std::mt19937 rng(42);
    std::uniform_int_distribution<int> d(0, 1000000);

    for (int n : {1000, 5000, 20000}) {
        std::vector<int> v(n);
        for (int& x : v) x = d(rng);

        auto a1 = v, a2 = v;

        auto t0 = Clock::now();
        bubble(a1);
        auto t1 = Clock::now();
        std::sort(a2.begin(), a2.end());
        auto t2 = Clock::now();

        auto ms = [](auto x, auto y) {
            return std::chrono::duration_cast<std::chrono::milliseconds>(y - x).count();
        };
        std::cout << "n=" << n
                  << "  冒泡 " << ms(t0, t1) << " ms"
                  << "   std::sort " << ms(t1, t2) << " ms\n";
    }
}
输出（g++ 13.1.0，-O2，某台普通办公机）
n=1000   冒泡 3 ms     std::sort 0 ms
n=5000   冒泡 103 ms   std::sort 1 ms
n=20000  冒泡 1698 ms  std::sort 3 ms
从这组数字能读出三件事
  1. n 涨 20 倍，冒泡慢了 566 倍（3 → 1698 ms）—— 这就是 O(n²) 的样子，肉眼可见。
  2. std::sort 只慢了几毫秒 —— 它是 O(n log n) 量级。
  3. n = 1000 时两者都不慢（3 ms vs 0 ms）。 数据量小的时候，选什么算法无所谓 —— 这正是复杂度「只管大 n」的含义。
结论：日常写代码，排序就用 std::sort（或 std::stable_sort）。 自己手写排序只在两种情况下有意义 —— 教学，或者你的数据量真的非常小（几十个）且 std::sort 的开销不可接受。

7冒泡唯一还有用的地方：稳定性

排序算法还有一个容易被忽略的性质：稳定性（stability）。

什么叫稳定

如果两个元素的排序键相同，稳定排序会保持它们原来的先后顺序； 不稳定排序则可能把它们的次序打乱。

举例：按「年龄」给人排序，输入里有两个 25 岁的人（小明在前）：

稳定性的意义复制
输入:  小明(25), 小红(23), 小刚(25)

稳定排序:  小红(23), 小明(25), 小刚(25)   ← 小明仍在 小刚 前面 ✓
不稳定排序: 小红(23), 小刚(25), 小明(25)   ← 25 岁两人的次序被打乱

冒泡排序（只要写成 a[j] > a[j+1] 而不是 >=） 天然是稳定的 —— 相等的元素不会被交换，相对次序自然保留。

实际用法：多关键字排序

要按「先年龄、年龄相同按姓名」排，稳定排序可以分两步做： 先按姓名排，再按年龄排（用稳定排序）。 第二次排序不会打乱第一次的结果，最终就是「年龄优先、姓名次之」。

C++ 里对应的就是 std::stable_sort。 不过更直接的做法是给 std::sort 传一个自定义比较函数， 一次比完两个键 —— 两者都可以，看场景。

8常见错误

写法问题
j < n内层循环越界：a[j+1] 会读到 a[n]，崩或读到垃圾值
j < n - 1 - i 写成 j <= n - 1 - i同样越界，多比一次
比较写成 a[j] >= a[j+1]相等也交换 → 不稳定，且做无用功
忘了 swapped 标记结果对，但接近有序的数据白跑很多趟
外层 i 从 1 开始还写 n-1-i趟数少一次，最后一个元素可能没排到
对大数组用冒泡10 万条要跑几分钟 —— 直接换 std::sort
最危险的一个：越界不一定报错

a[j+1] 越界读 a[n] 时，程序常常不崩 —— 它读到的是 vector 后面的内存，值不确定。 于是「大部分时候结果是对的，偶尔错一个数」，极难查。

用 v.at(i) 代替 v[i] 可以让越界直接抛异常， 调试时很好用（代价是运行稍慢，正式版可以换回来）。

9一页速查

概念一句话例子
冒泡排序相邻两两比较，大的往后推每趟把当前最大的送到末尾
优化①末尾已排好的不再比内层上界 n-1-i
优化②一趟没交换就说明有序if (!swapped) break;
O(n²)代价随 n 的平方增长冒泡、选择、插入排序
O(n log n)代价随 n log n 增长std::sort、归并、堆排序
稳定性键相同的元素保持原次序冒泡稳定，std::sort 不稳定
该用哪个能用标准库就别手写std::sort / std::stable_sort
实际写代码时照抄这一段复制
#include <algorithm>

std::sort(v.begin(), v.end());                       // 从小到大
std::sort(v.begin(), v.end(), std::greater<int>()); // 从大到小
std::stable_sort(v.begin(), v.end());                // 需要稳定时

// 自定义规则：按字符串长度排，长度相同按字典序
std::sort(v.begin(), v.end(), [](const auto& a, const auto& b) {
    if (a.size() != b.size()) return a.size() < b.size();
    return a < b;
});
一句话记住复杂度： O(n²) 是「每多一个数据，就要和已有的每一个都比一遍」； O(n log n) 是「每多一个数据，只要比 log n 次」。 n = 10000 时，前者一亿次，后者十三万次 —— 差 750 倍。
