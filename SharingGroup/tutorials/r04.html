十六进制颜色模型、HSV 与 Alpha*

UME 项目组内部教程 · R04（R） · 颜色在代码里怎么表示：十六进制 RGB、HSV、Alpha 与安全色

CSS 颜色模型 取色

为什么这一篇标了 *

做界面、做字体、做导出图，颜色是天天要碰的东西。 而颜色在代码里是用数字表示的 —— 不懂这套表示法，就只能靠试，改一次看一次。

这一篇把它讲透。不用记，但要懂。

1颜色在计算机里是什么

显示器由无数个发光的小点组成。每个点里有三个小灯： 红（Red）、绿（Green）、蓝（Blue）。

核心原理

调这三个灯的亮度，就能混出几乎所有颜色。

所以「一个颜色」在代码里其实是一组三个数：(红, 绿, 蓝)。

这叫 RGB 颜色模型。

灯的亮度混出来
全灭 (0,0,0)黑色
全亮 (255,255,255)白色
只亮红 (255,0,0)纯红
红+绿 (255,255,0)黄色
红+蓝 (255,0,255)品红（洋红）
绿+蓝 (0,255,255)青色
三个都是中间值 (128,128,128)灰色
为什么是「加法」

因为屏幕是自己发光的。灯越多越亮 → 全亮是白。

而打印机是反射光的，颜料越多越暗 → 全混是黑。 所以印刷用 CMY（青品黄）减法模型，和屏幕相反。

为什么最大是 255

因为每个灯用一个字节（8 位）存亮度：2⁸ = 256 档，从 0 到 255。

0   → 0000 0000  → 灯全灭
255 → 1111 1111  → 灯最亮
128 → 1000 0000  → 一半亮度

所以一个 RGB 颜色正好占 3 字节 —— 这也解释了后面看到的 「6 位十六进制」为什么刚好够。

★2十六进制 RGB

CSS 里最常写的颜色格式是 #RRGGBB：

十六进制颜色复制
/*  # 红 绿 蓝   每两位一组 */
   #FF0000    /* 纯红 */
   #00FF00    /* 纯绿 */
   #0000FF    /* 纯蓝 */
   #FFFFFF    /* 白 */
   #000000    /* 黑 */
   #1F6FEB    /* 本文档用的那个蓝 */
怎么读 #1F6FEB
分组十六进制换算成十进制
1F1×16 + 1531 → 红
6F6×16 + 15111 → 绿
EB14×16 + 11235 → 蓝

所以 #1F6FEB 就是 rgb(31, 111, 235) —— 两种写法是同一个颜色。

十六进制速记

十六进制位十进制含义
00全灭
F15这一位满
FF255整个通道满
80128约一半
4064约四分之一

十六进制只有 16 个符号：0-9 然后 A=10, B=11, C=12, D=13, E=14, F=15。 凑不出 16 个数才用字母 —— 这就是「为什么有字母」的全部原因。

六位可以缩成三位

缩写规则复制
/* 每一组两位相同 → 可以各留一位 */
#FF0000   →   #F00       /* 同一个红色 */
#FFFFFF   →   #FFF       /* 同一个白色 */
#1F6FEB   →   /* 缩不了：1F 两位不同 */

3十进制 RGB 表示法

不想换算就用十进制写法，更直观：

三种常用的等价写法复制
.a { color: #1F6FEB; }               /* 十六进制（最常用） */
.b { color: rgb(31, 111, 235); }    /* 十进制 0~255 */
.c { color: rgb(12%, 44%, 92%); }    /* 百分比 */
写法什么时候用
#1F6FEB设计稿上抄来的值，一般都用这个
rgb(31,111,235)想微调某个通道时更好读
rgb(12%,44%,92%)需要按比例算时

灰色系的写法

三个通道相等就是灰。CSS 里有个更短的词 gray 系列，但不够用， 实际都自己写：

做界面最常用的几个灰复制
#000000   /* 纯黑 —— 正文别用，太刺眼 */
#1a1f28   /* 近黑，正文色（本文档就用它） */
#4b5563   /* 次级文字 */
#8b95a5   /* 辅助文字 / 注释 */
#ccd5e3   /* 边框 */
#e3e8f0   /* 浅分隔线 */
#f7f9fc   /* 浅灰背景 */
#ffffff   /* 纯白 */
为什么正文不用纯黑

#000 在白底上对比度过高，长时间看容易累。 所以正经的界面正文都用 #1a1f28 这类「近黑」。

同理，纯白背景也常调成 #fafbfc 这种「近白」。

4HSV / HSL 颜色模型

RGB 的问题是不直观：「这个蓝再亮一点」在 RGB 里要同时改三个数，还容易改偏色。

于是有了另一套模型 —— HSV（也叫 HSB）和它的近亲 HSL：

字母含义取值
HHue 色相：什么颜色 0~360 度（色环上的角度）
SSaturation 饱和度：多鲜艳 0% = 灰，100% = 最鲜艳
VValue 明度（HSL 里是 Lightness 亮度） 0% = 黑，100% = 最亮
色相环：0~360 度
   0°  红
  60°  黄
 120°  绿
 180°  青
 240°  蓝
 300°  品红
 360°  回到红

所以「把红调成绿」就是 H 从 0 改成 120 —— 一个数的事，不用担心改出偏色。

HSL 在 CSS 里能直接用

同一个蓝的四种写法复制
hsl(217, 83%, 52%)      /* ← 本文档那个蓝 */
rgb(31, 111, 235)
#1F6FEB

/* 想调亮一点点：只动 L */
hsl(217, 83%, 62%)      /* 同样的蓝，亮一档，色相没变 */
什么时候 HSL 比 RGB 好用
  • 做「同色系深浅」：保持 H 和 S，只调 L —— 自动得到一组和谐的颜色
  • 做 hover 效果：hsl(217,83%,52%) → hsl(217,83%,62%)，只改一个数
  • 做灰阶：S 设 0%，只调 L

反过来，如果颜色是从设计稿抄来的，直接用十六进制，不用换算。

★5Alpha 通道（透明度）

前面三个数定「什么颜色」。再加第四个数就能定「多透明」—— 这叫 Alpha 通道。

Alpha 值效果
1.0 或 100%完全不透明（默认）
0.5 或 50%半透明，能看到背后
0.15 或 15%很淡，常用于浅色背景
0 或 0%完全透明（看不见，但仍占位置）
四种写法复制
/* ① 八位十六进制：最后两位是 alpha */
#1F6FEB80              /* 80 = 128/255 ≈ 50% 透明 */

/* ② rgba，第四个参数 0~1 */
rgba(31, 111, 235, 0.5)

/* ③ hsla */
hsla(217, 83%, 52%, 0.5)

/* ④ 现代写法：rgb 里直接给第四个值 */
rgb(31 111 235 / 50%)
Alpha 在十六进制里也是 0~255

最后两位虽是十六进制，但含义同 RGB 通道： 00 = 全透明，FF = 不透明，80 ≈ 一半。

所以 #1F6FEB80 里的 80 不是「80%」—— 它约等于 50%。别想当然。

半透明最有用的场景

常见的三种用法复制
/* ① 浅色背景：一个颜色兼顾白底和深色底 */
.card { background: rgba(31, 111, 235, 0.08); }

/* ② 遮罩：盖住页面又不完全挡住 */
.mask { background: rgba(18, 26, 40, 0.42); }

/* ③ 阴影：黑色加透明度，而不是用灰色 */
box-shadow: 0 2px 8px rgba(20, 30, 50, 0.14);

本文档的提示框、目录抽屉的遮罩、卡片的阴影， 全都用 rgba 而不是实色 —— 这样叠在任何背景上都自然。

6安全色与取色

什么是「安全色」

「Web 安全色」是早期（256 色显示器时代）的一套约定： 每个通道只取 00 / 33 / 66 / 99 / CC / FF 六个值， 共 6×6×6 = 216 种，保证在任何设备上都不抖动。

安全色的样子复制
#FF0000   /* ✅ 安全（每通道是 00 或 FF） */
#336699   /* ✅ 安全（33/66/99 都在那六个数里） */
#1F6FEB   /* ❌ 不安全（1F/6F/EB 是中间值） */
现在还需要守安全色吗

不需要了。今天的显示器都是 1600 万色以上， 安全色的限制早就没了意义。

但知道有这回事有好处：看到老代码里的 #336699、#CCCCCC 这种「很整齐」的颜色， 就知道它来自那个年代。

怎么取到一个颜色

办法说明
浏览器 F12 最实用。Elements 面板里点颜色方块 → 吸管图标 → 页面任意位置取色 → 直接给出十六进制
截图工具 / 取色器 Windows 的「截图工具」、各类取色软件都能读数
设计稿 Figma / PS 里点一下就能复制颜色值
对比度：比「好看」更重要的事

文字和背景的明暗差不够，读者会看不清 —— 这是无障碍（accessibility）的硬指标。

对比度评价
≥ 4.5 : 1合格 正文的最低要求
≥ 7 : 1优秀 AAA 级
< 3 : 1不合格 大标题也勉强

本系列文档的代码区对比度做到了 18:1 以上 —— 这不是「好看」，是「看得清」。

几个建议试的动作：

  • 把 R 拉到 255、G 和 B 都拉到 0 → 看十六进制变成 #FF0000
  • 把 透明度 A 慢慢拉小 → 看 #RRGGBB 后面多出两位、色块变透明
  • 把 R、G、B 调成同一个数 → 得到灰色，同时 HSL 里的 S 变成 0%
  • 随便选一个颜色，然后只改 L（亮度） → 色相不变，只变深浅 —— 这就是 HSL 比 RGB 好用的地方

拾取器在本页最下方（速查表之后）。

从拾取器里能看出来的三件事
  1. 十六进制和 rgb() 是同一个东西的两种写法 —— 拖滑块时两组数字同步变化。
  2. Alpha 加进去就是第四个数； 写成十六进制时占最后两位，80 ≈ 50%。
  3. HSL 的三个数各管一件事（色相 / 饱和 / 亮度）， 而 RGB 的三个数各管一盏灯 —— 前者更适合「调」，后者更适合「抄」。

这一篇要记住的六句话
  1. 颜色 = 三个灯的亮度：红、绿、蓝，各 0~255。
  2. 十六进制两位一组：#RRGGBB， FF=255、00=0；只有 16 个符号，所以有 A~F。
  3. 每通道两位相同可缩写：#FF0000 → #F00。
  4. HSV / HSL 更直观：H 是颜色（0~360 度），S 是鲜艳度，L/V 是明暗 —— 做同色系深浅时用它。
  5. Alpha 是第四个值：rgba(…, 0.5)； 写在十六进制里是最后两位，80 ≈ 50% 不是 80%。
  6. 安全色已经过时，但对比度永远要管 —— 正文至少 4.5 : 1。
