类、结构体

UME 项目组内部教程 · 第六讲 · C / C++ 混合项目 · 游戏开发场景

已学：数组 / 函数 / 指针 已学：内存与内存安全 本讲：把数据和行为打包 C++ 项目

这一讲从游戏开发讲起

前面几讲我们存的都是「一堆数」：成绩、数组、内存块。 但游戏里要存的是一个个角色 —— 每个角色有名字、血量、魔法、攻击力， 还有「挨打」「加血」「攻击」这些行为。

这一讲就是把这类东西打包成一个整体。 语法在 C 和 C++ 里都叫 struct，C++ 还多了一个 class。

文中所有「运行结果」与「编译错误」均经过实际编译运行核对（GCC 13.1）。

1从「一堆平行数组」说起

假设要存 3 个玩家：名字、血量、魔法值。

用你已经会的知识，最直接的办法是开三个数组：

平行数组：能跑，但很别扭复制
char names[3][20] = {"Archer", "Mage", "Knight"};
int  hps[3]        = {100, 80, 150};
int  mps[3]        = {30, 120, 10};

/* 下标 1 就是同一个人的三个属性 */
printf("%s hp=%d mp=%d\n", names[1], hps[1], mps[1]);
运行结果
Mage hp=80 mp=120

能跑。但问题会随着属性变多而迅速恶化：

加属性很烦
想加「攻击力」，就得再加一个数组，并且所有相关代码都要改
容易错位
names[2] 配 hps[1] 编译器不会拦你，但逻辑已经错了
传参更烦
想把「一个玩家」传给函数，得传三个参数，再加属性就再加参数
问题的根源

「名字、血量、魔法」本来是同一个东西的三个部分， 却被拆成了三个互不相干的数组。

它们之间只有「下标相同」这一条口头约定， 编译器完全不知道它们有关系，自然也没法替你检查。

2用 struct 打包

struct 解决的就是这件事：把属于同一个东西的若干数据， 声明成一个新的类型。

定义一个玩家类型复制
struct Player {
    char name[20];
    int  hp;
    int  mp;
};                       /* ← 注意这个分号，忘了会报一堆奇怪的错 */

这四行的意思是：从今以后，Player 就是一个类型了， 和 int、double 一样可以用来声明变量。

对比写法含义
内置类型int score;一个整数
内置类型double h;一个小数
自定义类型Player p;一个玩家（里面含 name、hp、mp）

怎么用

用「点号」访问里面的成员，每个成员就像一个普通变量：

读写成员复制
#include <stdio.h>
#include <string.h>

struct Player {
    char name[20];
    int  hp;
    int  mp;
};

int main(void) {
    struct Player p;              /* 声明一个玩家 */

    strcpy(p.name, "Archer");   /* 字符串要用 strcpy */
    p.hp = 100;
    p.mp = 30;

    printf("%s hp=%d mp=%d\n", p.name, p.hp, p.mp);

    /* 成员可以像普通变量一样参与运算 */
    p.hp = p.hp - 30;
    printf("受伤后 hp=%d\n", p.hp);

    /* 看这个类型占多少字节 */
    printf("sizeof(Player) = %d\n", (int)sizeof(struct Player));
    return 0;
}
运行结果
Archer hp=100 mp=30
受伤后 hp=70
sizeof(Player) = 28

28 字节 = 20（char name[20]）+ 4（int hp）+ 4（int mp）。 结构体的大小大致就是所有成员之和（有时因为「对齐」会稍大一点，入门阶段不必深究）。

C 语言里要写 struct Player p;

上面那样写是 C 的规范写法。每次都写 struct 有点啰嗦， 所以常用 typedef 起个别名：

typedef struct {
    char name[20];
    int  hp;
    int  mp;
} Player;                 /* 以后直接写 Player p; */

在 C++ 里不用这么麻烦 —— 直接写 Player p; 就行， struct 这个名字本身就当类型名用。本讲后面都用 C++ 的写法。

3一队玩家

结构体可以放进数组，于是「一队玩家」就是一个数组， 而不是三个平行的数组。这一步让代码立刻清爽起来。

结构体数组复制
#include <stdio.h>
#include <string.h>

struct Player {
    char name[20];       /* C 里用字符数组存名字，第八讲细讲 */
    int  hp;
    int  mp;
};

int main(void) {
    struct Player team[3];   /* 一个数组，装 3 个玩家 */

    strcpy(team[0].name, "Archer");  team[0].hp = 100;  team[0].mp = 30;
    strcpy(team[1].name, "Mage");    team[1].hp = 80;   team[1].mp = 120;
    strcpy(team[2].name, "Knight");  team[2].hp = 150;  team[2].mp = 10;

    for (int i = 0; i < 3; i++) {
        printf("%s hp=%d mp=%d\n",
               team[i].name, team[i].hp, team[i].mp);
    }
    return 0;
}
运行结果
Archer hp=100 mp=30
Mage hp=80 mp=120
Knight hp=150 mp=10
对比一下差别
想做的事平行数组结构体数组
取第 1 个玩家的血量hps[1]team[1].hp
看出「这是一整个玩家」看不出来很明显
加一个属性「攻击力」再加一个数组 + 到处改加一行成员即可
把「一个玩家」传给函数传 3 个参数传 1 个

4给 struct 加上函数

从这里开始会出现 C++ —— 带紫色「C++」徽标的才是

本文档大部分是 C。「把函数放进结构体里」这件事 C 语言做不到，它是 C++ 的特性，所以接下来有几段代码是 C++。

怎么区分：代码块标题栏上带紫色「C++」徽标的，就是 C++； 没有徽标的一律是 C。

本文档语言
第 2~3 节C —— struct 定义、用 . 读写成员
第 4 节「成员函数」起C++ C++ —— 把函数放进结构体
第 5 节「私有与共享成员」C++ C++ —— class / private
第 7 节「对象的生与死」C —— 用 xxx_init / xxx_destroy 约定代替构造函数
第 8 节常见错误两种都有，看徽标

编译方式也不同：带徽标的用 g++（或 Visual Studio 的 .cpp），没徽标的用 gcc（或 .c）。

数据打包好了，但「挨打」「加血」这些操作还散在外面。 如果能把它们也放进结构体里，用起来就顺多了 —— 这是 C++ 的加强。

成员函数C++复制
#include <iostream>
#include <string>
using namespace std;

struct Player {
    string name;
    int hp;
    int mp;

    /* 写在结构体里面的函数，叫「成员函数」 */
    void show() {
        cout << name << " hp=" << hp << " mp=" << mp << endl;
    }
    bool isAlive() { return hp > 0; }

    void takeDamage(int dmg) {
        hp -= dmg;
        if (hp < 0) hp = 0;   /* 血量不会变成负数 */
    }
};

int main() {
    Player p;
    p.name = "Archer";
    p.hp = 100;
    p.mp = 30;

    p.show();          /* 用「对象.函数名()」调用 */
    p.takeDamage(30);
    p.show();

    cout << "还活着吗？ " << (p.isAlive() ? "是" : "否") << endl;
    return 0;
}
运行结果
Archer hp=100 mp=30
Archer hp=70 mp=30
还活着吗？ 是

两个要点：

  • 成员函数里可以直接写 hp，不用写 p.hp。 因为它「知道」自己是哪个对象在调用 —— 编译器替你传递了这个信息。
  • 好处是「数据和操作放在一起」。 「挨打」这件事该改哪些数据，就在定义 Player 的地方一眼看全， 不用在几千行代码里到处找。
术语对照（先有个印象）
结构体 / 类Player —— 类型的定义，描述「一个玩家有什么」
对象 / 实例p、team[0] —— 按这个类型造出来的具体东西
成员变量name、hp、mp —— 对象里的数据
成员函数show()、takeDamage() —— 对象能做的操作

5私有与共有成员

上面那个 Player 有个隐患：外面可以随便改 hp。

危险：外面为所欲为复制
Player p;
p.hp = 100;
p.hp = 999999;      /* 血量改到天文数字，没人管 */
p.hp = -500;        /* 血量变负数，后面判断全乱 */

我们在 takeDamage 里写了「不让血量变成负数」的保护， 可这个保护可以被绕过去 —— 只要有人直接写 p.hp = -500。

5.1 为什么要藏起来

核心思想：把「能改的东西」控制起来

如果一个数据必须满足某种规则（血量不能为负、魔法不能超上限）， 那么就应该只允许通过函数去改它，在函数里保证规则成立。

这样「规则」只需要在一处维护，外部代码不可能绕过。

用生活里的例子理解：

自动售货机
你按按钮，它给你饮料。 你打不开它的内部去直接拿（数据被保护）
汽车
你踩油门，发动机按规则响应。 你不会去直接拧发动机的喷油嘴

5.2 private / public 怎么写

用 class 定义，并把数据放在 private: 下面， 把想对外提供的函数放在 public: 下面：

class + private / publicC++复制
#include <iostream>
#include <string>
using namespace std;

class Player {
private:                       /* 私有：只有自己人能用 */
    int hp;
    int maxHp;

public:                        /* 公开：外面可以调用 */
    string name;

    Player(string n, int m) {   /* 构造函数：造对象时自动执行 */
        name = n;
        maxHp = m;
        hp = m;
    }

    void takeDamage(int dmg) {
        hp -= dmg;
        if (hp < 0) hp = 0;
    }
    void heal(int v) {
        hp += v;
        if (hp > maxHp) hp = maxHp;
    }

    int  getHp() { return hp; }     /* 只读：只给看不给改 */
    bool isAlive() { return hp > 0; }
    void show() {
        cout << name << " HP " << hp << "/" << maxHp << endl;
    }
};

int main() {
    Player p("Archer", 100);     /* 构造函数自动被调用 */
    p.show();

    p.takeDamage(40);
    p.show();

    cout << "通过公开函数读 HP: " << p.getHp() << endl;

    /* 一路打到死 */
    p.takeDamage(1000);
    p.show();
    cout << "还活着吗？ " << (p.isAlive() ? "是" : "否") << endl;

    /* 治疗也不会超过上限 */
    p.heal(9999);
    p.show();
    return 0;
}
运行结果
Archer HP 100/100
Archer HP 60/100
通过公开函数读 HP: 60
Archer HP 0/100
还活着吗？ 否
Archer HP 100/100

注意最后两行：无论外面怎么折腾，血量都守规矩 —— 打不死成负数，也治不过上限。因为所有修改都必须经过 takeDamage / heal，而规则就写在里面。

构造函数：造对象时自动跑一次

Player(string n, int m) 这个函数名字和类名一样、没有返回值类型， 它就是构造函数。写 Player p("Archer", 100); 时自动被调用， 用来把对象初始化好。

为什么要构造函数

没有它的话，新造出来的对象里 hp 是不确定的值， 你可能会忘了初始化就用。构造函数保证对象一造出来就是合法状态。

5.3 亲眼看看编译错误

如果你从外面直接改私有成员，编译器根本不会让它编过。 实际编译一下（GCC 13.1）：

故意写错：从外面改私有成员C++复制
class Player {
private:
    int hp;
public:
    Player() { hp = 100; }
    int getHp() { return hp; }
};

int main() {
    Player p;
    p.hp = 999;          /* ← 这一行会编译失败 */
    return 0;
}
编译器的真实报错（已核对）
error: 'int Player::hp' is private within this context
   12 |     p.hp = 999;
      |       ^~
note: declared private here
    4 |     int hp;
      |         ^~
note: field 'int Player::hp' can be accessed via 'int Player::getHp()'
   12 |     p.hp = 999;
      |       ^~
      |       getHp()

编译器说得很清楚：hp 在这个上下文里是私有的， 而且还贴心地提示你「可以通过 getHp() 访问」。

这就是「私有」最大的价值

它把一类错误从「运行时的诡异 bug」变成了「编译时的明确报错」。

对比一下：如果 hp 是公开的，你写了 p.hp = -500， 程序照样编过、照样跑，直到某天血量算出乱七八糟的伤害才被发现问题所在 —— 那时你可能已经排查很久了。

能不写 bug，就别写 bug。让编译器帮你拦，是最省事的做法。

三种权限

关键字谁能访问典型用途
private只有自己 类内部的函数能用 数据（血量、上限），需要保护的成员
public谁都能用 对外提供的函数、构造函数
protected自己和子类 给继承用的，本讲暂不展开

6struct 与 class 的唯一区别

你可能会问：前面用 struct，这里用 class，到底差在哪？

答案是：只有一个区别 —— 默认权限
不写权限时，成员默认是
structpublic（公开）
classprivate（私有）

除此之外两者完全一样 —— 都可以有成员函数、构造函数、继承。sizeof 也一样大。

验证默认权限不同C++复制
#include <iostream>
using namespace std;

struct SA { int x; };      /* 默认 public */
class  SB { int x; };      /* 默认 private */

int main() {
    SA a;
    a.x = 10;                /* ✅ 可以，struct 默认公开 */
    cout << "struct SA 可以直接 a.x = " << a.x << endl;

    /* SB b; b.x = 10; */
    /* ↑ 取消注释就编译失败：class 默认私有 */

    cout << "sizeof(SA)=" << sizeof(SA)
         << "  sizeof(SB)=" << sizeof(SB) << endl;
    return 0;
}
运行结果
struct SA 可以直接 a.x = 10
sizeof(SA)=4  sizeof(SB)=4
实际项目里的选择习惯
  • 纯数据、没有规则要保护（比如一个坐标 Point{x, y}） → 用 struct，简单直接。
  • 有内部状态和不变量要维护（比如玩家血量、银行账户） → 用 class，把数据放 private。

这个习惯不是强制的，但它能让人一眼看出你的意图： 看到 struct 就知道「这只是个数据包」。

7对象的生与死

最后一节快速过一下对象的「生命周期」，这是把类用对的关键。

构造
对象被创建时
自动跑构造函数
使用
通过公开的函数
读写、调用成员函数
析构
对象消失时
自动跑析构函数
C 里的「构造」与「析构」：init / destroy 约定复制
#include <stdio.h>
#include <string.h>

struct Player {
    char name[20];
    int  hp;
};

/* C 里没有构造函数，用「初始化函数」代替 —— 约定：名字叫 xxx_init */
void player_init(struct Player *p, const char *n, int h) {
    strcpy(p->name, n);
    p->hp = h;
    printf("[构造] %s 诞生\n", p->name);
}

/* 需要收尾时，同样自己写一个函数显式调用 */
void player_destroy(struct Player *p) {
    printf("[析构] %s 退场\n", p->name);
}

void player_show(struct Player *p) {
    printf("%s HP %d\n", p->name, p->hp);
}

int main(void) {
    printf("--- 进入 main ---\n");

    struct Player p;
    player_init(&p, "Archer", 100);   /* 手动「构造」 */
    player_show(&p);

    printf("--- 即将离开 main ---\n");
    player_destroy(&p);            /* 手动「析构」—— 别忘了 */
    return 0;
}
运行结果
--- 进入 main ---
[构造] Archer 诞生
Archer HP 100
--- 即将离开 main ---
[析构] Archer 退场

注意 [析构] 是在 --- 即将离开 main --- 之后打印的：对象在离开作用域（main 结束）时自动销毁。

「析构」最重要的用途：归还资源

如果类里用 malloc / new 申请了资源， 就该在析构函数里释放。这样对象一消失，资源自动归还 —— 不用你记着写 free。

/* 把「申请」和「释放」包成一对函数，成对调用 */
struct Buffer {
    int  *data;
    int   n;
};

void buffer_init(struct Buffer *b, int n) {
    b->n = n;
    b->data = malloc(sizeof(int) * n);   /* 申请 */
}
void buffer_destroy(struct Buffer *b) {
    free(b->data);                     /* 归还 */
    b->data = NULL;
}

这就是第五讲「谁申请谁释放」在结构体上的落地方式： 申请写在 xxx_init，释放写在 xxx_destroy。

代价是：你必须记得调用 xxx_destroy。 C++ 的构造函数 / 析构函数之所以受欢迎，正是因为它们 自动在对象创建和销毁时被调用，不会忘 —— 这部分属于 C++，本讲不展开。

8常见错误

错误 1 · 定义结构体后忘了分号

对比复制
struct Player {
    int hp;
}                        /* ❌ 少分号：后面会报一串莫名其妙的错 */

struct Player {
    int hp;
};                       /* ✅ */

错误 2 · 忘了「数据放 private」

对比C++复制
/* ❌ 数据全公开，保护形同虚设 */
class Player {
public:
    int hp;              /* 外面能写 p.hp = -500 */
};

/* ✅ 数据私有，只通过公开函数改 */
class Player {
private:
    int hp;
public:
    void takeDamage(int d);   /* 规则写在里面 */
    int  getHp();

错误 3 · 用 . 去访问指针指向的对象

对比复制
struct Player p;
struct Player *ptr = &p;

ptr.hp = 10;       /* ❌ 指针要用 -> */
ptr->hp = 10;      /* ✅ */
(*ptr).hp = 10;   /* ✅ 也合法，但没人这么写 */

记法：对象用 .，指针用 ->。 （第四讲讲过，ptr->show() 就等价于 (*ptr).show()）

错误 4 · 忘了构造函数导致成员没初始化

对比复制
struct Player {
    int hp;
};
struct Player p;              /* ❌ 没初始化，hp 是不确定的值 */
printf("%d\n", p.hp);       /* 输出什么都有可能 */

/* ✅ 用初始化函数保证一造出来就合法 */
void player_init(struct Player *q) {
    q->hp = 100;
}
player_init(&p);

  2. 成员函数写在类里面，数据和操作放在一起。
  3. private 保护数据，只留 public 的函数当出口 —— 规矩写在一处，外面绕不过去。
  4. struct 与 class 只差默认权限： struct 默认 public，class 默认 private。
  5. 构造函数保证对象一造出来就合法，析构函数负责收尾（该释放的资源在那里放）。
下一讲预告

这一讲里，变量都写在很「显眼」的位置：成员变量在类里，局部变量在函数里。 但程序一大，就会冒出一堆问题：

  • 写 int hp = 100; 的时候，这个 hp 到底属于谁？ 为什么另一个函数里的同名变量完全不相干？
  • 为什么 for (int i = 0; ...) 里的 i 出了循环就用不了？
  • 全局变量到处都能改，什么时候该用、什么时候是灾难？

下一讲《作用域、全局与局部变量》就把这些问题讲清楚： 一个名字在哪些地方能被看见、活多久、被谁遮住。
