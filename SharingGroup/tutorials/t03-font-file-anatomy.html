字体文件结构大揭秘

UME 项目组内部教程 · T03（Theory） · · 深入到字体文件内部

只讨论 MNG 所有数字来自实际解析字体文件 动手：改一个字节看会怎样

这一篇讲什么

一个字体的 .ttf 文件里到底装了什么？为什么 171 个蒙文码位能撑起 3715 个字形？

这一篇把 NotoSansMongolian-Regular.ttf（388,168 字节） 拆开给你看。范围严格限定在这一款字体的这一种文字 —— 不涉及其他形式的回鹘文，也不涉及其他字体。

文中每个数字都可以自己复现，命令在最后一节。

它承接 T02：T02 讲到「码位」为止，T03 接着讲这些码位在字体文件里怎么变成字形。建议先看 T01 → T02。

1先看全局：一个文件装了 18 张表

打开字体文件的头 12 个字节，就能知道它有多大、有多少张表：

文件头（offset table）复制
偏移 0   sfnt 版本 + 表数量 + 查找参数
        00 01 00 00   ← 版本 1.0（TrueType）
        00 12         ← 18 张表
        00 40 00 03   ← 查找范围
...

紧接着是 18 条目录项，每条 16 字节：标签、校验和、偏移、长度。 所以「表」就是文件里一段一段的字节，靠这张目录找。

表大小装什么
glyf215,258 B字形轮廓（占了整份文件的 55%）
post63,511 BPostScript 信息 —— 主要是字形名字
GSUB59,284 B字形替换：连字、位置变体（本篇主角）
loca14,864 B字形在 glyf 里的索引表
hmtx14,860 B每个字形的推进量（advance）
GPOS10,782 B位置微调：kern / mark / mkmk
cmap3,702 B码位 → 字形的映射表
fpgm / prep / cvt3,848 BTrueType 指令（微调像素）
name1,344 B字体名、版权、许可证
GDEF190 B字形分类（基础字 / 连字 / 标记）
head / hhea / maxp / OS/2218 B头部标量：单位、上下沿、字重…
gasp8 B栅格化提示
第一眼就该注意到的比例

glyf 占 55% —— 轮廓是绝对大头。GSUB 占 15% 排第二， 而且比 GPOS 大 5.5 倍。

这个比例本身就说明问题：蒙文排版的难点不在「摆位置」，而在「换字形」。 GPOS 只做点标记微调，GSUB 才是主战场。

2head 与 hhea：字体自己的坐标系

实测值复制
head.unitsPerEm      = 1000    ← 字号 100px 时，1 单位 = 0.1px
head.magicNumber     = 0x5F0F3CF5
head.indexToLocFormat= 0（短格式 loca）

hhea.ascender        = 1457

hhea.lineGap         = 0

OS/2.sTypoAscender   = 1457

OS/2.usWeightClass   = 400（Regular）
OS/2.sxHeight = 500   sCapHeight = 700
maxp.numGlyphs       = 3715
为什么蒙文字体的 ascender 这么大

拉丁字体的 ascender 通常约等于 0.8 × unitsPerEm。 这个字体是 1457 / 1000 = 1.457 倍，明显超出正方框。

原因：蒙文是竖排的。字形要在竖直方向上依次「挂」下来， 所以纵向（在字体坐标系里是 y 轴）需要留出比拉丁字母高得多的空间。

这也解释了我们排版时列宽的来历：一列的宽度 ≈ ascender − descender = 1457 + 293 = 1750 单位 —— 一行的高度里，字形只占其中一部分。

3cmap：码位 → 字形，只有 517 条

cmap 是「你输入 U+1820，该画哪个字形」的查询表。 实测这份字体：

实测复制
cmap 总映射数        = 517
其中蒙文区           = 171   （U+1800 .. U+1166C）
拉丁 / 西里尔 / 希腊 = 其余 346   （数字、标点等）

maxp.numGlyphs       = 3715

517 / 3715 = 13.9%   ← 只有不到七分之一的字形能被直接输入
这就是全篇的核心问题

能直接输入 517 个字形，字体里却有 3715 个。 剩下 3198 个（86%）从哪来？

答案：由 GSUB 表在排版时现场「换」出来。 你永远输入不到它们，它们只在特定上下文中出现。

注意两件事
  1. U+180F 的字形名不是 uni180F 而是 fvs4 —— 因为 FVS4 是后来才补进 Unicode 的，字形名沿用了旧习惯。 看得出这个文件经历过多次修订。
  2. FVS / MVS 的 advance 都是 770，和普通字母差不多。 它们在语义上是「修饰符」，但在字体里占了一整格宽度 —— 这正是我们排版时要按字素簇处理、不能让它们独立成格的原因。

cmap 为什么只有 3,702 字节

517 条映射平均每条 7 字节 —— 因为用的是 format 4 （按区间压缩的查表格式）。如果每个码位都单独存一条， 光映射就要几万字节。

4GSUB 才是主角

GSUB = Glyph SUBstitution，字形替换。 它按「脚本 + 语言 + 特性」组织：

GSUB 脚本与特性（实测）复制
script mong  →  aalt, ccmp, fina, init, isol, medi, ordn, rclt, vert
script DFLT  →  同上
script latn  →  aalt, ccmp, ordn          ← 拉丁字母只做基础处理
script cyrl  →  aalt, ccmp, ordn
script grek  →  aalt, ccmp, ordn
特性作用
isol孤立形：字母两边都不连
init词首形：右边连接后面的字母
medi词中形：两边都连
fina词尾形：左边承接前面的字母
ccmp字形组合 / 分解（预处理的替换）
rclt必需连字：不做会读错，必须执行
vert竖排替换（25 个字形带这个后缀）
aalt全部替代字形（给用户挑选用）
为什么必须是 rclt 而不是普通连字

OpenType 里连字特性分两种：liga（可选，关了也能读） 和 rclt（必需，关了就读错）。

蒙文的音节连写属于后者 —— 同一串字母， 连与不连是不同的词。所以它写在 rclt 里。

这也解释了我们代码里那条禁令：绝对不能写 font-feature-settings 去手动打开 init/medi/fina/isol。 那会覆盖掉引擎本来会做的上下文判断，把连写拆散。

查表（lookup）的实际构成

实测：GSUB 里 202 个 lookup复制
type 1  Single            113 个   ← 一对一换字形（位置变体主力）
type 2  Multiple          10 个   ← 一变多（分解）
type 4  Ligature          13 个   ← 多对一（连字）
type 5  Context           11 个   ← 按上下文
type 6  ChainingContext   54 个   ← 按前后文链式判断
type 8  ReverseChaining    1 个

连字（Ligature）规则总数 = 1944 条
113 个 Single 说明什么

把 759 个「单码位位置变体」分摊到 113 个 lookup 里， 平均每个 lookup 管 7 个字形 —— 也就是按字母分组： 每个字母一组，内部再分 isol/init/medi/fina。

而 ChainingContext 有 54 个，是全表第二多。 它负责「看前一个字母是什么，再决定当前字母取哪个形」—— 上下文相关的连写，全靠这一类。

5最有意思的部分：字形名字里有音节

看 post 表里的字形名。它们不是随意编号，而是有语法的：

命名结构复制
u182A_u1820.BA.init
└──┬───┘ └┬┘ └┬─┘
   │      │   └── 位置：init（词首）
   │      └── 音节型：BA（用拉丁转写拼出来的音节）
   └── 参与组合的码位：U+182A + U+1820

也就是说：字形名 = 码位串 + 拉丁音节 + 位置。 那个拉丁音节是设计者手写的读音标注 —— BA、BO、GO、AGM、GxO…

音节型一共 448 种

出现次数最多的音节型（实测）复制
GO    66      GA    22      GI    20      GL    12
GxO   40      A     20      GxOI  20      GUe   12
I     26      AGM   20      AGL   19      GW    12
BO    26      G     20      O     16      GM    12
KO    26      GAa   20      BI    16
GOI   24                             ...共 448 种
K2O   24

读几个就明白规则了：G=GA、O=O、I=I、 A=A、M=MA、L=LA、B=BA、 K=KA。于是：

音节型拆开意思
GOGA + O音节「go」
GOIGA + O + I「goi」
AGMA + GA + MA「agma」—— 闭音节
GxOGA + x + O带 x 标记的特殊 GA 形
K2OKA + 2 + O2 是另一个变体标记
所以「连字」在这里的真正含义

蒙文不是一个字母一个字形。它是以「音节」为单位的。

字形名的结构清楚地告诉我们：设计者写这个字体时， 脑子里想的不是「182A 这个字母有几种写法」， 而是「ba、bo、bi、bue… 这些音节各自该怎么连」。

448 种音节型 × 4 个位置 × 变体 = 3715 个字形。 这就是为什么 cmap 只有 517 条。

参与组合的码位个数

实测（有后缀的字形共 3196 个）复制
单码位变体        759   ← 一个字母，四种位置形 + 变体
双码位连字       2165   ← 两个字母的连写（绝对主力，占 68%）
三码位及以上       272   ← 少见但存在

最长的连字名例子：
  u1807_u1863_u182E.AGM.medi     ← SIBE 符 + 一个字母 + MA，词中形
  u182A_u1826_u1822.BOI.init     ← BA + UE + I，词首形
这对排版意味着什么

2165 个双码位连字意味着：任意两个相邻字母， 都可能合成一个全新字形 —— 它的宽度和两个字母单独排不一样。

所以我们量一行的长度时不能把字母宽度相加。 必须让引擎真的把整行排出来，再逐个字素簇量实际高度 （UMCompos 就是这么做的：1000px 量尺 + 相邻相减）。

6hmtx 与 loca：两个不起眼但关键的表

loca —— 字形索引进 glyf 的地址簿

结构复制
loca 是 (numGlyphs + 1) 个偏移量：
  loca[0] = 0
  loca[1] = 字形 0 的长度
  ...
  loca[3714+1] = glyf 表总长

字形 i 的字节区间 = [ loca[i], loca[i+1] )

head.indexToLocFormat = 0  → 短格式，每项 2 字节、单位是「2 字节」
所以 loca 大小 = (3715 + 1) × 2 = 7,432 B
但实测是 14,864 B —— 正好两倍，说明实际用了长格式（每项 4 字节）。
loca = 14864 = 3716 × 4  ✔ 对上了
为什么要有 loca 这一层

因为 glyf 里每个字形的长度都不一样（轮廓点数不同）。 想随机访问第 2000 个字形，就得先查地址簿。

这也解释了「字形越多，文件越大」的具体方式： 3715 × 4 字节的 loca 就是 14.8 KB 的固定开销。

hmtx —— 每个字形的推进量

我们排版时依赖的 advance 就来自这里。实测几个：

码位字母advance相对最窄
U+180ANIRUGU1681.0×（最窄）
U+1828NA4922.9×
U+182ABA5573.3×
U+1820A9195.5×
U+1826UE14268.5×

但请注意 hhea.advanceWidthMax = 1596， 而字形里最宽的记录是 1426 —— 差值说明真正最宽的字形是连字， 不是这些单字母。

8自己复现这些数字

上面每个数字都能用 fontTools 复现。先装：

安装复制
pip install fonttools

① 看表清单与大小

dump_tables.py复制
from fontTools.ttLib import TTFont
import os

P = "font/NotoSansMongolian-Regular.ttf"
print("文件大小", os.path.getsize(P), "B")

f = TTFont(P)
rows = sorted(((e.length, tag) for tag, e in f.reader.tables.items()),
              reverse=True)
for size, tag in rows:
    print("%-6s %8d B" % (tag, size))

② 看码位、字形名、advance

dump_cmap.py复制
from fontTools.ttLib import TTFont
import unicodedata

f = TTFont("font/NotoSansMongolian-Regular.ttf")
cmap, hmtx = f.getBestCmap(), f["hmtx"]

mong = sorted(c for c in cmap
              if 0x1800 <= c <= 0x18AF or 0x11660 <= c <= 0x1167F)
print("cmap 总数", len(cmap), " 蒙文区", len(mong))

for c in mong[:20]:
    g = cmap[c]
    print("U+%04X  %-22s %-44s aw=%d"
          % (c, g, unicodedata.name(chr(c)), hmtx[g][0]))

③ 看 GSUB 的特性与 lookup 构成

dump_gsub.py复制
from fontTools.ttLib import TTFont
import collections

f = TTFont("font/NotoSansMongolian-Regular.ttf")
g = f["GSUB"].table

# 每个 script 支持哪些特性
for sr in g.ScriptList.ScriptRecord:
    if not sr.Script.DefaultLangSys:
        continue
    tags = [g.FeatureList.FeatureRecord[i].FeatureTag
            for i in sr.Script.DefaultLangSys.FeatureIndex]
    print(sr.ScriptTag, "→", ", ".join(sorted(tags)))

# lookup 类型统计
c = collections.Counter(l.LookupType for l in g.LookupList.Lookup)
for t, n in sorted(c.items()):
    print("type", t, n)

# 连字规则总数
lig = sum(len(ls) for l in g.LookupList.Lookup if l.LookupType == 4
          for st in l.SubTable for ls in getattr(st, "ligatures", {}).values())
print("连字规则总数", lig)

④ 看字形名里的音节型

dump_syllables.py复制
from fontTools.ttLib import TTFont
import collections

f = TTFont("font/NotoSansMongolian-Regular.ttf")
syl = collections.Counter()
for gname in f.getGlyphOrder():
    if "." in gname:
        parts = gname.split(".")
        if len(parts) >= 2:
            syl[parts[1]] += 1     # 第 2 段就是音节型

print("音节型共", len(syl), "种")
for k, v in syl.most_common(20):
    print("  %-8s %4d" % (k, v))

9回到项目：这些结构决定了我们的排版代码

字体里的事实我们代码里对应的做法
3715 字形 vs 517 码位 排版必须按字素簇，不能按码位切
FVS/MVS 的 advance = 770 它们语义上是修饰符却占一格， 必须黏附到前一字素（UAX #29 GB9）
2165 个双码位连字 行长度不能靠加字母宽度算， 必须真实排版后逐簇测量
rclt 是「必需连字」 代码里禁止写 font-feature-settings 手动开关 init/medi/fina/isol
ascender 1457 / descender -293 竖排列宽按 1.42 × 字号 估， 来自这个 1750 单位的纵向空间
GSUB 59 KB > GPOS 10 KB 难点在「换字形」不在「摆位置」， 所以调字距收益远小于把连写交给引擎
这一篇要记住的五句话
  1. 字体是一堆表的集合，靠开头 12 字节 + 18 条目录索引。 glyf 管轮廓、cmap 管码位、GSUB 管换字形。
  2. cmap 只覆盖 13.9% 的字形 —— 剩下 86% 由 GSUB 在排版时现场换出来， 所以你输入不到它们。
  3. GSUB 里 rclt 是必需连字。蒙文的连写会改变词义， 所以不能用普通可选连字的方式去干预。
  4. 字形名里有音节（448 种） —— 设计者以音节为单位组织字形，双码位连字有 2165 个。 这解释了为什么行长度必须实测。
  5. ascender 是 unitsPerEm 的 1.46 倍 —— 竖排文字在纵向要留出远超拉丁的空间。
