批处理与命令提示符进阶

UME 项目组内部教程 · E02（Extra） · 让命令行替你干活

本讲：把命令写成文件

这一篇解决什么

08-F01 讲的是「一条一条敲命令」。可是要重复做同一串操作时， 一条条敲就太笨了 —— 而且容易漏、容易敲错。

这一篇讲怎么把命令写进一个文件，一键重跑， 也就是批处理（batch）。顺带讲怎么在批处理里调用 项目会用到的三样工具：node、npm、python。

文中所有命令与脚本输出，均在本机（Windows 11 · cmd）实际运行核对。

1这一篇讲什么

内容解决什么问题难度
批处理初步把一串命令写进 .bat，一键运行入门
批处理语法变量、参数、判断、循环中等
两个必踩的坑 变量在括号里不更新、怎么判断上一步成功关键
调用 node / npm / python 把这三样工具接进脚本入门
为什么项目里值得学

项目里总有这些事要做：清掉旧的编译产物、重新编译、跑一遍检查、启动程序。 每次都手敲一遍，迟早会漏某步。

写成 build.bat 之后，新来的同事双击一下就能跑， 不用看一长串配置说明 —— 这本身就是最好的一份文档。

2批处理（.bat）初步

批处理文件就是以 .bat 结尾的纯文本文件， 里面一行写一条 cmd 命令。双击或敲它的名字，cmd 就会从上到下一行行执行。

第一行通常写 @echo off —— 关掉「把命令自己也打印出来」
中间就是你在 cmd 里会敲的那些命令，一行一条
最后常用 pause 停一下，好让你看清输出

2.1 第一个 .bat

用记事本新建一个文件，写上三行，另存为 hello.bat：

hello.bat复制
@echo off
chcp 65001 >nul
echo 你好，这是第一个批处理文件
pause
双击运行的结果
你好，这是第一个批处理文件
请按任意键继续. . .

逐行看：

这一行作用
@echo off 别把命令本身也打印出来。 不加的话每行命令都会先显示一遍，输出全是噪音。@ 是让这一行自己也不显示
chcp 65001 >nul 把本窗口切到 UTF-8，中文才不会变问号（见 2.2）
echo 你好…打印一行字
pause 停住等按键。不加的话窗口一闪就关了，看不到输出
新手第一个坑：窗口一闪而过

双击 .bat，如果它很快跑完，窗口会立刻关闭 —— 你根本来不及看清输出，更别说看报错了。

两种应对：

  • 脚本最后加一行 pause（调试时最常用）
  • 或者不要双击，而是从命令行里敲它的名字运行 —— 这样输出会留在当前窗口里，还能往上翻

2.2 编码：中文为什么会变问号

这是一个必定会遇到的问题。先看现象：一个存了中文的 .bat， 运行后中文变成了一串问号 ??? 或者乱码。

成因

批处理文件里的中文是按字节存的，而 cmd 默认用 GBK（代码页 936）去读它。

如果文件存成 UTF-8，cmd 却按 GBK 解释， 字节就对不上了 —— 于是显示成 ???。

反过来，如果文件存成 GBK，在别的地方（比如某些编辑器、 Git、跨平台工具）又会乱码。

实测两种方案，结论很明确：

方案 A：文件存 UTF-8 + 脚本里切 chcp 65001 ✅
D:\Path\To>demo.bat
项目名: UME
中文可以正常显示
方案 B：文件存 GBK + 不写 chcp ❌（换环境就出问题）
D:\Path\To>demo.bat
��Ŀ��: UME
���Ŀ���������ʾ
结论：统一用「UTF-8 无 BOM + 脚本开头 chcp 65001」
每个 .bat 的开头两行复制
@echo off
chcp 65001 >nul

>nul 是「把 chcp 自己那行输出丢掉」，免得屏幕上多一句 Active code page: 65001。

另外注意：一定要存成「UTF-8 无 BOM」。带 BOM 的话， 文件开头会多出三个看不见的字节，第一行命令会直接解析失败。

2.3 双击 与 命令行 的区别

同一个 .bat，双击和从命令行运行有两处不同，都会咬人。

双击运行从命令行运行
工作目录 脚本所在目录 你敲命令时所在的目录
跑完之后 窗口关闭 看不到输出 留在窗口里 能翻、能复制

第一行那个差异，正是 08-F02 讲过的「相对路径相对于 CWD」问题。 无论怎么运行都得到同一个结果的标准做法，是在脚本开头把目录钉死：

钉死工作目录复制
@echo off
chcp 65001 >nul
rem %~dp0 是「本脚本所在目录」（见 3.3）
cd /d "%~dp0"

rem 从这里开始，所有相对路径都以脚本目录为基准
echo 当前目录: %CD%
建议：开发时一律从命令行运行

在脚本目录的地址栏输入 cmd 回车， 然后敲 脚本名.bat。输出留在窗口里，报错看得见，还能往上翻。

等到脚本稳定了，再考虑加 pause 给别人双击用。

3批处理语法

3.1 注释与输出

注释与几种输出复制
rem 这是注释（rem = remark）
:: 这也是注释，但只在行首有效

echo 普通一行
echo.                        rem 输出一个空行（注意那个点，不能省）
echo ====================
echo 正在编译...
写法说明
rem 注释最稳妥的注释，哪里都能用
:: 注释更短，但只能在行首；写在 for/if 括号里可能出错
echo.输出空行。那个点不能省 —— 光写 echo 会打印「echo 是开还是关」
echo off / on临时关掉 / 打开命令回显

输出重定向

把输出写进文件复制
echo first > out.txt        rem >  覆盖写入（原内容没了）
echo second >> out.txt      rem >> 追加到末尾
type out.txt               rem 打印文件内容

rem 把错误信息也一起收进文件（2>&1 = 把错误流并到正常流）
gcc main.c -o main.exe > build.log 2>&1
运行结果（out.txt 内容）
first
second
写法作用
>覆盖写入文件
>>追加到文件末尾
>nul丢掉输出（nul 是 Windows 的「黑洞设备」）
2>&1把错误输出也合并进来 —— 日志里两个都要才完整

3.2 变量与四种写法

这里有件事必须先说清：批处理的 % 写法有好几种， 含义完全不同，混起来是最大的困惑来源。

定义与使用变量复制
rem 定义：set 名字=值   （等号两边不要留空格！）
set NAME=UME
set BUILD_DIR=build

rem 使用：%名字%
echo 项目名: %NAME%
echo 输出到: %BUILD_DIR%\app.exe

rem 算术：set /a
set /a COUNT=3*4+1
echo COUNT=%COUNT%          rem 13

rem 删除变量
set NAME=
运行结果
项目名: UME
输出到: build\app.exe
COUNT=13
set NAME = UME 是错的

等号两边不能有空格。写了空格，你得到的是一个名字叫 NAME （带尾随空格）的变量，而 %NAME% 取不到。

这类错误不报错、只是「值怎么是空的」，特别难查。 记住：set 名字=值，紧挨着写。

四种 % 写法对照

写法含义例子
%NAME%你 set 的变量%BUILD_DIR%
%PATH%系统环境变量（08-F02 讲过）%TEMP%
%1 %2 %*命令行参数（见 3.3）build.bat release
%%ffor 循环变量（见 3.4）for %%f in (*.c) do …
为什么 for 里要写两个 %

在命令行直接敲时写一个：for %f in (*.c) do echo %f。

在 .bat 文件里要写两个：for %%f in (*.c) do echo %%f。

原因是批处理文件本身要用 % 表示参数（%1）， 所以循环变量得用 %% 来区分。写脚本时永远用两个。

3.3 参数与 %~dp0

批处理也能收命令行参数，写法和 C 的 argv 是一回事。

收参数复制
@echo off
chcp 65001 >nul

echo 收到 %# 个参数    rem 见下方说明
echo 第 1 个: %1
echo 第 2 个: %2
echo 全部   : %*
echo 脚本目录: %~dp0
写法含义实测值（参数为 build）
%1第 1 个参数build
%2第 2 个参数（没传就是空）
%*所有参数，原样一串build
%0脚本自身的路径D:\Path\To\demo.bat
%~dp0脚本所在目录（带结尾反斜杠）D:\Path\To\
参数个数怎么取

批处理没有 %# 这种直接写法。要数个数得绕一下：

数参数个数复制
set N=0
for %%a in (%*) do set /a N+=1
echo 参数个数: %N%

不过大多数脚本并不需要数个数，直接判断关键参数在不在就够了：

更实用的做法复制
if "%1"=="clean" echo 准备清理
if "%1"==""      echo 没给参数，按默认来

%~dp0 与 %CD% 的区别

为什么用 %~dp0 而不是 %CD%复制
rem 用户可能在任意目录下调用这个脚本：
rem   D:\> Path\To\project\build.bat

echo %CD%        rem D:\            ← 你敲命令的地方
echo %~dp0       rem D:\Path\To\project\   ← 脚本所在处

rem 所以脚本开头一定要这样钉住：
cd /d "%~dp0"

%~dp0 这几个字母拆开看更好记：

字母来自含义
%0第 0 个参数脚本自己
~—「把引号去掉并做修饰」
ddrive取盘符与路径部分（去掉文件名）
ppath取路径（不含文件名）

3.4 if 与 for

if：判断

几种 if 写法复制
rem ① 比较字符串（注意两边都要引号，防止空参数炸掉语法）
if "%1"=="build" (
    echo 开始编译
) else (
    echo 未知参数: %1
)

rem ② 文件/目录是否存在
if exist build\app.exe echo 程序已经编译过
if not exist src echo 找不到 src 目录

rem ③ 变量是否为空 / 是否已定义
if "%NAME%"=="" echo NAME 是空的
if defined NAME echo NAME 有值

rem ④ 上一步是否成功（见 4.2，最常用）
if %ERRORLEVEL% neq 0 echo 出错了
引号不能省：if %1==build 会炸

如果用户没传参数，%1 是空的，那一行就变成 if ==build —— 语法错误，脚本直接崩。

写成 if "%1"=="build" 之后，空参数时变成 if ""=="build"，语法合法、判断为假，安全通过。

规则：批处理里比较字符串，两边一律加引号。

for：循环

三种常用 for复制
rem ① 遍历一组值
for %%f in (a.c b.c c.c) do echo 文件: %%f

rem ② 遍历通配符匹配到的文件（编译所有 .c 最常用）
for %%f in (*.c) do (
    echo 正在编译 %%f
    gcc -std=c99 -c "%%f" -o "%%~nf.o"
)

rem ③ for /f ：逐行读文件或读命令输出
for /f "delims=" %%L in (list.txt) do echo 读到一行: %%L

rem 读某个命令的输出（这里列出所有 .c 文件）
for /f %%L in ('dir /b *.c') do echo %%L
运行结果（第一种）
文件: a.c
文件: b.c
文件: c.c

第二种里出现的 %%~nf 是「取文件名、去掉扩展名」：

写法对 src\main.c 得到
%%fsrc\main.c
%%~nfmain  去掉扩展名
%%~xf.c  只要扩展名
%%~dpfD:\Path\To\src\  所在目录

4两个必踩的坑

这两个坑几乎每个人都会踩一次，而且报错信息都很误导。提前知道能省很多时间。

4.1 变量在括号里不更新

先看现象。这个脚本想在循环里数数：

看起来没问题的写法复制
@echo off
chcp 65001 >nul

set N=0
for %%f in (a b c) do (
    set /a N+=1
    echo 第 %N% 个
)
echo 一共 %N% 个
运行结果 —— 全错了
第 0 个
第 0 个
第 0 个
一共 3 个

循环里明明加了 3 次，打印出来却一直是 0； 可循环外面那个 一共 3 个 又是对的。为什么？

原因：整个括号块被当成「一行」先读完了

cmd 读到一个 ( ... ) 块时，会先把整块读进来， 并在读的时候就把 %N% 全部替换成当前值， 然后再执行。

读的那一刻 N=0，所以三个 %N% 全被换成了 0， 后面怎么加都不影响已经替换好的文本。

而循环外那行是单独一条命令，执行到它时才替换，此时 N 已经是 3。

解法：用「延迟展开」。开头开一下，然后把 %N% 写成 !N!：

正确写法复制
@echo off
chcp 65001 >nul
setlocal enabledelayedexpansion      rem ① 打开延迟展开

set N=0
for %%f in (a b c) do (
    set /a N+=1
    echo 第 !N! 个                  rem ② 用 ! 而不是 %
)
echo 一共 !N! 个

endlocal                          rem 收尾，还原设置
运行结果
第 1 个
第 2 个
第 3 个
一共 3 个
口诀：括号里要「读一次看一次」的变量，就用 !变量!。
括号外用 %变量%、括号内用 !变量! —— 这是最省心的记法。
这个坑也影响 %ERRORLEVEL%

同一个道理：在括号里用 %ERRORLEVEL% 拿到的是 进括号之前的值，是「旧的」。

想知道括号里某条命令的结果，就得用 !ERRORLEVEL!。 不过更常用的做法是下面 4.2 的写法 —— 把判断放在括号外。

4.2 判断上一步是否成功

脚本的关键用途之一是「编译失败就别继续了」。 这就需要拿到上一条命令的退出码。

约定：0 = 成功，非 0 = 失败

这条约定和 C 的 main 返回值完全一致 —— return 0; 表示正常结束。

退出码存在 %ERRORLEVEL% 里，每条命令执行后都会更新。

写法一：&& 与 ||（最简）

短路写法复制
rem && ：前面成功才执行后面
gcc main.c -o main.exe && echo 编译成功

rem || ：前面失败才执行后面
gcc main.c -o main.exe || echo 编译失败

rem 三个连起来：成功就运行，失败就提示并中止
gcc main.c -o main.exe && main.exe || exit /b 1
运行结果
[OK] 成功时执行
[OK] 失败时执行

这两个符号和 C 里的 && / || 含义完全一样 （M01里讲过短路求值），所以很好记。

写法二：if %ERRORLEVEL% neq 0（最清楚）

显式判断并中止复制
gcc main.c -o main.exe

if %ERRORLEVEL% neq 0 (
    echo 编译失败，中止
    exit /b 1                rem /b = 只退出脚本，不关窗口
)
echo 编译通过，继续下一步
比较符含义
equ等于（equal）
neq不等于（not equal）
lss / leq小于 / 小于等于
gtr / geq大于 / 大于等于
if errorlevel 1 的意思不是「等于 1」

它是「大于等于 1」：

对比复制
if errorlevel 1  echo 成立  rem ERRORLEVEL 是 5 时也成立！
if %ERRORLEVEL% neq 0 echo 成立  rem 这个才是「非 0 即失败」

所以想判断「有没有失败」，用 if %ERRORLEVEL% neq 0， 语义最清楚，也不会误读。

exit /b 与 exit 的区别

写法效果
exit /b 1 退出当前脚本，返回码 1。窗口留着 —— 脚本里要用这个
exit 关掉整个 cmd 窗口。双击运行时看着像「闪退」，别在脚本里用

常用来做数据分析、批量处理

5.1 node

node 后面跟一个 .js 文件就能跑。先写一个最小的：

hello.js复制
console.log("Hello from Node.js");
console.log("Node 版本:", process.version);
console.log("当前目录:", process.cwd());
console.log("参数:", process.argv.slice(2));
运行
D:\Path\To>node hello.js alpha beta
Hello from Node.js
Node 版本: v24.16.0
当前目录: D:\Path\To
参数: [ 'alpha', 'beta' ]
写法作用
node 文件.js运行一个脚本文件
node 文件.js a b带参数运行，脚本里用 process.argv 取
node -e "代码"直接执行一行，不建文件。适合快速算个东西
node进入交互模式（REPL），敲一行执行一行，.exit 退出
-e 直接算一行
D:\>node -e "console.log(1+2)"
3
node 里取三样「环境信息」
对应的写法复制
process.argv.slice(2)      // 命令行参数（去掉 node 和文件名）
process.cwd()              // 当前工作目录（= cmd 里的 %CD%）
process.env.UME_ROOT       // 读环境变量（= cmd 里的 %UME_ROOT%）
process.exitCode = 1       // 设置退出码，供批处理判断

最后一行很重要：它和批处理的 %ERRORLEVEL% 是同一个东西。 node 脚本想告诉批处理「我失败了」，就设 process.exitCode = 1。

5.2 npm

npm 是 node 的包管理器，但它有个更有用的功能： 把常用命令写进 package.json，用 npm run 名字 调用。

先造一个项目

npm init -y 生成 package.json
D:\Path\To\demo>npm init -y
Wrote to D:\Path\To\demo\package.json:
{
  "name": "demo",
  "version": "1.0.0",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "license": "ISC"
}

-y 是「所有问题都用默认答案」。生成的 package.json 就是这个项目的「说明书」。

核心用法：scripts

package.json（节选）复制
{
  "name": "ume-demo",
  "version": "1.0.0",
  "scripts": {
    "hello": "node -e \"console.log('hello from npm script')\"",
    "build": "echo building...",
    "check": "node check.js"
  }
}
npm run 名字
D:\Path\To\demo>npm run hello

> ume-demo@1.0.0 hello
> node -e "console.log('hello from npm script')"

hello from npm script

D:\Path\To\demo>npm run
Scripts available in ume-demo@1.0.0 via `npm run`:
  hello
    node -e "console.log('hello from npm script')"
  build
    echo building...
  check
    node check.js

注意最后那个 npm run（不带名字）会列出所有可用脚本 —— 拿到一个陌生项目时，这是最先该敲的命令。

常用 npm 命令

命令作用
npm init -y生成 package.json
npm run列出所有脚本

为什么 npm 能当命令用

因为 npm 本身就是个 批处理文件 （安装目录里能找到 npm.cmd）。

这顺带解释了一个常见报错：如果你写脚本时写成 npm.bat 并调用它， 可能报权限或递归错误。在批处理里调用 npm 要写成 call npm run build （call 的作用见 5.4）。

5.3 python

用法和 node 几乎对称：

hello.py复制
import sys

print("Hello from Python")
print("Python 版本:", sys.version.split()[0])
print("参数:", sys.argv[1:])
运行
D:\Path\To>python hello.py alpha beta

参数: ['alpha', 'beta']

D:\Path\To>python -c "print(sum(range(1,101)))"

写法作用
python 文件.py运行一个脚本文件
python 文件.py a b带参数运行，脚本里用 sys.argv 取
python -c "代码"直接执行一行
python进入交互模式，exit() 退出
python -m 模块名把模块当程序跑，见下

python 里取三样「环境信息」

对应的写法复制
import sys, os

sys.argv[1:]               # 命令行参数（第 0 个是脚本名，所以要切掉）
os.getcwd()                # 当前工作目录（= cmd 里的 %CD%）
os.environ.get("UME_ROOT") # 读环境变量（= cmd 里的 %UME_ROOT%）
sys.exit(1)                # 退出码 1，供批处理判断
python 在 cmd 里输出中文会乱码 —— 这是个真坑

同一个脚本，node 输出中文正常，python 却打印出乱码。 原因是 python 判断「输出到控制台」时会按 Windows 的默认编码走，而不是 UTF-8。

实测三种解法，推荐前两种：

解法 A：脚本里自己声明（最稳）

写在脚本开头复制
import sys
sys.stdout.reconfigure(encoding="utf-8")

print("中文测试 OK")
运行结果
中文测试 OK

解法 B：批处理里设环境变量（不改脚本）

批处理里加一行复制
set PYTHONIOENCODING=utf-8
python report.py

解法 C：走命令行参数

只影响这一次运行复制
python -X utf8 report.py

注意解法 B 里 set 之后不要留尾随空格 —— 否则 python 会直接拒绝启动：

实测：值里带了空格就会这样
Fatal Python error: preconfig_init_utf8_mode: invalid PYTHONUTF8 environment variable value

python -m 有什么用

-m 是「把某个模块当程序运行」。两个很实用的：

常用 -m复制
# 装包（比直接敲 pip 更可靠，一定是当前这个 python 的 pip）
python -m pip install requests

# 建虚拟环境：给项目一个独立的包目录，不和系统混
python -m venv .venv

# 在某个目录起一个临时网页服务器（用来预览 UME.html 很方便）
python -m http.server 8000
为什么推荐 python -m pip

如果机器上装了多个 python，直接敲 pip 可能装到另一个 python 里去， 于是「明明装了却 import 不到」。

写 python -m pip 就锁定了正在用的这个 python，不会搞错。

5.4 在批处理里调用它们：别忘了 call

一条关键规则

在批处理里调用另一个 .bat / .cmd（npm 就是）， 必须加 call：

对比复制
rem ❌ 不加 call：控制权交给 npm 后就不回来了，后面的都不执行
npm run build
echo 这行不会被执行

rem ✅ 加 call：执行完回来继续
call npm run build
echo 这行会执行

原因：不加 call 时，cmd 会把控制权整个交给被调用的批处理， 自己那行之后的内容就不再执行了。call 的意思是「去执行一下，然后回来」。

node.exe 和 python.exe 是可执行程序（不是批处理）， 所以不需要 call：

对照复制
node build.js            rem ✅ 不用 call（node 是 exe）
python report.py         rem ✅ 不用 call（python 是 exe）
call npm run build       rem ✅ 要 call（npm 是 .cmd）
call other.bat           rem ✅ 要 call（另一个批处理）

6完整例子：一键检查环境

把前面所有东西合起来写一个实用脚本： 检查项目需要的工具是否都装好、版本对不对。

check_env.bat复制
@echo off
chcp 65001 >nul
setlocal enabledelayedexpansion

rem ① 把工作目录钉在脚本所在处，后面相对路径才有准
cd /d "%~dp0"
echo === UME 环境检查 ===
echo 项目目录: %CD%
echo.

rem ② 用一个变量累计失败次数
set FAIL=0

rem ③ 检查四个工具（where 找不到就返回非 0）
for %%T in (gcc node npm python) do (
    where %%T >nul 2>&1
    if !ERRORLEVEL! equ 0 (
        for /f "delims=" %%P in ('where %%T') do (
            echo [OK]   %%T  -^> %%P
            goto :next_%%T
        )
    )
    echo [缺失] %%T  请检查 PATH
    set /a FAIL+=1
    :next_%%T
)

echo.
if !FAIL! gtr 0 (
    echo 检查未通过：有 !FAIL! 个工具没找到
    exit /b 1
)
echo 检查通过，可以开始编译
exit /b 0
运行结果
D:\Path\To\project>check_env.bat
=== UME 环境检查 ===
项目目录: D:\Path\To\project

[OK]   gcc    -> D:\Qt\Tools\mingw1310_64\bin\gcc.exe
[OK]   node   -> D:\nodejs\node.exe
[OK]   npm    -> D:\nodejs\npm.cmd
[OK]   python -> C:\Users\Your_Username\AppData\Local\Python\bin\python.exe

检查通过，可以开始编译

D:\Path\To\project>echo %ERRORLEVEL%
0

这个脚本用到了本篇几乎所有知识点：

用到的在哪
@echo off + chcp 65001开头固定两行（2.1 / 2.2）
cd /d "%~dp0"钉住工作目录（2.3 / 3.3）
setlocal enabledelayedexpansion为了在括号里用 !FAIL!（4.1）
for %%T in (...)遍历四个工具（3.4）
!ERRORLEVEL!括号内取退出码（4.1 / 4.2）
where查工具装在哪（F01 讲过）
for /f读 where 的输出（3.4）
exit /b 数字把结果作为退出码返回（4.2）
这个脚本怎么改进

实际的 for 里用 goto 跳标签是有点取巧的写法 （为了避免打印多行）。更简单的做法是只检查存在性，不打印路径：

更简洁的版本复制
for %%T in (gcc node npm python) do (
    where %%T >nul 2>&1
    if !ERRORLEVEL! equ 0 (echo [OK]   %%T) else (
        echo [缺失] %%T
        set /a FAIL+=1
    )
)

够用就好 —— 脚本是给自己省事的，不必追求写得像正式程序。

顺带：把它接进一键构建

build.bat复制
@echo off
chcp 65001 >nul
cd /d "%~dp0"

rem ① 先检查环境，不通过就别往下走
call check_env.bat || exit /b 1

rem ② 清理旧产物
if exist build rd /s /q build
mkdir build

rem ③ 编译每一个 .c 文件
echo 正在编译...
for %%f in (src\*.c) do (
    gcc -std=c99 -c "%%f" -o "build\%%~nf.o"
    if !ERRORLEVEL! neq 0 (
        echo 编译失败: %%f
        exit /b 1
    )
)

rem ④ 链接
gcc build\*.o -o build\app.exe || exit /b 1

echo.
echo 构建完成: build\app.exe
exit /b 0

注意 ③ 里面用了 !ERRORLEVEL! —— 因为在 for 的括号里， 用 %ERRORLEVEL% 会拿到旧值（4.1 那个坑）。 所以这个脚本开头也得有 setlocal enabledelayedexpansion。

7常见错误

错误 1 · 中文变问号

对比复制
rem ❌ 存了中文却没切代码页
@echo off
echo 开始编译

rem ✅ 第二行固定加上
@echo off
chcp 65001 >nul
echo 开始编译

并确认文件另存为 UTF-8 无 BOM。

错误 2 · set 等号旁边留了空格

对比复制
set NAME = UME        rem ❌ 定义出的是 "NAME "，%NAME% 取不到
set NAME=UME          rem ✅ 紧挨着写

错误 3 · 括号里用 %变量%

对比复制
for %%f in (a b c) do (
    set /a N+=1
    echo %N%          rem ❌ 永远是进括号前的值
    echo !N!          rem ✅ 需要 enabledelayedexpansion
)

错误 4 · 比较字符串没加引号

对比复制
if %1==build echo hi     rem ❌ 没传参数时语法错误，脚本崩
if "%1"=="build" echo hi  rem ✅

错误 5 · 忘了 call

对比复制
npm run build         rem ❌ 后面的命令不执行了
echo 不会到这里

call npm run build    rem ✅
echo 会到这里

错误 6 · 用 exit 而不是 exit /b

对比复制
exit 1            rem ❌ 把整个 cmd 窗口关了，双击时像「闪退」
exit /b 1         rem ✅ 只结束当前脚本并返回码 1

错误 7 · 双击运行却没 pause

对比复制
rem ❌ 双击后窗口一闪就没了，看不到任何输出
@echo off
echo 做完了

rem ✅ 给别人双击的脚本，最后加一行
@echo off
echo 做完了
pause

错误 8 · python 输出中文乱码

对比复制
print("中文")                       rem ⚠ 在 cmd 里可能乱码

import sys
sys.stdout.reconfigure(encoding="utf-8")   rem ✅ 或设 PYTHONIOENCODING=utf-8
print("中文")

这一篇要记住的六句话
  1. 批处理 = 把命令写进 .bat，从上到下一行行执行。
  2. 开头固定两行：@echo off + chcp 65001 >nul， 文件存 UTF-8 无 BOM，中文才正常。
  3. 用 cd /d "%~dp0" 钉住工作目录， 这样双击和命令行运行结果一致。
  4. 括号里要用 !变量!（先开 setlocal enabledelayedexpansion）， 用 %变量% 拿到的是旧值。
  5. 判断成败用 if %ERRORLEVEL% neq 0 或 && / ||； 脚本里结束用 exit /b，别用 exit。
  6. 在批处理里调用 npm 要写 call npm …； node / python 是 exe，不用 call。
