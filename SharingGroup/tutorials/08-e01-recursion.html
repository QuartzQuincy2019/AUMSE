1递归是什么

第二讲讲函数时说过「函数可以相互调用」。递归是其中一种特殊情况：

递归 = 函数直接或间接地调用它自己。

听起来像「自己咬自己尾巴」，但用对了非常有力。先看一个最小的例子：

从 n 倒数到 0复制
#include <stdio.h>

void countdown(int n) {
    printf("%d ", n);

    if (n == 0) return;      /* ① 停下来的条件 */

    countdown(n - 1);           /* ② 调用自己，但问题变小了 */
}

int main(void) {
    countdown(5);
    printf("\n");
    return 0;
}
运行结果
5 4 3 2 1 0

注意那两行注释：递归能正常工作，全靠这两个条件。

2两个必备条件

一个递归函数必须同时具备
  1. 终止条件（base case） —— 什么时候不再调用自己，直接返回。 没有它就会无限递归，程序崩溃。
  2. 规模缩小 —— 每次调用自己时，问题要变得更小 （n - 1，而不是 n）。 这样才能保证最终会碰到终止条件。
对比：能停 vs 停不下来复制
/* ✅ 正确：有终止条件，规模在缩小 */
void good(int n) {
    if (n == 0) return;      /* 终止条件 */
    good(n - 1);               /* 规模缩小 */
}

/* ❌ 漏了终止条件 → 无限递归，栈被撑爆，程序崩 */
void bad1(int n) {
    bad1(n - 1);
}

/* ❌ 规模没缩小 → 永远碰不到终止条件 */
void bad2(int n) {
    if (n == 0) return;
    bad2(n);                   /* 还是 n！ */
}
写递归的顺序

很多人写递归时卡住，是因为想「一层层推下去」。 换个思路会顺很多：

  1. 先写终止条件：最小的情况答案是什么？（fact(1) = 1）
  2. 再假设「小一号的问题已经解决了」，然后写出「本题答案」和「小一号答案」的关系。

第二步是关键：不要去追它怎么解决的，直接相信它是对的。 这叫「递归信任」。

3调用栈：递归怎么跑起来的

递归不是魔法。每次调用自己，系统就在栈上新建一层 （第五讲讲过：栈上的东西随函数进出一层层叠放）。

把每一层打印出来看看复制
void countdown(int n, int depth) {
    for (int i = 0; i < depth; i++) printf("  ");   /* 缩进表示层数 */
    printf("countdown(%d)\n", n);

    if (n == 0) {
        for (int i = 0; i < depth; i++) printf("  ");
        printf("到底了，开始返回\n");
        return;
    }
    countdown(n - 1, depth + 1);
}
运行结果
countdown(3)
  countdown(2)
    countdown(1)
      countdown(0)
      到底了，开始返回

缩进一层层加深，说明栈一层层压下去。整个过程的形状是：

countdown(3) 第 1 层：n=3
countdown(2) 第 2 层：n=2
countdown(1) 第 3 层：n=1
countdown(0) 第 4 层：碰到终止条件，返回
返回时一层层往上退：第 4 层返回给第 3 层，第 3 层返回给第 2 层…… 直到第 1 层结束。这就是「递」和「归」两个阶段。
「递」与「归」

递：一层层往下调用，直到终止条件（写在调用自己之前的代码， 在往下走时执行）。

归：从最底层一层层返回（写在调用自己之后的代码， 在返回时执行）。

这个顺序很重要 —— 第 4 节有两个例子正是靠它才成立的。

4四个经典例子

① 阶乘：最标准的递归

n! = n × (n-1)!，而 1! = 1。直接照着写就行：

阶乘复制
long long fact(int n) {
    if (n <= 1) return 1;              /* 终止条件 */
    return n * fact(n - 1);              /* 本题 = n × 小一号的答案 */
}
运行结果
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
6! = 720

对比一下循环写法，两种都对，视习惯选择：

循环版复制
long long factLoop(int n) {
    long long r = 1;
    for (int i = 2; i <= n; i++) r *= i;
    return r;
}

② 斐波那契：能看出递归的代价

规律：f(0)=0, f(1)=1, f(n)=f(n-1)+f(n-2)。

斐波那契复制
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);       /* 两个递归调用 */
}
运行结果（前 9 项）
0 1 1 2 3 5 8 13 21
这个写法效率很差

因为它把同一个子问题重复算了很多遍： fib(5) 会算 fib(3) 两次、fib(2) 三次……

算 fib(40) 就要几秒钟。要实用， 得改成循环（或加「记住算过的结果」的缓存）。递归不等于高效。

③ 递归求和

1+2+...+n复制
int sumTo(int n) {
    if (n == 0) return 0;
    return n + sumTo(n - 1);
}
运行结果
1+2+...+10 = 55

④ 十进制转二进制：靠「归」的顺序

这个例子最能体现「先递后归」的妙处。 10 的二进制是 1010，可如果先算个位再算高位，打印出来是反的。 把打印写在递归调用之后，就自动正过来了：

转二进制复制
void toBinary(int n) {
    if (n == 0) return;          /* 终止条件 */
    toBinary(n / 2);              /* 先处理高位（往下走） */
    printf("%d", n % 2);             /* 返回时才打印这一位 */
}
运行结果
10 -> 1010
255 -> 11111111

如果把 printf 挪到 toBinary(n/2) 前面，就会打印成 0101 —— 顺序全反了。这就是「递」和「归」的差别。

⑤ 顺便：递归也能处理字符串

倒着打印一个字符串复制
void printReverse(const char *s) {
    if (*s == '\0') return;       /* 终止条件：遇到字符串结尾 */
    printReverse(s + 1);          /* 先处理剩下的（第四讲的指针算术） */
    printf("%c", *s);                  /* 返回时才打印自己 */
}
运行结果
Mongol 倒过来: lognoM

终止条件用的是第八讲的 '\0'，往下走用的是指针 s + 1。

5递归的代价

递归写起来简洁，但有两个实际代价。

代价一：占栈空间，太深会崩

每一层递归都要在栈上占一块地方（第五讲：栈只有 1~8 MB）。 递归几千层还行，几十万层就会「栈溢出」——程序直接崩，而且报错信息很难懂。

void boom(int n) {
    if (n == 0) return;
    boom(n - 1);       /* n = 1000000 时多半就崩了 */
}

循环版本没有这个问题 —— 它只占一层。

代价二：可能重复计算

就是上面斐波那契的问题。递归写法的「形状」如果是分叉的， 同一个子问题会被反复求解，效率可能差到不可用。

判断办法：看递归调用有几处。一处（如阶乘）通常没问题； 两处以上（如斐波那契）就要当心。

什么时候该用递归

情况建议
问题天然是「一层套一层」的（括号嵌套、目录树、表达式） 用递归 循环很难写清楚
结构是「线性」的（数组求和、找最大值、数个数） 用循环 更简单也更快
深度可能很大（几万层以上） 用循环 或改写成「带自己栈的循环」
递归调用有两处以上，且规模不大 小心 先估算重复计算的量
一个判断口诀

能用循环写得一样清楚的，就用循环；只有循环写起来很别扭时才用递归。

递归的价值在于表达力（把复杂结构写得短），不在于性能。

6常见错误

错误 1 · 忘了终止条件

对比复制
int fact(int n) {
    return n * fact(n - 1);       /* ❌ 永远停不下来 */
}

int fact(int n) {
    if (n <= 1) return 1;          /* ✅ 终止条件必须在最前面 */
    return n * fact(n - 1);
}

错误 2 · 规模没缩小

对比复制
void f(int n) {
    if (n == 0) return;
    f(n);                    /* ❌ 还是 n，永远到不了 0 */
}

void f(int n) {
    if (n == 0) return;
    f(n - 1);                 /* ✅ 每次小一点 */
}

错误 3 · 终止条件写错边界

对比复制
/* ❌ 如果传进来 0，n-1 变成 -1，越走越远，永远到不了 n==1 */
int fact(int n) {
    if (n == 1) return 1;
    return n * fact(n - 1);
}

/* ✅ 用 <= 覆盖最小的几种情况 */
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}

终止条件建议写成「小于等于」，把边界外的意外输入也兜住。

错误 4 · 忘了把「递归调用之后」的代码写对顺序

对比复制
/* ❌ 先打印低位 → 结果是倒的（0101） */
void toBinary(int n) {
    if (n == 0) return;
    printf("%d", n % 2);
    toBinary(n / 2);
}

/* ✅ 把打印放到调用之后 → 自动正序 */
void toBinary(int n) {
    if (n == 0) return;
    toBinary(n / 2);
    printf("%d", n % 2);
}

错误 5 · 该用循环的地方硬用递归

对比复制
/* ❌ 求数组最大值用递归：又慢又有深度风险 */
int maxInArray(int a[], int n) {
    if (n == 1) return a[0];
    int rest = maxInArray(a, n - 1);
    return a[n - 1] > rest ? a[n - 1] : rest;
}

/* ✅ 一遍循环就够了（第一讲的打擂法） */
int maxInArray(int a[], int n) {
    int mx = a[0];
    for (int i = 1; i < n; i++)
        if (a[i] > mx) mx = a[i];
    return mx;
}

7一页速查

想做的事写法
递归函数的三段结构 终止条件 → 缩小规模 → 调用自己
阶乘n <= 1 ? 1 : n * fact(n-1)
求和 1..nn == 0 ? 0 : n + sumTo(n-1)
斐波那契（不推荐）fib(n-1) + fib(n-2)
按「归」的顺序做事把语句写在递归调用之后
字符串递归终止：*s == '\0'；缩小：s + 1
判断递归有几处两处以上要警惕重复计算
深度太大改用循环
这一篇要记住的四句话
  1. 递归 = 函数调用自己，必须有终止条件且每次都缩小规模。
  2. 「递」是往下调用，「归」是往上返回； 把语句放在递归调用之前还是之后，结果可能完全不同。
  3. 递归占栈空间，太深会崩；分叉的递归还可能重复计算。
  4. 能用循环写清楚的就用循环，只在结构天然嵌套时才用递归。
