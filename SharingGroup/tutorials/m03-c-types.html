1类型为什么重要

你写过的每一条变量声明，都包含了类型：

类型无处不在复制
int a = 10;          /* int 是类型 */
double d = 3.14;     /* double 是类型 */
char c = 'A';        /* char 是类型 */
int arr[5];          /* 「5 个 int」也是一种类型 */

很多人觉得类型只是「写代码时的规定」，其实它管着三件大事：

占多少内存
int 占 4 字节，char 占 1 字节
能表示多大
决定取值范围，超了就出错
怎么解释这串位
同样的位，按不同规则读出不同的值

举一个立刻能感受到的例子 —— 同一串二进制位 11111111：

同样的位，不同的读法复制
#include <stdio.h>

int main(void) {
    char c = -1;
    unsigned char u = 255;

    printf("按有符号读： %d\n", (int)c);
    printf("按无符号读： %d\n", (int)u);
    return 0;
}
运行结果
按有符号读： -1
按无符号读： 255

内存里那 8 位都是 11111111，一模一样。 但按 char 读出来是 -1，按 unsigned char 读出来是 255。

本讲最重要的一句话

类型决定了「这块内存占多宽」以及「里面的位该怎么解释」。

所以类型不是形式主义 —— 它直接决定了程序算出来的是不是你要的答案。

2类型的三件事

学类型，只要盯住三个问题就够了：

问题以 int 为例为什么重要
① 占几字节4 字节 = 32 位 决定内存用量；也是数组「总大小 ÷ 单个大小 = 元素个数」的依据
② 能表示多大范围-2147483648 ~ 2147483647 算超出范围就会「溢出」，结果不是你想要的
③ 有没有负数有（signed）；
加了 unsigned 就没有		 影响比较运算的结果，也影响范围怎么算

这三件事理解了，后面所有类型都是同一套逻辑。

3二进制速成

要理解类型，先得知道内存里的数字长什么样。这一节把二进制讲清楚。

3.1 内存里只有 0 和 1

内存由无数个小开关组成，每个开关只有两种状态：通或断， 记作 1 和 0。这就是二进制。

为什么不用十进制？因为电路做「两种状态」最容易、最可靠。 计算机内部一切都是二进制，我们看到的 10、'A'、3.14 都是「给人看的写法」，存进去时都变成了 0 和 1。

3.2 十进制 ↔ 二进制

十进制的每一位代表 10 的幂，二进制每一位代表 2 的幂：

第几位（从右往左数）01234567
代表的值1248163264128

把十进制数拆成「2 的幂之和」，再把对应的位置写成 1，就得到二进制。

例：把 5 写成二进制

5 = 4 + 1，也就是 2² + 2⁰， 所以第 2 位和第 0 位是 1：

12 = 8 + 4 = 2³ + 2²，所以第 3 位和第 2 位是 1：

用程序打印出来核对一下：

打印一个数的二进制复制
#include <stdio.h>

/* 从最高位往最低位，一位一位打印 */
void printBinary(int n) {
    for (int i = 7; i >= 0; i--) {
        printf("%d", (n >> i) & 1);
    }
}

int main(void) {
    int vals[5] = {0, 1, 2, 5, 12};
    for (int i = 0; i < 5; i++) {
        printf("%3d -> ", vals[i]);
        printBinary(vals[i]);
        printf("\n");
    }
    return 0;
}
运行结果
  0 -> 00000000
  1 -> 00000001
  2 -> 00000010
  5 -> 00000101
 12 -> 00001100

其中 (n >> i) & 1 的意思是： 把第 i 位移到最右边，再取出最低位。 现在不用深究，第 4 节之后再回来看就懂了。

3.3 位与字节

一位（bit）太小，所以把 8 位打包成一个字节（byte）：

1 字节 = 8 位

8 位能表示多少个数

每一位有 2 种可能，8 位就有 2⁸ = 256 种组合。所以：

  • 无符号 unsigned char：把 256 种全给非负数 → 0 ~ 255
  • 有符号 char：正负各分一半 → -128 ~ 127

注意两种情况的总数都是 256，只是分配方式不同。

3.4 为什么还要用十六进制

二进制写起来太长（00001100），十进制又看不出位的规律。 于是有了折中方案：十六进制。

它好用的原因很巧：1 位十六进制正好等于 4 位二进制。 所以 8 位二进制正好写成 2 位十六进制，非常整齐。

十进制二进制十六进制说明
101010A十六进制里 10~15 用 A~F 表示
121100C
151111F4 位全是 1
25511111111FF8 位全是 1 = 一个字节塞满

在 C 里写十六进制，前面加 0x：

十六进制写法复制
#include <stdio.h>

int main(void) {
    int a = 12;

    printf("12 = 0x%X\n", a);      /* %X 按十六进制打印 */
    printf("255 = 0x%X\n", 255);
    printf("0xFF = %d\n", 0xFF);  /* 反过来：0x 开头就是十六进制数 */
    printf("0x10 = %d\n", 0x10);  /* 注意不是 10，是 16 */
    return 0;
}
运行结果
12 = 0xC
255 = 0xFF
0xFF = 255
0x10 = 16
小心这个坑

0x10 不是 10，而是 16（1×16 + 0）。 同理 010（以 0 开头）在 C 里是八进制，等于 8。 写数字时不要随便在前面加 0。

4常见类型的大小

先亲手量一量最靠谱 —— 用 sizeof 运算符， 它能问出「某个类型占几字节」：

sizeof 量一量复制
#include <stdio.h>

int main(void) {
    printf("char        %d 字节\n", (int)sizeof(char));
    printf("short       %d 字节\n", (int)sizeof(short));
    printf("int         %d 字节\n", (int)sizeof(int));
    printf("long        %d 字节\n", (int)sizeof(long));
    printf("long long   %d 字节\n", (int)sizeof(long long));
    printf("float       %d 字节\n", (int)sizeof(float));
    printf("double      %d 字节\n", (int)sizeof(double));
    return 0;
}
运行结果（64 位 Windows）
char        1 字节
short       2 字节
int         4 字节
long        4 字节
long long   8 字节
float       4 字节
double      8 字节

unsigned char18 0 ~ 255字节数据、0~255 的数

两点必须注意
  • 上表是「常见情况」，不是铁律。C 标准只规定了最少位数， 具体大小由「编译器 + 平台」决定。 比如 long 在 64 位 Windows 上是 4 字节， 在 64 位 Linux 上却是 8 字节。
  • 想确定就用 sizeof 量，不要凭记忆猜。 这也是为什么上面先让你自己跑一遍。
关于 float 和 double 怎么存

本讲不展开小数（浮点数）的内部编码 —— 那涉及 IEEE 754 的符号位/指数位/尾数位划分，属于进阶内容。

现在只需要记住三件事：

  • float 占 4 字节，double 占 8 字节
  • 它们能表示的范围极大，但有效数字有限 （float 约 7 位，double 约 15 位）
  • 初学阶段小数一律用 double，稳妥

用 sizeof 算出数组长度

你在M01见过这个用法，现在能解释原理了：

总大小 ÷ 单个大小复制
int a[10];
int n = (int)(sizeof(a) / sizeof(a[0]));
/*  40 字节  ÷  4 字节  =  10 个元素 */

5有多少位，就有多大范围

范围不是随便定的，它由位数直接算出来：

n 位的无符号整数，能表示 2ⁿ 个数，范围是 0 ~ 2ⁿ-1。
有符号的话，把 2ⁿ 个名额分成「负数 + 非负数」两半，就是 -2ⁿ⁻¹ ~ 2ⁿ⁻¹-1。

对照着看，规律非常明显：

位数2ⁿ无符号范围有符号范围
82560 ~ 255-128 ~ 127
16655360 ~ 65535-32768 ~ 32767
3242949672960 ~ 4294967295-2147483648 ~ 2147483647
641.8×10¹⁹0 ~ 1.8×10¹⁹约 ±9.2×10¹⁸

注意有符号的那一列：负数那半边总比正数那半边多一个。 因为 0 占了正数侧的一个名额，所以 char 是 -128 ~ 127， 而不是对称的 -127 ~ 127。

用程序把上下限打出来（用 <limits.h> 里的现成常量）：

打印各类型的边界复制
#include <stdio.h>
#include <limits.h>      /* 各种边界常量都在这里 */

int main(void) {
    printf("char      %d ~ %d\n", CHAR_MIN, CHAR_MAX);
    printf("short     %d ~ %d\n", SHRT_MIN, SHRT_MAX);
    printf("int       %d ~ %d\n", INT_MIN, INT_MAX);
    printf("unsigned  %u ~ %u\n", 0u, UINT_MAX);
    printf("int 有 %d 位\n", (int)(sizeof(int) * 8));
    return 0;
}
运行结果
char      -128 ~ 127
short     -32768 ~ 32767
int       -2147483648 ~ 2147483647
unsigned  0 ~ 4294967295
int 有 32 位

6有符号与无符号

在类型前加 unsigned，就表示「不要负数，把全部名额都给非负数」：

类型含义范围
int有符号，能存负数-2147483648 ~ 2147483647
unsigned int无符号，只能非负0 ~ 4294967295

注意：两者的范围宽度是一样的（都是 2³²）， 只是 unsigned 把原本给负数的部分挪到了正数那边。

无符号的「回绕」

无符号数减到 0 以下不会变成负数，而是绕回到最大值：

0 减 1 的两种命运复制
#include <stdio.h>

int main(void) {
    int i = 0;
    unsigned int u = 0;
    unsigned char uc = 0;

    printf("int           0 - 1 = %d\n", i - 1);
    printf("unsigned int  0 - 1 = %u\n", u - 1);
    printf("unsigned char 0 - 1 = %d\n", (int)(unsigned char)(uc - 1));
    return 0;
}
运行结果
int           0 - 1 = -1
unsigned int  0 - 1 = 4294967295
unsigned char 0 - 1 = 255

可以这样理解：无符号数像一个只有 0~9 的里程表， 从 0 往回拨一格，就跳到了 9（最大值）。

真正的陷阱：有符号和无符号一起比较

当 int 和 unsigned int 出现在同一个比较里， C 会把 int 悄悄转成无符号再看。如果它是负数，就会变成一个极大的数：

看着对，其实反了复制
#include <stdio.h>

int main(void) {
    int n = -1;
    unsigned int m = 1;

    printf("m > n 的结果 = %d\n", m > n);
    printf("(unsigned)-1 = %u\n", (unsigned)-1);

    /* 无符号循环变量往回走，会死循环 */
    printf("0u - 1 = %u\n", 0u - 1);
    return 0;
}
运行结果
m > n 的结果 = 0
(unsigned)-1 = 4294967295
0u - 1 = 4294967295

m > n 即 1 > -1， 按数学应该是「成立」，可结果是 0（不成立）！ 原因是 -1 被当成了 4294967295，1 当然不比它大。

实用建议
  • 循环变量一律用 int，不要用 unsigned。 这样倒着遍历（i--）才不会出事。
  • 不要拿无符号数和有符号数直接比大小。真的要混用， 先想清楚哪一个该转成什么。
  • 日常生活中「数量、下标」这类天然非负的量， 用 int 也完全够（21 亿的上限很难用完）。

7溢出的真面目

既然范围有限，那超过范围会怎样？ 答案：绕回去，而且不报错。这是 C 语言最需要警惕的地方之一。

最大值再加 1 会怎样复制
#include <stdio.h>
#include <limits.h>

int main(void) {
    int big = INT_MAX;

    printf("INT_MAX     = %d\n", big);
    printf("INT_MAX + 1 = %d\n", big + 1);
    printf("INT_MIN     = %d\n", INT_MIN);
    printf("INT_MIN - 1 = %d\n", INT_MIN - 1);
    return 0;
}
运行结果
INT_MAX     = 2147483647
INT_MAX + 1 = -2147483648
INT_MIN     = -2147483648
INT_MIN - 1 = 2147483647

最大的正数加 1，变成了最小的负数；最小的负数减 1，变成了最大的正数。 就像里程表从 99999 再走一格变成 00000。

溢出为什么危险

因为它不会报错、不会崩溃，只是安静地给你一个错的数。 等你发现结果不对时，可能已经排查了很久。

典型场景：

  • 累加很多个大数（比如求 1 到 100000 的平方和）
  • 计算阶乘（13! 就已经超出 int 范围了）
  • 两个大数相乘

对策：事先估算一下结果大概多大。觉得可能超，就换成 long long（8 字节，约 ±9.2×10¹⁸）。

自己动手检查有没有溢出

有个简单办法：加之前先看看会不会超。

加法前先判断复制
#include <stdio.h>
#include <limits.h>

int main(void) {
    int a = 2000000000;
    int b = 2000000000;

    /* 若 a + b 会超出 INT_MAX，就提前提醒 */
    if (a > INT_MAX - b) {
        printf("会溢出，不能直接相加\n");
        printf("用 long long 算：%lld\n", (long long)a + b);
    }
    return 0;
}
运行结果
会溢出，不能直接相加
用 long long 算：4000000000

诀窍是：把「加法」换成「减法」来判断。 a + b 会溢出，但 INT_MAX - b 不会， 所以比较 a > INT_MAX - b 是安全的。

8类型转换

不同类型混在一起运算时，C 会自动转换；你也可以用 (类型) 强制转换。

自动转换：小的往大的靠

int 和 double 一起算复制
int a = 5;
double d = 2.0;

a + d      /* a 先被转成 double，结果是 7.0 */

强制转换：写 (类型)

显式转换复制
int n = 7, m = 2;

printf("%d\n", n / m);              /* 整数除法：3      */
printf("%.1f\n", (double)n / m); /* 转成小数再除：3.5 */
运行结果
3
3.5

大转小：会把高位切掉

把一个大的数塞进小的类型，多出来的部分会被直接丢掉：

300 装不进一个 char复制
#include <stdio.h>

int main(void) {
    int v = 300;

    printf("v = %d\n", v);
    printf("(char)300          = %d\n", (char)v);
    printf("(unsigned char)300 = %d\n", (unsigned char)v);
    printf("(short)70000       = %d\n", (short)70000);
    return 0;
}
运行结果
v = 300
(char)300          = 44
(unsigned char)300 = 44
(short)70000       = 4464

为什么 300 会变成 44？因为 char 只有 8 位， 只能留下 300 的低 8 位。300 = 100101100（9 位）， 砍掉最高位剩下 00101100 = 44。

小数转整数：直接截断，不四舍五入

截断而不是取整复制
#include <stdio.h>

int main(void) {
    printf("(int)3.9  = %d\n", (int)3.9);
    printf("(int)-3.9 = %d\n", (int)-3.9);
    printf("(int)3.5 + (int)3.5 = %d\n", (int)3.5 + (int)3.5);
    printf("(int)(3.5 + 3.5)    = %d\n", (int)(3.5 + 3.5));
    return 0;
}
运行结果
(int)3.9  = 3
(int)-3.9 = -3
(int)3.5 + (int)3.5 = 6
(int)(3.5 + 3.5)    = 7
最后两行的差别很关键

(int)3.5 + (int)3.5 是先各自截断再相加： 3 + 3 = 6。

(int)(3.5 + 3.5) 是先加再截断： (int)7.0 = 7。

括号的位置决定了先做哪一步，结果就不一样。 强制转换的括号要写清楚作用范围。

需要四舍五入怎么办

(int) 只会砍掉小数，想要「四舍五入」得自己加 0.5：

手工四舍五入复制
double x = 3.7;
int r = (int)(x + 0.5);   /* 3.7+0.5 = 4.2 → 4 */

double y = 3.2;
int s = (int)(y + 0.5);   /* 3.2+0.5 = 3.7 → 3 */

9初识「地址」

前面讲了「一个变量占几字节」。接下来问一个更根本的问题： 这些字节到底放在哪里？

核心概念：地址

内存可以想象成一条很长很长的走廊，走廊两侧是无数个编了号的房间， 每个房间 1 字节。

房间的编号，就叫「地址」。

你声明一个变量时，系统就分配给它若干个房间（int 要 4 个）， 并且这些房间有确定的地址。

怎么看到一个变量的地址

用 & 运算符 —— 读作「取地址」：

& 取地址复制
#include <stdio.h>

int main(void) {
    int a = 10;

    printf("a 的值   = %d\n", a);
    printf("a 的地址 = %p\n", (void *)&a);
    return 0;
}
运行结果（每次运行地址都会变）
a 的值   = 10
a 的地址 = 000000000060FD8C

说明两点：

  • %p 是专门用来打印地址的格式符（p = pointer）。 这里的 (void *) 是打印地址时的固定写法，先照抄。
  • 这个数字每次运行都可能不同，也可能换台电脑就不同。 它是系统运行时分配的，不用去记具体值。
记住这个符号表
写法读作意思
aa 的值房间里装的东西
&aa 的地址房间的编号

「值」和「地址」是两回事，别混。 就像「房间里住着谁」和「房间是 302 号」是两回事。

为什么要知道地址

因为下一讲的指针，本质就是「专门用来装地址的变量」。

如果现在「地址」这个概念没立住，学指针时就会一头雾水。 所以这一节请务必看懂：变量有值，也有地址；& 用来取地址。

10地址与数组

数组和地址的关系特别紧密，因为M01说过：数组元素是排成一排挨着的。 这一节用地址来验证这句话。

看看相邻元素的地址复制
#include <stdio.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};

    for (int i = 0; i < 4; i++) {
        printf("arr[%d] 值=%-3d 地址=%p\n", i, arr[i], (void *)&arr[i]);
    }
    return 0;
}
运行结果
arr[0] 值=10  地址=000000000060FD7C
arr[1] 值=20  地址=000000000060FD80
arr[2] 值=30  地址=000000000060FD84
arr[3] 值=40  地址=000000000060FD88

把地址的后两位单独看，规律一目了然：

元素地址与上一个相差
arr[0]...FD7C—
arr[1]...FD80+4
arr[2]...FD84+4
arr[3]...FD88+4

每个元素正好差 4 字节 —— 因为每个 int 占 4 字节， 它们一个挨一个排着，中间没有空隙。

数组的第一条地址规律

数组名就是第一个元素的地址：

int arr[4];
/* arr      等价于  &arr[0]   —— 都是第一个元素的地址 */

这也是为什么 scanf("%d", &arr[i]) 要写 &： scanf 需要知道往哪个房间放东西，所以要给它地址。

验证 arr 与 &arr[0] 相同复制
#include <stdio.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};

    printf("arr       = %p\n", (void *)arr);
    printf("&arr[0]   = %p\n", (void *)&arr[0]);
    printf("两者相同吗？ %d\n", arr == &arr[0]);
    return 0;
}
运行结果
arr       = 000000000060FD7C
&arr[0]   = 000000000060FD7C

地址的「步长」由类型决定

有意思的是：同样是「加 1」，不同类型的地址前进的距离不一样。 因为要跳过一个完整的元素。

不同类型前进多少字节复制
#include <stdio.h>

int main(void) {
    int    ia[2] = {0, 0};
    char   ca[2] = {0, 0};
    double da[2] = {0, 0};

    printf("int    相邻元素差 %d 字节\n",
           (int)((char *)&ia[1] - (char *)&ia[0]));
    printf("char   相邻元素差 %d 字节\n",
           (int)((char *)&ca[1] - (char *)&ca[0]));
    printf("double 相邻元素差 %d 字节\n",
           (int)((char *)&da[1] - (char *)&da[0]));
    return 0;
}
运行结果
int    相邻元素差 4 字节
char   相邻元素差 1 字节
double 相邻元素差 8 字节

正好对应它们的 sizeof：4、1、8。

一句话总结本讲： 类型决定房间有多大（sizeof）、能装多大的数（范围）、 怎么读里面的位（有符号/无符号）；
而每个变量都住在有编号的房间里，编号就是地址，& 用来取它。

11常见错误

错误 1 · 以为数据能装进小类型

对比复制
/* ❌ char 最大 127，装不下 200 */
char c = 200;              /* 结果 -56，完全不是 200 */

/* ✅ 用够大的类型 */
int  c = 200;              /* 200 */
unsigned char c = 200;     /* 200（0~255 装得下） */

错误 2 · 整数除法丢小数

对比复制
int sum = 499, n = 6;

printf("%.2f\n", sum / n);         /* ❌ 83.00 */
printf("%.2f\n", (double)sum / n); /* ✅ 83.17 */

错误 3 · 混用有符号与无符号做比较

对比复制
unsigned int m = 1;
int n = -1;

if (m > n) { ... }            /* ❌ 结果是不成立！ */

/* ✅ 要么都用 int，要么先想清楚转换方向 */
int m = 1;
if (m > n) { ... }            /* 成立 */

错误 4 · 数字前面随手加 0

对比复制
int a = 010;      /* ❌ 这是八进制，等于 8，不是 10 */
int a = 10;       /* ✅ */

错误 5 · 溢出没察觉

对比复制
/* 求 1..100000 的平方和，结果约 3.3×10^14，远超 int */
int s = 0;                              /* ❌ 溢出，结果是错的 */
long long s = 0;                      /* ✅ 8 字节能装下 */

错误 6 · 把「地址」和「值」搞混

对比复制
int a = 10;

printf("%d\n", a);     /* ✅ 打印值：10 */
printf("%d\n", &a);    /* ❌ 用 %d 打印地址，类型不对 */
printf("%p\n", (void *)&a);  /* ✅ 地址要用 %p */

想做的事写法
量某个类型占几字节sizeof(int)
量某个变量占几字节sizeof(a)
算出数组元素个数sizeof(a) / sizeof(a[0])
取变量的地址&a
打印地址printf("%p", (void *)&a);
int 的范围-2147483648 ~ 2147483647
unsigned int 的范围0 ~ 4294967295
查范围常量#include <limits.h> → INT_MAX

强制类型转换(double)sum / n

第 i 个元素的地址&arr[i]
两个地址相差多少字节(char *)&b - (char *)&a
本讲要记住的五句话
  1. 类型决定三件事：占多宽、能表示多大、怎么读里面的位。
  2. 1 字节 = 8 位；n 位无符号能表示 2ⁿ 个数，范围 0 ~ 2ⁿ-1。
  3. int 是 4 字节 32 位，范围约 ±21 亿；超了会「绕回去」，而且不报错。
  4. unsigned 没有负数，减到 0 以下会绕成最大值。
  5. 变量有值，也有地址；& 取地址，%p 打印地址。

既然地址就是一个数，那能不能把它存进一个变量里？

能 —— 这种「专门装地址的变量」就叫指针。 你会发现它一点也不神秘，只是把本讲第 9 节的「地址」装进了变量； 而且它非常强大：能让函数修改外面的变量、能高效遍历数组、 能用一句话处理一整片数据。
