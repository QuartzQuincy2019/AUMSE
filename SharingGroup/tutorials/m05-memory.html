静态、动态内存与内存安全初步

UME 项目组内部教程 · M05（Main） · 面向零编程基础成员

已学：数组 / 函数 / 指针 已学：类型与地址 本讲：内存从哪来、怎么还

这一讲要解决什么

前面几讲里，数组的长度都是写死的：int arr[100];。 可是如果运行时才知道要存多少个数呢？

这一讲回答这个问题，并顺带把「内存分几块、各自什么脾气」讲清楚 —— 这是写出不崩溃的程序的基础。

文中所有「运行结果」均经过实际编译运行核对。

1内存为什么不够用

先看一个真实的需求：读入 n 个数，然后倒序输出。

问题在于，n 是运行时才知道的 —— 用户可能输入 5，也可能输入 5000。 你写数组的时候不知道要开多大。

办法一：开一个「肯定够大」的数组

先开大一点复制
int a[10000];      /* 先按最大可能开 */
scanf("%d", &n);
for (int i = 0; i < n; i++) {
    scanf("%d", &a[i]);
}

这个办法能跑，但有两个毛病：

  • 浪费。用户只输入 3 个数，你却一直占着 10000 个格子的位置。
  • 还是可能不够。万一用户输入 20000 个呢？照样越界。

办法二：运行时再决定开多大

这就是动态内存要做的事：程序跑起来之后， 根据实际需要临时向系统申请一块刚好的内存，用完再还回去。

本讲的核心问题

内存不是只有一种，它们来历不同、脾气不同。

搞清楚「这块内存是谁给的、什么时候没的、要不要我负责还」， 就能避开一大类很难查的程序崩溃。

2三种「存放方式」总览

程序运行时用到的内存，大致分三块。先看整体印象，后面逐个展开。

静态内存
谁给的：编译时就安排好
什么时候没的：程序结束
要我还吗：不用
典型：全局变量、static 变量
特点：整份程序共用一份
自动内存（栈）
谁给的：进函数时自动分配
什么时候没的：出函数就没了
要我还吗：不用
典型：局部变量、局部数组
特点：又快又省心，但空间有限
动态内存（堆）
谁给的：你调用 malloc 才给
什么时候没的：你调用 free 才没
要我还吗：必须还
典型：malloc 得到的内存
特点：大小随意、活得久，但一切自己管
一句话对比：
静态和栈内存系统替你管，你只管用；
堆内存系统一概不管，申请和归还都得你亲手做。
先记住这个比喻：
静态内存像自己家的家具（一直在）；
栈内存像去餐厅吃饭的桌子（坐下就有，走时自动收）；
堆内存像租的仓库（要自己去租，用完必须自己去退，忘了退就一直扣钱）。

3静态内存

写在所有函数外面的变量，就是静态内存。它在程序启动时就存在， 程序结束才消失。

全局变量复制
#include <stdio.h>

int gCount = 0;          /* 写在函数外面：全局变量 */

void addOne(void) {
    gCount++;                /* 任何函数都能用它 */
}

int main(void) {
    printf("开始: gCount = %d
", gCount);
    addOne();
    addOne();
    printf("调用两次后: gCount = %d
", gCount);
    return 0;
}
运行结果
开始: gCount = 0
调用两次后: gCount = 2

static 局部变量：只初始化一次，但活得很久

在局部变量前面加 static，它就变成静态的： 函数退出后它不会消失，下次进函数还是上次的值。

对比：普通局部 vs static 局部复制
#include <stdio.h>

void normal(void) {
    int n = 0;        /* 每次进来都重新变成 0 */
    n++;
    printf("普通局部   n = %d
", n);
}

void keep(void) {
    static int n = 0;  /* 只初始化一次，之后一直留着 */
    n++;
    printf("static局部 n = %d
", n);
}

int main(void) {
    for (int i = 0; i < 3; i++) {
        normal();
        keep();
    }
    return 0;
}
运行结果
普通局部   n = 1
static局部 n = 1
普通局部   n = 1
static局部 n = 2
普通局部   n = 1
static局部 n = 3
静态内存的特点
  • 不用管。不用申请，也不用释放，最省心。
  • 大小固定。编译时就定下来了，运行时改不了。
  • 全局可见（不加 static 时）。任何函数都能读写，很方便 —— 但正因为太方便，滥用会让程序很难维护： 你不知道到底是谁把它改了。

建议：能用局部变量就用局部变量，全局变量只在确实需要共享时才用。

4自动内存（栈）

你在函数里写的每一个局部变量、每一个局部数组，都在栈上。 进函数时自动分配，出函数时自动回收。

局部变量都在栈上复制
#include <stdio.h>

void demo(void) {
    int a = 1;
    int b = 2;
    int c = 3;
    printf("a=%d b=%d c=%d
", a, b, c);
    printf("&a=%p  &b=%p  &c=%p
", (void *)&a, (void *)&b, (void *)&c);
    /* 地址是挨着的，说明它们挤在同一块「栈」上 */
}

int main(void) {
    demo();
    return 0;
}
运行结果（地址每次运行都会变）
a=1 b=2 c=3
&a=000000000060FD0C  &b=000000000060FD08  &c=000000000060FD04

三个地址挨在一起（这里是每个差 4 字节，正好是 int 的大小）， 说明它们确实排在同一块内存上。

栈的两个硬性限制

限制一：大小有限

栈通常只有 1~8 MB（具体看系统设置）。 在函数里开一个巨大的局部数组，就会「爆栈」：

void bad(void) {
    int big[10000000];   /* 约 40 MB，多半直接崩 */
}

这种崩溃往往表现为「程序一闪就没了」，很难看出原因。

限制二：出函数就消失

局部变量只在函数执行期间存在。函数一返回，它们就没了。 所以不能把局部数组的地址返回给调用者：

int *bad(void) {
    int local[3] = {1, 2, 3};
    return local;    /* ❌ 函数一结束，这块内存就没了 */
}

返回的地址指向一块已经不属于你的内存，用它是未定义行为。 第 8 节会讲正确做法。

栈的好处

别因为上面两条就觉得栈不好。绝大多数情况下都应该用栈：

  • 不用申请、不用释放，不可能忘记归还
  • 分配回收极快（就是挪一下栈指针）
  • 局部性好，别人改不到你的变量

5动态内存（堆）

当「大小要运行时才知道」或者「需要活得比函数长」时， 就要用堆：自己去申请，自己负责归还。

完整的一生只有三步：

malloc
申请一块内存
拿到它的地址
使用
像数组一样读写
下标或指针都行
free
还回去
必须做，且只能做一次

5.1 malloc：申请一块内存

用法是 malloc(要多少字节)，返回这块内存的起始地址：

基本用法复制
#include <stdio.h>
#include <stdlib.h>          /* malloc / free 在这里 */

int main(void) {
    int n = 5;

    /* 申请「5 个 int」那么大的内存 */
    int *p = malloc(sizeof(int) * n);

    if (p == NULL) {          /* 判断是否成功，好习惯 */
        printf("申请失败
");
        return 1;
    }

    /* 用起来和数组一模一样 */
    for (int i = 0; i < n; i++) {
        p[i] = (i + 1) * 10;
    }
    for (int i = 0; i < n; i++) {
        printf("%d ", p[i]);
    }
    printf("
");

    free(p);               /* 用完还回去 */
    return 0;
}
运行结果
10 20 30 40 50

注意两个要点：

写法为什么这样写
malloc(sizeof(int) * n) sizeof(int) 拿到一个 int 的字节数，乘 n 就是总字节数。 不要自己写 4 —— 换个平台可能就不是 4 了
p[i] 拿到的地址可以当数组用，下标写法最清楚
malloc 只负责「给地方」，不负责「打扫」

申请到的内存里是不确定的内容（可能是任意数据）， 不是 0。用之前一定要自己赋值。

实测对照（下面会讲 calloc）：

malloc 与 calloc 的差别复制
int *a = malloc(sizeof(int) * 4);
int *b = calloc(4, sizeof(int));
printf("malloc: %d %d %d %d
", a[0], a[1], a[2], a[3]);
printf("calloc: %d %d %d %d
", b[0], b[1], b[2], b[3]);
运行结果（malloc 那几个数每次都可能不同）
malloc: 341 47 0 0
calloc: 0 0 0 0

malloc 出来的是「脏」内存，calloc 出来的是全 0。 需要用 0 打底（比如做计数、累加）时，calloc 更省事。

5.2 free：还回去

用完了就还。这一步绝不能不写。

规范写法：free 之后置 NULL复制
int *q = malloc(sizeof(int) * 4);
*q = 7;
printf("用的时候 *q = %d
", *q);

free(q);        /* 还回去 */
q = NULL;         /* 立刻置空，防止以后误用 */

if (q != NULL) {
    printf("还指向旧地址，不能碰
");
} else {
    printf("已经是空指针，可以安全判断
");
}
运行结果
用的时候 *q = 7
free 后 q == NULL 吗？ 1
已经是空指针，可以安全判断
free(NULL) 是安全的

标准规定：free(NULL) 什么也不做，不会出错。 所以「free 后置 NULL」这个习惯不会带来麻烦，反而让 if (p) free(p); 这种写法也安全。

实测：

int *p = NULL;
free(p);      /* 安全，什么都不做 */

运行结果：free(NULL) 没有崩溃，说明它是安全的

5.3 calloc 与 realloc

函数作用要点
malloc(n)申请 n 字节内容不确定
calloc(k, size)申请 k 个、每个 size 字节自动清零；注意参数是「个数 + 单个大小」
realloc(p, n)把已申请的内存改成 n 字节可能搬家，必须接住返回值
realloc 扩容复制
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 3;
    int *p = malloc(sizeof(int) * n);
    for (int i = 0; i < n; i++) p[i] = i + 1;
    printf("扩容前: ");
    for (int i = 0; i < n; i++) printf("%d ", p[i]);
    printf("
");

    /* 想扩到 6 个 —— 用临时变量接住返回值 */
    int n2 = 6;
    int *q = realloc(p, sizeof(int) * n2);
    if (q == NULL) {     /* 失败时原来的 p 还在，不能丢 */
        free(p);
        return 1;
    }
    p = q;                  /* 成功了才把 p 换成新的 */

    for (int i = n; i < n2; i++) p[i] = (i + 1) * 100;
    printf("扩容后: ");
    for (int i = 0; i < n2; i++) printf("%d ", p[i]);
    printf("
");

    free(p);
    return 0;
}
运行结果
扩容前: 1 2 3 
扩容后: 1 2 3 400 500 600
realloc 的三个注意点
  • 老内容会保留（前 3 个还是 1 2 3），新加的部分不确定，要自己赋值。
  • 必须接住返回值。因为空间不够时它会「搬家」到别处， 老地址就失效了。写 realloc(p, n) 而不管返回值， 一旦搬家就可能用上废弃地址。
  • 失败时返回 NULL，但原来的内存还在。 所以要用临时变量接 —— 像上面那样写 int *q = realloc(p, ...)， 失败了还能 free(p)。直接写 p = realloc(p, ...) 一旦失败，原来那块就永远找不回来了（内存泄漏）。

6栈与堆的主要区别

这一节是全讲的重点。把这几个区别记住，用的时候就不会选错。

对比项 栈 堆
谁分配 系统自动（进函数就分） 你调用 malloc 才分
谁回收 系统自动（出函数就收） 你必须调用 free
大小 小，通常 1~8 MB 大，受物理内存限制
大小何时定 编译时定死（写 int a[5]） 运行时随便定（malloc(sizeof(int)*n)）
速度 极快（挪一下指针） 较慢（要查找可用块）
活得多久 只到函数结束 直到你 free，能跨函数
内容 局部变量未初始化时也是脏的 脏的（calloc 才清零）
出错后果 爆栈 → 程序直接崩 忘记 free → 内存泄漏（慢慢变大）
数量限制 受栈空间限制 受总内存限制
选哪个？一句话判断：
大小编译时能写死、且只在函数里用 → 用栈（普通数组）；
大小运行时才知道、或要带回函数外面 → 用堆（malloc）。

一个直观的大小对照

同样是 10 个 int复制
int stackArr[10];                          /* 栈上，自动的 */
int *heapArr = malloc(sizeof(int) * 10);   /* 堆上，要手动 free */

printf("sizeof(stackArr) = %d
", (int)sizeof(stackArr));
printf("sizeof(heapArr)  = %d
", (int)sizeof(heapArr));
free(heapArr);
运行结果
sizeof(stackArr) = 40  （整个数组）
sizeof(heapArr)  = 8  （只是指针）

这是M04讲过的「数组名不是指针变量」在这里的体现： 栈数组的名字知道整个数组多大，而指向堆内存的只是一个指针。

7什么时候真的需要堆

堆虽然灵活，但「要自己 free」这件事本身就是负担。 所以先问自己：真的需要吗？

情况一：长度运行时才知道

这是最常见的理由。用「边读边算」能省掉数组的场合，就别开数组：

不需要数组也能求平均复制
double sum = 0;
int n;
scanf("%d", &n);
for (int i = 0; i < n; i++) {
    int v;
    scanf("%d", &v);
    sum += v;               /* 读完就加，不存 */
}
printf("平均 = %.2f
", n > 0 ? sum / n : 0.0);

但如果需要回头再看（比如倒序输出、排序、找第二大）， 就必须把数都存下来 —— 这时才需要数组，也才可能需要堆。

需要回头再看，用堆复制
int n;
scanf("%d", &n);

int *p = malloc(sizeof(int) * n);
if (p == NULL) return 1;

for (int i = 0; i < n; i++) {
    scanf("%d", &p[i]);
}
printf("倒序输出: ");
for (int i = n - 1; i >= 0; i--) {
    printf("%d ", p[i]);
}
printf("
");
free(p);

情况二：要带回函数外面

M04讲过「不能返回局部数组」。那想让函数造一个数组给外面用，怎么办？ 让它申请堆内存，交给调用者 free。

造一个数组交给调用者复制
#include <stdio.h>
#include <stdlib.h>

/* 造一个 0..n-1 的数组返回；调用者负责 free */
int *makeRange(int n) {
    int *p = malloc(sizeof(int) * n);
    if (p == NULL) return NULL;
    for (int i = 0; i < n; i++) p[i] = i;
    return p;                 /* 堆内存不会随函数消失，可以返回 */
}

int main(void) {
    int *r = makeRange(6);
    if (r != NULL) {
        printf("makeRange(6) = ");
        for (int i = 0; i < 6; i++) printf("%d ", r[i]);
        printf("
");
        free(r);               /* 谁用谁负责还 */
    }
    return 0;
}
运行结果
makeRange(6) = 0 1 2 3 4 5
这里有个「约定」问题

makeRange 申请了内存，却让调用者去 free —— 这是可以的， 但必须在函数说明里写清楚，否则调用者不知道要还，就泄漏了。

所以这类函数的注释很重要，例如：

/* 返回一个新数组，调用者负责 free；失败返回 NULL */
int *makeRange(int n);

8维护内存安全的基本习惯

堆内存的绝大多数问题，都来自不守规矩。 下面六条是入门阶段最该养成的习惯 —— 每一条都对应一类真实故障。

8.1 配对：谁申请谁释放

每一个 malloc / calloc / realloc， 都必须有恰好一次 free 与之对应。

配对示意复制
/* ✅ 好：申请和释放挨得近，一眼能看出配平 */
int *p = malloc(sizeof(int) * n);
if (p == NULL) return;
/* ... 用 p ... */
free(p);
p = NULL;

/* ❌ 坏：申请了却没有任何 free —— 内存泄漏 */
int *q = malloc(sizeof(int) * n);
/* ... 用 q ... */
/* 忘了还！程序运行越久占用越多 */
实用写法：让释放路径唯一

如果函数里有多个 return，很容易漏掉 free。 简单的办法是把申请和释放在同一层缩进里， 中间所有提前退出的分支都先 free 再 return：

int *p = malloc(sizeof(int) * n);
if (p == NULL) return NULL;

if (出错了) { free(p); return NULL; }   /* 先还再退 */

/* 正常用完 */
free(p);
p = NULL;

8.2 释放后立刻置 NULL

free 只是把内存还给了系统，指针变量里的地址还在。 这个指针叫「悬空指针」，再用它就是未定义行为。

对比复制
/* ❌ 危险：free 之后指针还指着那块地方 */
free(p);
printf("%d
", *p);      /* 用了已经归还的内存 */
free(p);                /* 重复释放，可能直接崩 */

/* ✅ 安全：还完就置空 */
free(p);
p = NULL;
if (p != NULL) {
    printf("%d
", *p);  /* 进不来，安全 */
}
free(p);                /* free(NULL) 安全 */
为什么置 NULL 能防住这么多问题
  • 防误用：加一句 if (p != NULL) 就挡住了
  • 防重复释放：第二次 free(NULL) 是安全的
  • 崩溃点前移：万一真去解引用空指针，通常立刻崩在那一行， 而不是「隔了很久在别处莫名崩溃」—— 好查得多

8.3 检查分配是否成功

malloc 有可能失败（内存不够），失败时返回 NULL。 不检查就直接用，是最典型的崩溃原因。

对比复制
/* ❌ 如果 n 很大，p 可能是 NULL，下一行就崩 */
int *p = malloc(sizeof(int) * n);
p[0] = 1;

/* ✅ 先判断再用 */
int *p = malloc(sizeof(int) * n);
if (p == NULL) {
    printf("内存不足
");
    return 1;
}
p[0] = 1;

8.4 不要越界

堆内存也不会替你检查边界。申请了 5 个，写第 6 个就是越界。 越界在堆上尤其危险 —— 它可能悄悄改坏别处的数据， 直到很久以后才以奇怪的方式暴露。

对比复制
int n = 5;
int *p = malloc(sizeof(int) * n);

for (int i = 0; i <= n; i++) p[i] = 0;   /* ❌ i==5 越界 */
for (int i = 0; i <  n; i++) p[i] = 0;   /* ✅ 0..4 */
字符缓冲特别容易少算 1

字符串结尾要留一个位置给 ''。 放 6 个字符要申请 7 字节：

char *s = malloc(sizeof(char) * (6 + 1));   /* +1 给 '' */

实测：申请 5 字节放 "Mong"（4 个字符 + 结束符）正好；
申请 7 字节放 "Mongol"（6 个字符 + 结束符）正好：

运行结果
s = Mong  strlen = 4
t = Mongol  strlen = 6

8.5 不要返回局部数组的地址

这是M04提过的问题，这里给出正确做法。

两种做法对照复制
/* ❌ 错：local 随函数结束而消失，返回的地址悬空 */
int *bad(int n) {
    int local[100];
    for (int i = 0; i < n; i++) local[i] = i;
    return local;
}

/* ✅ 对：用堆，活得比函数久 */
int *good(int n) {
    int *p = malloc(sizeof(int) * n);
    if (p == NULL) return NULL;
    for (int i = 0; i < n; i++) p[i] = i;
    return p;                  /* 记得：调用者要 free */
}

/* ✅ 另一种对：外面传进来一块内存，函数只往里写 */
void fill(int *out, int n) {
    for (int i = 0; i < n; i++) out[i] = i;
}
第二种做法往往更好

「外面传进来，函数只写」这种形式（M04的指针参数）， 把「谁申请」和「谁释放」都留在了调用者手里， 不容易出现「到底该谁 free」的扯皮。很多标准库函数都是这个风格。

8.6 先算清楚要多少字节

申请字节数写错，是新手最常踩的坑。两种情况要分清：

你想要正确写法
n 个 intmalloc(sizeof(int) * n)
n 个 doublemalloc(sizeof(double) * n)
n 个 structmalloc(sizeof(Player) * n)
一个 intmalloc(sizeof(int))
放 6 个字符的字符串malloc(sizeof(char) * (6 + 1))
两个高频错误
  • 忘了乘 n：malloc(sizeof(int)) 只给了 一个 int 的位置，你当地址用了 n 个 → 越界。
  • n 本身算错了：比如 n 是「字符个数」， 却忘了给 '' 多留一格。

习惯：写 sizeof(类型) * 个数 这个形状， 一眼就能看出「申请了几个」。

9常见错误

错误 1 · 内存泄漏（忘了 free）

对比复制
/* ❌ 在循环里反复申请却从不释放 */
for (int i = 0; i < 1000000; i++) {
    int *p = malloc(sizeof(int) * 100);
    /* 用完没 free，每次都漏一点 */
}
/* 结果：内存占用一路涨，最后可能被系统杀掉 */

/* ✅ 每轮用完就还 */
for (int i = 0; i < 1000000; i++) {
    int *p = malloc(sizeof(int) * 100);
    /* ... 用 p ... */
    free(p);
}

泄漏的特点：程序不会立刻崩，只是越来越占内存。 短时间跑的小程序看不出来，长时间运行的服务会因此被拖垮。

错误 2 · 用了已释放的内存

对比复制
free(p);
printf("%d
", p[0]);   /* ❌ 那块内存已经不属于你 */

free(p);
p = NULL;               /* ✅ 置空后就不会误用 */

错误 3 · 重复释放

对比复制
free(p);
free(p);                 /* ❌ 释放两次，可能直接崩 */

free(p);
p = NULL;
free(p);                 /* ✅ free(NULL) 安全，什么也不做 */

错误 4 · 用 realloc 时丢掉原指针

对比复制
/* ❌ 失败时返回 NULL，原来的内存就找不回来了（泄漏） */
p = realloc(p, sizeof(int) * n2);

/* ✅ 用临时变量接，成功了再换 */
int *q = realloc(p, sizeof(int) * n2);
if (q == NULL) {
    free(p);              /* 原来的还在，正常还掉 */
    return 1;
}
p = q;

错误 5 · 申请了却没检查，直接用

对比复制
int *p = malloc(sizeof(int) * n);
p[0] = 1;                /* ❌ n 太大时 p 是 NULL，这里崩 */

int *p = malloc(sizeof(int) * n);
if (p == NULL) return 1;   /* ✅ */
p[0] = 1;

错误 6 · 在栈上开过大的数组

对比复制
/* ❌ 栈通常只有几 MB，这个要 40 MB，直接爆栈 */
int big[10000000];

/* ✅ 大块内存放到堆上 */
int *big = malloc(sizeof(int) * 10000000);
if (big == NULL) return 1;
/* ... */
free(big);

错误 7 · 忘了 #include <stdlib.h>

对比复制
#include <stdio.h>
#include <stdlib.h>      /* ✅ malloc / free 声明在这里 */

少了这个头文件，编译器可能只给个警告，程序却带着错误假定继续跑。

10一页速查

想做的事写法
包含所需头文件#include <stdlib.h>
申请 n 个 intint *p = malloc(sizeof(int) * n);
申请并清零int *p = calloc(n, sizeof(int));
判断是否成功if (p == NULL) { 处理失败 }
当数组用p[i]  或  *(p + i)
扩容int *q = realloc(p, sizeof(int) * n2);
扩容成功后再换指针if (q) p = q; else free(p);
释放free(p);
释放后防误用p = NULL;
字符串缓冲（6 字符）malloc(sizeof(char) * (6 + 1))
全局变量写在所有函数外面
函数间保留值的局部变量static int n = 0;
大块内存用 malloc，不要开大局部数组
本讲要记住的六句话
  1. 静态内存（全局/static）程序全程都在，不用管，但别滥用。
  2. 栈内存（局部变量）进函数分配、出函数回收，又快又省心，但空间小。
  3. 堆内存要先 malloc、后 free， 大小运行时定，能跨函数，但一切自己负责。
  4. 申请和释放必须配对，而且只释放一次。
  5. free 之后立刻 p = NULL —— 一条习惯防住三类错误。
  6. 每次 malloc 都要检查是不是 NULL，不检查就是等着崩。
