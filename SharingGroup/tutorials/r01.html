1为什么排版的人要懂这些

这一篇是背景知识：把字体排版里最常被提到的几个词讲清楚 —— EM Square、基线、上悬线 / 下悬线、大写字高 / x 字高、行高、字重。 看完你能做到两件事：

  • 看懂字体工具（FontForge、Glyphs、FontLab）里那一堆指标的含义；
  • 知道为什么两行字之间会多出空白，以及为什么调了行高有时没反应。

两行字之间空得太开 / 太挤上悬线、下悬线、行高
图标和文字放一起时对不齐基线
换了字体，同样的字号看着却一大一小x 字高、大写字高
蒙文竖排时，「基线」怎么跑到左边去了基线的方向（第 8 节）
本篇的定位

只解决「看到这个词不至于发懵」。真正的字形设计、曲线拟合、 轮廓构造都不在这里 —— 那是另一门手艺。

2EM Square：一切尺寸的尺子

EM Square（也写作 em square、字身框）是字体设计里最基本的单位 —— 可以理解成设计师用的那块正方形画布。所有字形的坐标都画在这块画布上。

三个要点
  1. 它是相对的，不是固定像素。 画布切成多少份由字体自己决定，常见 1000 份（PostScript / CFF 系） 或 2048 份（TrueType 系）。这个份数叫 UPM（Units Per Em，每 em 的单位数）。
  2. 字号就是在设定这块画布有多大。 写 font-size:16px，意思是「把这 1000（或 2048）份铺成 16 像素」—— 所以字形坐标本身没有绝对大小，全靠这一层缩放。
  3. 字形可以冲出画布。 上下悬线常常落在 EM Square 之外 —— 这是正常的，不是设计错误。

用一组数来看就清楚了。假设某字体 UPM = 1000， 设计师把上悬线定在 y = 900、下悬线定在 y = −200：

上下悬线跨度（> 1000）
换算成像素（font-size 16px 时）复制
1 份        = 16 / 1000 = 0.016 px
上悬线高度   = 900  × 0.016 = 14.4 px
下悬线深度   = 200  × 0.016 =  3.2 px
两者相加     = 17.6 px   ← 比 font-size(16px) 还大

最后一行就是关键：上下悬线的跨度经常大于 EM Square。 这正是「为什么行距看着比字号大」的根源之一。

一个容易混的说法

「EM Square」在不同资料里指的东西不完全一样：

  • 有的指 UPM 那块方形画布 —— 最常用的意思，本篇采这个；
  • 有的特指 字母 M 的宽度 —— 铅字时代的原义， 那时 M 占满一个正方形，所以叫 em；
  • 还有的把设计上的 em 方框（可能小于 UPM 网格）单独区分出来。

看到这个词，先看上下文说的是坐标系还是那一块具体的方框， 基本就不会理解错。

3基线：那条看不见的线

基线（Baseline）是所有这些线里唯一必须存在的一条。 它是字形「站上去」的那条线，也是字体的原点（y = 0）。

基线的规则很简单，但几个推论很重要：

规则说明
拉丁字母坐在基线上a o m n x 的底边贴着基线，不越过
升部向上、降部向下b d h k l 向上伸；g p q y 向下沉
汉字也坐在基线上方块字的底边与基线对齐，所以中英混排能排整齐
基线是整行共用的同一行里所有字共用一个基线 —— 这是「一行字」的定义
实用推论：图标和文字对不齐，多半是基线问题

把图标和文字放在同一行，图标默认会坐在基线上，于是看起来「偏低」。 要竖排居中，用 vertical-align: middle， 或者干脆改成 flex 布局加 align-items: center。

4上悬线与下悬线

这两条线管的是「一行字的上下边界」：

Ascender line 上悬线：升部（b d h k l）能达到的最高位置。
Descender line 下悬线：降部（g j p q y）能下沉到的最低位置。
三条线的上下顺序

凡是「向上多少 / 向下多少」，都是相对基线量的，因为基线是 y = 0。 这就是为什么字体文件里 ascender 是正数、descender 是负数。

5大写字高与 x 字高

这两条线在上悬线下面，管的是「常见字母长多高」：

Cap height line 大写字高线：大写字母 A B C H 的顶边。
Mean line 主线：小写字母主体的高度（与下面的中线含义相近）。
Middle line 中线 / x 半高线：x 字高所在的高度。

对照上图的数值，层级关系一眼可见：

同一种字体里的高度对比复制
上悬线距    110px   ← 最高
大写字高     68px   ← 大写 A 到这里
x 字高       49px   ← 小写 x 到这里，只有大写的 72%
下悬线距     54px   ← 向下沉这么多
行高        214px   ← 还要加上下留白，见第 6 节
为什么 x 字高比大写字高更影响观感

一段文字看起来「大不大」，主要由 x 字高决定，而不是大写字母 —— 因为正文里绝大多数是小写字母。

这就是「同样 16px，换字体后看着一大一小」的原因： 两个字体的 x 字高不一样。有些字体（如 Verdana）x 字高特别大， 所以显得比实际字号大。

它们的关系是一个等式：

行高是怎么凑出来的复制
行高 = 上半行距 + 上悬线距 + 下悬线距 + 下半行距
214  =    25    +    110    +    54    +    25
                              ↑
                    110 + 54 = 164  ← 内容高度
                    214 − 164 = 50  ← 多出来的「行距」，上下各分 25
关键概念：上下半行距（half-leading）

字体的「内容高度」（上悬线距 + 下悬线距）通常不等于你设的行高。 多出来的部分被平均分到上下两边，各叫半行距。

所以行高比字号大时，文字并不是「贴底之后往下长」， 而是上下各撑开一点 —— 这就是为什么加大行高后， 第一行文字看起来也往下挪了一点。

实用推论：为什么调行高「没反应」

因为行高管的是行与行之间的距离，管不了「一行字在自己的行盒里怎么放」。 想让单个元素垂直居中，该用 display:flex 加 align-items:center，而不是调行高。

关键：字重不是「加粗」，是「另一套字形」

加粗有两种完全不同的方式：

  • 真字重：字体文件里确实有一套粗体字形，直接取用 —— 效果好；
  • 伪粗体（synthetic bold）：文件里没有，浏览器把细字形整体描粗一圈 —— 笔画会糊在一起，字形结构也走样。

所以一个字体家族包含多少种字重，是衡量它完整度的重要指标。 中文字体尤其明显 —— 一套完整黑体家族常有 6～9 个字重， 这也是中文字体文件动辄几十 MB 的原因。
