1位置形态独立 / 上形 / 中形 / 下形

同一码位在词的不同位置取不同字形，对应竖排的上、中、下与独立成字。 下面用零宽连接符把字形强行逼到指定形态： 字母后面接 ZWJ → 它「右边有人」→ 取上形； 前面接 ZWJ → 取下形；前后都接 → 中形；两侧不接 → 独立形。

2元音组合矩阵8 × 8，行 × 列

行是前一个元音、列是后一个元音，单元格里渲染这一对。 用下面的「上下文」切换，看同一对处在不同位置时是否长出不同字形。 悬停能看到这一对的实际行宽（与两字各自中形的行宽之和比较）—— 那只是线索，不是判据。

3借词辅音阿礼嘎礼字母

鲍培表第二栏的 f k h lh dz ts zh ch sh rh 是借词辅音， 为转写汉语、藏语、梵语借词而设。 其中 zh / ch / sh / rh 四个是「基字 + 下加的 r」（ᠷ U+1837） —— 字形上看就是基字下面再接一笔 r 的转角，依次是 Ƶ 1841、Ç 1842、 Š 1831、Ʒ 183F。 lh 例外，它是「l + 小 h」（U+1840）。 注意别拿预组合的 1841 ZHI／1842 CHI／183F ZRA 当这四个字 —— 它们都比手写稿少了下面那笔 r。

4元音 + 自由变体选择符FVS1–4

同一个元音码位，后接 FVS 可以指定用哪一种字形变体。 词中的 a / e 常常同形，靠的就是这一列区分。 如果某一格的 FVS 自己画出了方框占位符，说明这支字体没有把它当成 变体选择符「吃掉」，而是照常画了字形 —— 那也是需要记录的信息， 换字体时对比一下就知道是不是字体行为。

5连字测试辅音 + 元音，两笔并成一笔了吗

辅音接元音时，字体可能把两笔并成一个字形（连字），也可能只是让两笔各自换个形态。 每格上下两排：上排直接连写，下排用 U+200C 强行断开， 断开后两字各自取独立形，中间留出断口 —— 这一排只是对照物，不参与判定。 判断只看形状：上排如果少了一道笔画的交接、整体是第三种形状， 就是真的合成了一个字形，而不是两笔并排。 悬停看到的是两字中形之和 vs 连写的实测行宽（两个数，不是这一格的），差值为正说明连写更窄。

上下文

下排不是另一个码位，就是把同一对拆成两段分别渲染（各取独立形）， 中间那段间距是页面给的、不是字体的，所以任何一支字体都连不上。 点格子可以打标记。宽度别拿上下两排去量 —— 要量就点悬停给的那两个数。

串 字形序列结论
ᠨᠡᠮᠡᠬᠦ u1828.N.init u1821.A.medi u182E.M.medi u1821.A.medi u182C_u1826.GO.fina 是连字：末两笔 ᠬ + ᠦ 并成一个字形
ᠭᠡᠷ u182D_u1821.GA.init u1837.R.fina 是连字：ᠭ + ᠡ 并成一个字形

怎么用这张表
  • 形态由字体决定：同一串在不同字体里可能给出不同结果， 所以顶部留了字体切换 —— 内置 Noto / 微软 Baiti / 蒙科立 Tig 与 StdEx 各 28 款，共 58 个选项。各家字面高矮差得很远 （Hawang 与 Vyangga 差近一倍），所以按等墨迹高度给了每支一个缩放系数。
  • 蒙科立那 56 款只收 91 个蒙文码位：缺 U+180F(FVS4)、 托忒长元音、锡伯/满文字母与阿礼嘎礼。第 3、4 节里冒出空白格或回退字形 不是页面坏了，是那支字体本身没有这些码位 —— 这本身就是可比的结论。 要完整覆盖请切回 Noto 或 Baiti（两者都是 158/158）。
  • 不确定字形来自哪支字体：点顶栏「校验」当场量一次 —— 同一串蒙文在「目标字体 + 内置」与「只用内置」下宽度不同，才算那支字体接管了； 一次点完还会顺带把 58 支全表自检一遍。没装时浏览器自动回退到内置 Noto， 页面照常工作，所以本页不做预判、也不在选项名后标注「未安装」 （各浏览器探本机字体的行为不一致，预判容易全线误报）。
  • 切了字体但字形没变：最常见的原因是同一族名装了两份 —— 蒙科立这套就装在 HKLM（系统级 8103）和 HKCU（用户级 8102） 两处且同名，Menk Qagan Tig 更是 MQG8103 与 MQG8F02 撞名，浏览器可能两边都匹配不上、直接回退。 先跑 python tools/check_font_name_collisions.py 看撞了哪些， 再用 tools/remove_duplicate_user_fonts.ps1（默认只预演、不加 -Apply 不动手）。 注意 StdEx 那 28 款都没撞名，可以拿它来验证这个猜测。
  • ZWJ / ZWNJ 不占位：U+200D 让两侧连上， U+200C 让两侧断开。它们不出字形，只影响形态选择。
  • 行宽只是线索：连字通常会让推进量变小，但形态变化本身也会改变宽度。 所以这一页不替你判定「有没有合形」，只把宽度差放在悬停提示里。
  • 竖排才是本来的排法：横排按钮只是方便扫读，横排下字形仍是竖式设计的，看着会「躺倒」。
