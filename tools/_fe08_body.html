语言：JS JavaScript 需要 HTML / CSS 基础

这一篇讲什么

前七篇讲的是 HTML 与 CSS —— 它们决定网页长什么样。 这一篇开始讲 JavaScript，它决定网页怎么动。

先说结论，让你放心：JS 的语法比 C / C++ 简单得多。 它是弱类型的、解释执行的 —— 不用写类型，也不用编译。 你已经会的变量、if、for、函数在这里几乎原样能用。

一句话定位

HTML 是骨架，CSS 是外观，JavaScript 是行为。

语言管什么例子
HTML有什么东西一个按钮、一段文字、一张图
CSS它们长什么样按钮是红的、文字 16px、圆角
JS它们做什么点按钮弹出提示、输入框校验、改变颜色

1JS 在网页里干什么

先看它最朴素的样子 —— 只是一段能被浏览器执行的文字：

最小的一段 JS复制
var name = "UME";
console.log("你好，" + name);
在浏览器控制台里看到
你好，UME

就这两行，已经包含了 JS 的两个基本要素：变量和函数调用 —— 和 C / C++ 长得几乎一样，只是 var 后面不用写类型。

JS 能做的事情，大致四类
  1. 响应操作 —— 点击、输入、滚动、按键。
  2. 修改页面 —— 换文字、换颜色、显示/隐藏元素。
  3. 和服务器通信 —— 不用刷新页面就取回数据。
  4. 算东西 —— 校验表单、格式化数字、处理数组。

2弱类型：不用写类型

这是 JS 比 C / C++ 简单的第一个原因。看两段等价的代码：

同一件事：声明几个变量复制
// C / C++ —— 每个变量都要写明类型
int    age  = 20;
double pi   = 3.14;
char   ch   = 'A';
bool   ok   = true;

// JavaScript —— 一个 var 全搞定
var age  = 20;
var pi   = 3.14;
var ch   = 'A';
var ok   = true;
「弱类型」是什么意思

变量的类型由它当前存的值决定，不由声明决定。 var 自己看右边是什么就存什么。

更关键的是：同一个变量可以先后装不同类型的东西 —— 在 C++ 里这是编译错误，在 JS 里完全合法。

同一个变量，三种类型复制
var x = 1;            // 现在是数字
x = "hello";          // 改成字符串 —— 合法
x = true;             // 再改成布尔 —— 也合法

// typeof 可以问它「现在是什么」
console.log(typeof x);    // "boolean"
输出
boolean

弱类型带来的方便与代价

方便 少写一大堆类型声明。写个小脚本、调个页面， 不用先想清楚「这个到底该是 int 还是 long」
方便 不用管类型转换的细节 —— 需要的时候 JS 自己转
代价 编译器不再帮你检查类型错误。 C++ 里 1 + "2" 直接编译不过，JS 里它会给出一个 你意想不到的结果，而且不报错
代价的具体样子
弱类型最容易踩的两个坑复制
console.log(1 + "2");    // "12"  —— 字符串拼接，不是加法
console.log(1 == "1");   // true  —— 只比值，不比较类型
console.log(1 === "1");  // false —— 全等：值和类型都要一样

所以有一条规矩要一开始就养成：比较一律用 ===， 不用 ==。（第 7 节还会再讲一次。）

还有一件事：JS 没有指针

C / C++ 里最难的 &、*、内存管理， JS 里全都没有。你拿不到变量的地址，也不用手动释放内存 —— 浏览器会自己回收不再使用的对象。

这是「语法更简单」里省掉的最大一块。

3console.log：JS 的 printf

这是 JS 比 C / C++ 简单的第二个原因：它不需要编译。

两种语言从代码到运行，路径完全不同
步骤C / C++JavaScript
①写代码写代码
②编译（还要链接） — 没有这一步 —
③生成 .exe，再运行 浏览器直接读源码执行
④改了要重新编译 改了刷新一下就行

所以你的开发循环从「改 → 编译 → 运行 → 看」缩短成了 「改 → 刷新 → 看」。

解释执行还有一个表现：错误是「跑到那一行才报」

没跑到就不报错复制
console.log("第一行没问题");

// 下面这行的变量名拼错了（应该是 userName）
console.log(userNmae);

console.log("这行不会执行");
控制台里的结果
第一行没问题
Uncaught ReferenceError: userNmae is not defined
    at demo.js:4
前面照常执行 出错之前的代码已经跑完了 —— 不像 C++ 在编译期就拦下来
出错后面的不执行 当前这段脚本从出错那一行起停下，后面的语句不再运行
给出文件名和行号 报错里带 at 文件:行号， 这是排查问题的第一手线索
所以第一件事是学会看控制台

按 F12（或右键 → 检查），切到 Console 面板。 页面「没反应」的时候，先看这里有没有红字 —— 十有八九问题就写在上面。

4解释性：改完刷新就见效

前面一直在用 console.log。这一节专门讲它，因为 它是你以后最常用的一个函数。

等价关系

调试页面时，console.log() 就是 JS 里的 printf()。 作用完全对等 —— 都是「把值打出来，让我看看现在是什么」。

你想做的事C / C++JS
看一个变量的值printf("%d", x); console.log(x);
看一段文字printf("hello"); console.log("hello");
看多个值printf("%d %d", a, b); console.log(a, b);
确认「跑到这里了」printf("here\n"); console.log("here");

最大的区别：printf 要写格式符（%d、%s） 还得自己加 \n；console.log 直接给什么就打什么，多个值用逗号隔开，而且自动换行。

console.log 的各种用法复制
// 打印一个值
console.log("hello");

// 打印多个值（自动用空格隔开）—— 相当于 printf("%d %d", a, b)
console.log("x =", 10, "y =", 20);

// 打印变量
var name = "UME";
console.log(name);

// 打印算式结果
console.log(1 + 2);

// 打印对象和数组（在控制台里可以点开看）
console.log({ a: 1, b: 2 });
console.log([1, 2, 3]);
控制台里的输出
hello
x = 10 y = 20
UME
3
{a: 1, b: 2}
[1, 2, 3]
为什么调试不要用 alert

alert() 会打断页面、必须点确定才能继续， 而且只能显示一段文字、不能打印对象。

调试一律用 console.log：不打断、能打印对象、能看历史记录。 alert 只适合「确认脚本有没有跑起来」这种一次性的检查 （第 9 节会讲）。

console 还有别的成员

常用的还有 console.warn()（黄色警告）、 console.error()（红色错误）、 console.table()（把数组/对象打成表格）。

5三种放进网页的方式

写完的 JS 得让浏览器知道去哪找。有三种放法。

① 行内（写在标签属性里）

行内写法复制
<button onclick="alert('你好')">点我</button>

最短，但不好维护：行为和结构混在一起。适合「就试一下」的场合。

② 内联（写在 <script> 里）

内联写法复制
<body>
  <button id="btn">点我</button>

  <script>
    console.log("脚本跑起来了");
    // 后面第 10 节会在这个位置操作那个按钮
  </script>
</body>

③ 外联（单独的 .js 文件）—— 推荐

外联写法复制
<!-- 在 HTML 里引进来 -->
<script src="demo.js"></script>
三种方式怎么选
方式用在哪说明
行内 onclick试一下、临时演示别用在正式代码里
内联 <script>只有这一页用的短脚本 本教程前几篇的示例用这种
外联 .js正式项目 能被浏览器缓存、能被多个页面共用

和我们前面讲 CSS 时的结论一模一样：能外联就外联。 第 10 节就给一个完整的三文件项目。

脚本放的位置会影响你能不能拿到元素

浏览器是从上往下执行的。如果脚本写在 <head> 里， 而此时 <body> 还没被解析，那么 document.getElementById("btn") 会返回 null —— 因为那个按钮还不存在。

最省心的做法：把 <script> 放在 </body> 之前， 此时页面上所有元素都已就绪。

6JS 与 C / C++ 像在哪

这是「语法更简单」的具体体现：你已经会的写法，大部分原样可用。

运算符与表达式

运算符：一模一样复制
var a = 7, b = 3;

a + b     // 10
a - b     // 4
a * b     // 21
a / b     // 2.333…  —— 注意：不是整除
a % b     // 1

a++;   a--;              // 自增自减
a += 5;   a *= 2;        // 复合赋值

a > b    a <= b    a != b          // 比较
a > 0 && b > 0    !(a > 0)        // 逻辑

这些运算符的优先级和结合性也和 C / C++ 一致， 所以你在 C++ 里养成的直觉可以直接用。

if / else

分支：连大括号的位置都一样复制
var score = 85;

if (score >= 90) {
  console.log("优");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
输出
及格

for 与 while

循环：基本一样复制
for (var i = 0; i < 5; i++) {
  console.log(i);
}

var n = 3;
while (n > 0) {
  console.log(n);
  n--;
}
输出
0
1
2
3
4
3
2
1

函数

函数：两种写法都对复制
// 写法一：和 C / C++ 最像 —— 只是参数也不用写类型
function add(a, b) {
  return a + b;
}

// 写法二：函数也是一种值，可以装进变量
var sub = function (a, b) {
  return a - b;
};

console.log(add(3, 4));   // 7
console.log(sub(3, 4));   // -1
输出
7
-1

注意 C++ 的 int add(int a, int b) 在 JS 里 只剩 function add(a, b) —— 返回类型和参数类型都不用写。

数组

数组：下标从 0 开始，一样复制
var nums = [10, 20, 30, 40];

console.log(nums[0]);          // 10
console.log(nums.length);      // 4
nums[1] = 99;                  // 直接改

for (var i = 0; i < nums.length; i++) {
  console.log(nums[i]);
}
相似性小结
你在 C / C++ 里学的JS 里怎么写
变量声明var x = 1;  （省掉类型）
算术 / 比较 / 逻辑运算符完全一样
if / else if / else完全一样
for / while完全一样
函数（参数、返回值）function f(a, b) { return …; }
数组与下标一样，下标从 0 开始
代码块用 { }一样
语句以 ; 结尾一样（但 JS 里可以省，不推荐省）
注释 // 与 /* */一样

结论：语法层面你几乎没有新东西要学， 而且每一处都少写一点（类型、返回类型、格式符）。

7和 C / C++ 不一样的地方

相似的地方很多，但有几处必须改掉 C++ 的习惯。

① 相等：用 === 而不是 ==

第 2 节已经提过，这里说清原因。

== 会偷偷转换类型复制
1 == "1"              // true   == 先把两边转成同一类型再比
1 === "1"             // false  === 值和类型都要一样

0 == ""               // true
0 == false            // true
null == undefined      // true
这一条记死

比较一律用 === 和 !==， 永远不用 == 和 !=。

在 C++ 里 == 就是「相等」，很安全； 在 JS 里 == 带着一堆隐式转换规则，是 bug 的常见来源。

② 加号 + 有两种意思

+ 是加法还是拼接，看两边是什么复制
1 + 2          // 3     两个数字 → 加法
"a" + "b"      // "ab"  两个字符串 → 拼接
1 + "2"        // "12"  只要有一个是字符串 → 拼接！
"3" - 1        // 2     减号没有拼接含义，会转成数字
"3" * "4"      // 12    乘号同理

这是弱类型的直接后果：同一个运算符，结果由操作数的类型决定。 第 9 节的 prompt 就会踩到这个坑。

③ 没有指针，也没有手动内存管理

JS 里拿不到变量的地址。对象默认就是「引用语义」， 但你看不见也管不了那个引用 —— 没有 &，也没有 *。

对象是引用、基本类型是值复制
var a = { n: 1 };
var b = a;          // b 和 a 指向同一个对象

b.n = 99;
console.log(a.n);     // 99 —— a 也变了

// 但数字、字符串是「值」语义
var p = 1, q = p;
q = 99;
console.log(p);       // 1 —— 没变
输出
99
1

这个区别和 C++ 里「传对象引用会改到本体、传 int 不会」 是同一个道理 —— 只是 JS 不让你选，它按类型自动决定。

④ 数组不是固定长度的

数组：想加就加复制
var arr = [1, 2, 3];

arr.push(4);            // 末尾追加 → [1, 2, 3, 4]
arr.pop();              // 删掉末尾 → [1, 2, 3]
arr.unshift(0);         // 开头插入 → [0, 1, 2, 3]

console.log(arr.length);   // 4

没有 sizeof，也没有「容量」的概念 —— 长度随时可变。

8var / let / const

JS 里声明变量有三种写法。这一节说清它们的区别。

var 会「漏」出代码块复制
if (true) {
  var leaked = "我漏出来了";
}
console.log(leaked);     // "我漏出来了" —— var 不受 { } 限制

if (true) {
  let scoped = "我出不去";
}
// console.log(scoped);   ← 报错：scoped is not defined
三种声明怎么选
写法作用域什么时候用
var函数作用域，会漏出 { } 老代码里到处都是；新代码别再用
let块作用域，和 C++ 一样 需要改变的变量
const块作用域，且不能重新赋值 默认就写 const，确实要改时再换 let

本教程为了和旧代码接轨，示例里用 var； 你自己写新代码时，优先 const，其次 let。

const 不能重新赋值

const 锁的是变量，不是内容复制
const PI = 3.14;
// PI = 3.15;      ← 报错：Assignment to constant variable.

const arr = [1, 2, 3];
arr.push(4);            // 合法！arr 仍然指向同一个数组
// arr = [9];           ← 报错：不能让它指向别的数组

console.log(arr);       // [1, 2, 3, 4]
这一点和 C++ 的 const 不同

C++ 里 const std::vector<int> v 之后， v.push_back() 是编译错误 —— const 会传到对象内部。

JS 里 const arr = [] 只保证变量不重新赋值， 不影响对象内容。想冻结内容要用 Object.freeze()。

9alert 与 prompt

这两个是浏览器提供的「弹窗」函数。它们很土，但写一行就能看到效果 —— 适合拿来确认「我的脚本真的跑起来了」。

alert：只显示，不返回东西

alert 的用法复制
<script>
  alert("脚本跑起来了");

  var n = 3;
  alert("n 的值是 " + n);

  // 换行用 \n —— 和 printf 一样
  alert("第一行\n第二行");
</script>
alert 会「卡住」页面

弹出期间，整个页面停止响应 —— 后面的代码不会执行，动画也停。 所以它只适合调试，正式项目里不要用。

prompt：向用户要一个输入

输入 → 处理 → 输出复制
<script>
  var name = prompt("你叫什么名字？");
  alert("你好，" + name);
</script>
prompt 的返回值：三种情况
用户动作返回什么
输入了内容，点「确定」"UME"  （字符串）
什么都没输入，点「确定」""  （空字符串）
点「取消」或按 Escnull
最容易踩的坑：prompt 返回的永远是字符串

即使用户输入 7，拿到的也是字符串 "7"。

于是 input + 1 会得到 "71"（拼接），不是 8。 必须先 Number(input) 转一下。

这正是第 7 节「+ 有两种意思」在现实里的后果。

完整例子：判断 + 类型转换复制
<script>
  var input = prompt("请输入一个数字：");

  // ① 判断用户有没有取消
  if (input === null) {
    alert("你取消了");
  } else {
    // ② prompt 返回的是字符串，做算术要先转数字
    var n = Number(input);

    // ③ NaN = Not a Number，用来判断转成功没有
    if (isNaN(n)) {
      alert("这不是一个数字");
    } else {
      alert("它的两倍是 " + (n * 2));
    }
  }
</script>

串起来：猜数字

猜数字（约 20 行）复制
<script>
  var secret = 42;
  var tries  = 0;

  while (true) {
    var raw = prompt("猜一个 1~100 的数字：");
    if (raw === null) { alert("放弃了？"); break; }

    var g = Number(raw);
    if (isNaN(g)) { alert("请输入数字"); continue; }

    tries++;

    if (g > secret)      alert("大了");
    else if (g < secret) alert("小了");
    else {
      alert("猜对了！用了 " + tries + " 次");
      break;
    }
  }
</script>

这一段里 while、if / else、break、 continue、变量自增全是你已经会的写法。 新的只有 prompt / alert / Number / isNaN 这几个名字。

文件三：demo.js

这个脚本做三件事，正好把这一篇的东西串一遍： 打印日志、改页面上的文字和样式、响应按钮点击。

demo.js复制
// ① 先确认脚本加载成功 —— console.log 就是 JS 的 printf
console.log("demo.js 已加载");

// ② 找到页面上那两个元素
var msg = document.getElementById("msg");
var btn = document.getElementById("btn");

// ③ 页面一打开，就改掉那段文字和它的颜色
msg.textContent = "这行字已经被 JS 改过了";
msg.style.color = "#7c3aed";

// ④ 给按钮绑一个点击动作
var count = 0;

btn.onclick = function () {
  count++;
  msg.textContent = "你点了 " + count + " 次";
  console.log("点击次数：", count);
};

现象说明
标题是紫色的demo.css 加载成功
文字是「被 JS 改过了」demo.js 加载成功
控制台有「demo.js 已加载」脚本确实跑到了第一行
点按钮数字在涨事件绑定成功，变量能累加
如果没效果，按这个顺序查
  1. 先看控制台有没有红字。报错会写清楚是哪个文件的第几行。
  2. 确认三个文件在同一个目录下，而且文件名拼写完全一致 （是 demo.js 不是 Demo.js； Windows 不区分大小写，但传到服务器就会出问题）。
  3. 确认 <link> 和 <script> 的路径对： 同目录下直接写文件名即可，不要写成 C:\… 这样的绝对路径。
  4. 确认 <script> 在 </body> 之前。 放到 <head> 里会因为按钮还不存在而失败。
  5. 改完记得保存文件再刷新浏览器。
这个结构就是真实项目的样子

JS 比 C / C++ 简单在哪

特点含义
弱类型不用写类型；同一个变量可以先后装不同类型
解释性不用编译，改完刷新就见效；错误在跑到那一行时才报
没有指针没有 & 和 *，也不用手动释放内存
语法接近 Cif / for / while / function / 运算符 / 注释都一样

项目C / C++JS

函数作用

五句话记住这一篇：
① HTML 骨架、CSS 外观、JS 行为 —— 三者分工不同。
② JS 是弱类型的 —— 不用写类型，但也就没有编译期类型检查， 所以比较一律用 ===。
③ JS 是解释性的 —— 不用编译，改完刷新就见效； 出错在跑到那一行时才报，所以第一件事是学会看控制台。
④ 语法比 C / C++ 简单 —— 运算符、if、for、函数、数组都能直接迁移， 而且没有指针、不用管内存。
⑤ console.log 就是 JS 的 printf； 把它和 alert / prompt 用熟， 再把第 10 节那三个文件跑通，就可以往下走了。
