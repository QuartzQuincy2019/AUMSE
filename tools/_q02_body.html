上一篇（Q01）讲的是 ::。这一篇讲另一个你很快就会到处遇到的符号： 一个 &。

它在 Qt 里出现的频率几乎和 :: 一样高 —— 你随手翻一段 Qt 代码，函数参数里全是 const QString &name 这种写法。学会读它，很多「为什么这么写」的疑问会一起消失。

这一篇的定位

M04《指针初步》已经把指针讲透了。这一篇只讲引用， 指针只在一个地方出场：第 3 节做对比，和第 8 节看底层实现。 没有读过 M04 也能看懂，但要真正吃透，建议先过一遍 M04。

一句话

引用 = 给已经存在的变量起第二个名字。

没有新变量、没有新内存，只是又多了一个称呼它的方式。 所以 C++ 里管引用叫 alias（别名）。

1引用是什么：给变量起别名

先看最简单的写法。& 加在类型后面，表示「引用类型」：

ref1.cpp —— 第一个引用复制
#include <iostream>

int main() {
    int x = 10;

    int& r = x;        // r 是 x 的引用（另一个名字）

    r = 20;              // 改 r —— 其实就是改 x
    std::cout << "x = " << x << "\n";
    std::cout << "r = " << r << "\n";

    std::cout << "&x = " << &x << "\n";
    std::cout << "&r = " << &r << "\n";
}
输出
x = 20
r = 20
&x = 0x7ffd3f2a1b4c
&r = 0x7ffd3f2a1b4c      ← 和 &x 完全一样

最后两行是关键：取 x 的地址和取 r 的地址，结果一模一样。 因为 r 根本不是变量 —— 它只是 x 的另一个名字。

int x = 10; 内存里开一块地方，名字叫 x，里面放 10
int& r = x; 没有开新地方。r 是x 的别名 —— 同一块内存，两个名字
r = 20; 通过 r 找到那块内存，写入 20。所以 x 也变成 20
把引用想成「外号」。 一个人可以有大名和小名，但只有一个人。 叫小名让他做事，和叫大名让他做事，是同一件事。

2三条铁律：必须初始化、不能改绑、不能为空

引用只有三条规则，但每一条都对应一类常见错误。

铁律
  1. 声明时必须初始化。不存在「先声明、以后再绑定」的引用。
  2. 一旦绑定，不能改绑到别的变量。之后所有对它的赋值，都是改它绑定的那个变量。
  3. 没有「空引用」。引用一定指着某个真实存在的对象。

① 必须初始化

ref2.cpp —— 不初始化就编译不过复制
int x = 10;

int& a;          // ✗ 编译错误：declared as a reference but not initialized
int& b = x;       // ✓ 必须像这样一开始就指定绑谁
编译器报错
error: 'a' declared as reference but not initialized
    int& a;
         ^

② 不能改绑 —— 最容易误会的一条

下面这段代码看起来像「把 r 改成绑定 y」，实际完全不是：

ref3.cpp —— 赋值 ≠ 改绑复制
int x = 10, y = 99;

int& r = x;
r = y;                  // ✗ 这不是「让 r 改绑 y」
                        // ✓ 而是「把 y 的值 99 赋给 r 所指的 x」

std::cout << "x = " << x << "\n";   // 99（被改了）
std::cout << "y = " << y << "\n";   // 99（没动）
std::cout << "&r == &x ? " << (&r == &x) << "\n";   // 1（仍绑着 x）
输出
x = 99
y = 99
&r == &x ? 1
这是初学者最常踩的坑

r = y; 里的 = 不是「绑定」的意思，是「赋值」的意思。

引用一旦绑好，任何操作都是作用在它绑定的那个对象上 —— 包括 =。所以这一行等价于 x = y;。

想「换一个目标」，引用做不到 —— 那是指针的活（p = &y;）。

③ 没有空引用

引用一定指着真实对象，所以用引用时不需要检查「它是不是空的」。 这是引用比指针省心的地方：

ref4.cpp —— 指针要查空，引用不用复制
// 用指针：调用者可能传 nullptr，你必须防
void printPtr(const std::string* s) {
    if (!s) return;                 // ← 这一句不能省
    std::cout << *s << "\n";
}

// 用引用：一定指向某个真实对象，不需要查
void printRef(const std::string& s) {
    std::cout << s << "\n";         // ← 直接就是对象本身
}
注意
printPtr 里要写 *s —— 因为 s 是「地址」，得解引用才拿到对象
printRef 里直接写 s —— 因为 s 就是那个对象本身（只是换了个名字）

3与指针的关系（一）：语法上的区别

这一节回答最常被问的问题：引用和指针到底差在哪？ 先看语法，第 8 节再看底层。

对比项指针 T* 引用 T&
是什么一个变量，里面存着地址一个别名，不是变量
必须初始化不必须
int* p; 合法		 必须
int& r; 编译错
能否为空可以（nullptr）不可以
能否改指向可以 p = &y;不可以
访问目标要解引用 *p直接用 r

选哪个？先问一句：这个东西可能「不存在」吗？
可能不存在（比如查找失败）→ 用指针，返回 nullptr；
一定存在 → 用引用，语法干净，调用者也不用查空。

4与指针的关系（二）：它们常常一起出现

虽然语法不同，两者并不是对立的。有三处「接口」在它们之间来回转换：

引用 → 指针 int* p = &r; —— 对引用取地址，得到它绑定对象的地址
指针 → 引用 int& r = *p; —— 解引用指针，得到对象的引用（前提：p 不是空）
函数传参 形参写引用，实参可以直接传对象；写指针就得显式传 &x
第二行是危险动作

int& r = *p; 在 p == nullptr 时是未定义行为。 编译器不一定报错，程序可能「看起来正常」跑很久。

所以「指针转引用」只在你刚刚确认过非空的紧邻位置才安全。 这也是为什么很多老代码宁可在函数里继续用指针。

反过来「引用转指针」是绝对安全的：引用一定绑着真实对象，所以 &r 一定有效。

5函数参数里的引用：Qt 里遍地都是

这是引用最重要的用途，也是你在 Qt 代码里看到它的主要原因。

三种传参方式对比

param.cpp —— 值传递 vs 引用 vs const 引用复制
#include <iostream>
#include <string>

// ① 值传递：把整个字符串【复制】一份给函数
void byValue(std::string s) { s += "!"; }        // 改的是副本

// ② 引用传递：不复制，直接操作调用者的那个对象
void byRef(std::string& s)  { s += "!"; }        // 改的就是原对象

// ③ const 引用：不复制，也不许改
void byCRef(const std::string& s) {
    std::cout << s.size() << "\n";                // 只读
    // s += "!";   ← 取消注释会编译错
}

int main() {
    std::string a = "UME", b = "UME", c = "UME";
    byValue(a); byRef(b); byCRef(c);
    std::cout << a << " " << b << " " << c << "\n";
}
输出
3
UME UME! UME

结果说明：a 没变（改的是副本）、b 变了、c 没变（只读了它的长度）。

选哪种？一张表定下来
你想要的效果怎么写
只读，且类型很小（int、double、指针） T v
只读，且类型较大（std::string、QString、容器） const T& v  ← Qt 里最常见
要修改调用者的对象T& v
可以接受「没有」，或要重新指向别处T* v
为什么 Qt 的函数几乎都写 const QString&

两个理由叠在一起：

  • 不复制：QString 内部是隐式共享的，但传值仍要维护引用计数， 传 const& 连这个都省了；
  • 不修改：const 让编译器帮你保证这个参数在函数里不会被改。

所以 void setWindowTitle(const QString &title) 读作：「我要用你的字符串，但不会改它，也不会拷一份」。

Qt 里真实的样子

Qt 的签名为什么这么写
void setWindowTitle(const QString &title)只读、不复制
void append(const QString &str)只读、不复制
QString &operator+=(const QString &other)返回引用，好让 a += b += c 连起来
QString &operator[](int i)返回引用，于是 s[i] = 'x' 能直接改到内容
connect(..., const QObject *receiver, ...)接收者可以为空 → 用指针
void mousePressEvent(QMouseEvent *event)历史原因 + 事件对象可空，Qt 用指针
注意最后两行：Qt 不是「一律用引用」

Qt 的老接口（尤其事件、connect）大量用指针， 因为它们诞生于「可能为空」的语义。新一些的接口（getter/setter）则普遍用 const T&。

看到参数是 *，先想「它可能是空的吗」； 看到 &，就可以放心直接用。

6作为返回值：一个必须知道的陷阱

函数也可以返回引用。这么做有明确的目的，但用错了会导致悬空引用。

ret.cpp —— 返回引用改到原对象复制
#include <iostream>
#include <vector>

std::vector<int> v{1, 2, 3};

// 返回引用：调用者拿到的是容器里那个元素的【别名】
int& at(int i) { return v[i]; }

int main() {
    at(1) = 99;                       // 直接改到容器里
    std::cout << v[0] << " " << v[1] << " " << v[2] << "\n";
}
输出
1 99 3

at(1) = 99; 能编译通过，正是因为 at(1) 返回的是引用 （v[1] 的别名），而不是一个临时副本。这也是 std::vector::operator[] 能赋值的原因。

陷阱：绝不要返回局部变量的引用

局部变量在函数返回时就销毁了，返回它的引用 = 返回一块已经失效的内存。

悬空引用复制
int& bad() {
    int local = 42;
    return local;      // ✗ local 在函数返回时已经死了
}

int& r = bad();       // r 指向已销毁的内存 —— 未定义行为
std::cout << r;        // 可能打印 42，也可能打印垃圾

这类错误编译不一定报错（好编译器会给 warning）， 运行时也可能「碰巧正常」，是典型的难查 bug。

安全的做法：函数里创建的东西，按值返回（int 而不是 int&）。

7const 引用：只读的那把锁

const T& 是引用里出现最多的一种组合，值得单独说清楚它到底锁住了什么。

const int& r = x; 锁的是「通过 r 修改」这条路

它不意味着 x 不能被改，只意味着不能通过 r 去改：

const 只锁一条路复制
int x = 10;
const int& r = x;

// r = 20;   ✗ 编译错：不能通过 r 改
x = 20;      // ✓ 可以：x 自己不是 const

std::cout << r;   // 20 —— r 看到的是最新的值

另外两个常见用途：

绑定临时对象 const std::string& s = "hello"; —— 普通引用绑不了临时值，const 引用可以（编译器会延长它的生命期）
接住任意类型 const auto& x = expr; —— 不复制、也不怕 expr 是个临时值，是很常用的写法
constref.cpp —— 两个常见写法复制
// ① 绑定临时值：普通引用不行，const 引用可以
// std::string& bad = "hi";        ✗ 编译错
const std::string& ok = "hi";    // ✓

// ② const auto&：范围 for 里最省事的写法
std::vector<std::string> names{"A", "BB", "CCC"};
for (const auto& n : names) {
    std::cout << n.size() << " ";      // 不复制每个元素
}
输出
1 2 3
范围 for 里的三种写法
写法含义
for (auto n : v)每个元素复制一份 —— 元素大就慢
for (const auto& n : v)不复制、不能改 —— 只读遍历首选
for (auto& n : v)不复制、可以改 —— 要修改元素时用

8底层：引用通常就是指针

前面说「引用不是变量、不占内存」。这句话在语法层面完全正确， 但在实现层面要补一句：

编译之后，引用基本就是指针

编译器实现引用最常见的做法，就是在底层用一个指针， 然后在你每次写 r 的地方自动替你解引用。

也就是说：int& r = x; r = 20; 在机器码层面很可能是 int* const r = &x; *r = 20;。

x 的地址
x
10 → 20
r 的地址（若真的分配了）
r
存着 x 的地址

但要注意三件事，别把这个类比用过头：

说法是否准确
引用在语法上是别名，不是对象✅ 准确。所以 sizeof(r) 是目标类型的大小， 不是指针大小
引用在实现上通常用指针做✅ 通常如此，但标准不保证， 编译器完全可以优化掉
「引用就是一个自动解引用的指针」⚠ 作为理解工具很好用， 但别拿它解释语法（比如「引用不能改绑」用指针就解释不通）
「引用一定占 8 字节」❌ 错。成员引用可能占空间， 但局部引用经常被完全优化掉
那为什么还要有引用？

因为语法更安全、更干净。用引用的话：

  • 不可能忘记初始化（编译期强制）；
  • 不可能为空，函数里不用写一堆 if (!p) return;；
  • 调用处不用写 &，读起来更像「传了对象本身」；
  • 不会手滑写成 p + 1 这类指针算术。

换句话说：引用是把「一定有效」这件事交给编译器去保证的指针。

9常见错误

写法 / 想法问题
int& r;引用必须初始化，编译错
r = y; 想「改绑」那是赋值：把 y 的值写进 r 绑定的对象
int& r = *p; 且 p 可能为空未定义行为；先确认非空
返回局部变量的引用悬空引用；按值返回
用引用当「可空的参数」表达不了「没有」；这种情况该用指针
给大对象写 T v 传参每次调用都复制一份；改 const T& v
给 int 也写 const int&不算错，但没收益（int 就 4 字节，复制更便宜）
for (auto n : v) 改 n改的是副本，原容器没变；要改写 auto&
以为 sizeof(r) 是指针大小是目标类型的大小（引用不是对象）

10一页速查

写法读作用途
int& r = x;r 是 x 的别名给变量起第二个名字
T& v传进来的是你的对象要修改调用者的对象
const T& v只读，且不复制大对象只读传参 —— Qt 里最常见
T& f()返回的是别名让 f() = x 或 v[i] = x 成立

三句话记住引用：
① 引用是别名，不是变量 —— 不占地方、不用解引用、改它就是改本体。
② 必须初始化、不能改绑、不能为空 —— 三条铁律，违反了就是编译错或未定义行为。
③ 底层通常是指针，语法上是「一定有效的指针」 —— 所以「可能不存在」就用指针，「一定存在」就用引用。
