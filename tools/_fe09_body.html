JS

FE-08 说 JS 是「控制网页行为」的。这一篇就来真的动一下页面 —— 用 JS 造出新的元素，放进页面里。

要用的只有三个函数。学会了它们，你就能让页面「长」出东西来。

三个函数，一句话分工
函数干什么
document.getElementById(id) 按 id 找到页面上已有的一个元素
document.createElement(tag) 造一个还没有放进页面的新元素
父元素.append(子元素) 把子元素放进父元素里（这时才看得见）

顺序正好是：找到父元素 → 造出子元素 → 放进去。

前置

FE-08 讲过的 var、函数、字符串拼接这一篇会直接用。 示例都在浏览器里跑过，输出是实际结果。

1先建立直觉：DOM 树

浏览器读到 demo.html 之后，不是把文字原样记住就完了 —— 它把每个标签变成一个对象，并按嵌套关系连起来。

demo.html复制
<body>
  <h1>角色面板</h1>
  <div id="panel">
    <p>忘情牛肉面</p>
  </div>
</body>

浏览器心里的结构是这样一棵树：

body
├─ h1「角色面板」
└─ div id="panel"
├─ p「忘情牛肉面」
└─ （panel 里还能再放东西）

每个方框叫一个节点，方框之间的连线是父子关系。 这套结构就叫 DOM 树（Document Object Model）。

树上有什么说明
标签 body、div、p —— 对应 HTML 里写的标签
纯文字 「角色面板」也是一个节点（文字节点）， 它没有标签，是某个标签的孩子
在 JS 里怎么拿 每一个节点都是一个 JS 对象，可以读写它的属性 （textContent、id、className …）
为什么叫「树」

因为每个节点最多只有一个父节点，但可以有任意多个子节点 —— 从 body 往下画，就像树根长出枝和叶，不会有环。

这条规则带来一个很实用的结论：任何元素都有一个 parent， 所以「往某个元素里加东西」永远是有意义的操作。这正是下面要讲的核心。

2getElementById：把元素拿在手里

想在 JS 里操作一个元素，先得拿到它。最直接的方式是按 id 找：

getById.js复制
// HTML 里：<div id="panel"></div>

var panel = document.getElementById("panel");

console.log(panel);              // <div id="panel"></div>
console.log(panel.tagName);      // "DIV"  —— 注意是大写
console.log(panel.childNodes.length);  // 0  —— 现在是空的
控制台输出
<div id="panel"></div>
DIV
0
两个必须知道的细节
  1. 找不到就返回 null，不报错。 所以拿到之后要用 if (panel) 判一下，否则后面一用就崩。
  2. id 区分大小写。getElementById("Panel") 找不到 id="panel" 的那个元素。
忘记判空的后果复制
// ❌ 页面上没有 id="nope" 的元素
var x = document.getElementById("nope");
console.log(x);            // null
x.append("文字");          // 💥 TypeError: Cannot read properties of null

// ✅ 先判一下
var y = document.getElementById("nope");
if (y) {
    y.append("文字");
} else {
    console.log("没找到这个 id");
}
控制台输出
null
没找到这个 id

3createElement：凭空造一个元素

document.createElement("标签名") 造出一个新元素。

create.js复制
var p = document.createElement("p");

console.log(p.tagName);        // "P"
console.log(p.isConnected);    // false —— 造出来了，但**还不在页面上**

p.textContent = "忘情牛肉面";   // 往里填文字
p.id = "heroName";              // 给它一个 id
p.className = "name big";       // 给它类名（可多个，空格隔开）

console.log(p.textContent);    // "忘情牛肉面"
控制台输出
P
false
忘情牛肉面
最容易忽略的一点：造出来 ≠ 显示出来

createElement 造出的元素只活在内存里 —— isConnected 是 false，屏幕上什么都没有。

填文字、设 id、加类名，随便怎么改，只要没放进去，页面上就看不见。 要显示，必须做下一步：append。

顺手说：textContent 是安全的

把尖括号写进 textContent，它当纯文字显示，不会变成标签：

p.textContent = "<b>不是标签</b>";
console.log(p.textContent);   // "<b>不是标签</b>"
console.log(p.querySelector("b"));   // null —— 里面没有 b 元素

所以用户输入的内容用 textContent 填是安全的。

4append：放进父元素，这才看得见

父元素.append(子元素) 把子元素挂到父元素下面。 做完这一步，页面上才出现它。

append.js复制
// ① 找到父元素
var panel = document.getElementById("panel");

// ② 造一个子元素
var p = document.createElement("p");
p.textContent = "忘情牛肉面";

console.log(p.isConnected);    // false —— 还没放

// ③ 放进去
panel.append(p);

console.log(p.isConnected);    // true —— 已经在页面上了
console.log(panel.childNodes.length);   // 1
控制台输出
false
true
1

三步连起来就是这一篇的骨架：找到父元素 → 造子元素 → append。

append 能接什么

append 比想象中宽松 —— 字符串也能直接给，它会自动变成文字：

append 的几种给法复制
var box = document.createElement("div");

box.append("直接给字符串");              // 自动变成文字节点
box.append(document.createElement("b"));  // 给元素
box.append("x", document.createElement("b"), "y");
                              // 一次给多个，按顺序放

console.log(box.childNodes.length);   // 5
控制台输出
5
append 是「移动」，不是「复制」

一个节点只能有一个父节点。把已经在 A 里的节点 append 给 B， 它就从 A 搬走了：

var A = document.createElement("div");
var B = document.createElement("div");
var kid = document.createElement("span");

A.append(kid);
B.append(kid);        // 从 A 移到 B，不是复制一份

console.log(A.childNodes.length);   // 0
console.log(B.childNodes.length);   // 1

想真正复制一份，得先 kid.cloneNode(true) 再 append 克隆体。

老代码里的 appendChild

你会在旧代码里看到 appendChild。它和 append 干的是同一件事，但只收节点 —— 给字符串直接抛错：

box.appendChild("文字");   // 💥 TypeError

另一个区别：appendChild 返回被插入的节点， append 返回 undefined。 新代码用 append 就行，更好写。

5串起来：一个能跑的小例子

demo.html复制
<!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="utf-8"></head>
<body>
  <h1>角色面板</h1>
  <div id="panel"></div>
  <script src="demo.js"></script>
</body>
</html>
demo.js复制
var names = ["忘情牛肉面", "奶蛙", "University of Naiwa"];

var panel = document.getElementById("panel");

for (var i = 0; i < names.length; i++) {
    var p = document.createElement("p");   // 造
    p.textContent = names[i];                    // 填
    panel.append(p);                             // 放
}
页面上出现
角色面板

忘情牛肉面
奶蛙
University of Naiwa
为什么这个循环每轮都要重新 createElement

因为 append 是移动。如果在循环外只造一个 p， 那么第二轮 append 会把它从第一行的位置搬走 —— 最后页面上只剩一行。

「每轮造一个新的」是这里的固定套路。第 4 节那条「移动不是复制」 说的就是这件事。

6重点：这和 Qt 的 addWidget 是一回事

如果你写过 Qt，上面那三步其实一点也不陌生 —— 把它和 Qt 的写法并排看：

Qt（C++）
// ① 拿到容器
auto *panel = findChild<QWidget*>("panel");

// ② 造一个子控件
auto *label = new QLabel("忘情牛肉面");

// ③ 放进容器
panel->layout()->addWidget(label);
DOM（JS）
// ① 拿到父元素
var panel = document.getElementById("panel");

// ② 造一个子元素
var p = document.createElement("p");
p.textContent = "忘情牛肉面";

// ③ 放进父元素
panel.append(p);

两边都是同一个动作：容器.add(子件)。

关键认识：把 DOM 元素当成 Widget 看

如果将要添加的元素视作组件（Widget），那么「向父元素添加子元素」 和 Qt 的 addWidget 完全相同。

都是：先有容器 → 再造子件 → 把子件交给容器托管。 子件从交出那一刻起就归容器管，显示、位置、生命周期都跟着容器走。

逐项对照

要做的事QtDOM（JS）
造一个组件new QLabel("…") document.createElement("p")
设它显示的文字label->setText(…) p.textContent = …
加进容器 layout->addWidget(label) parent.append(p)
按名字找控件findChild<QWidget*>("panel") document.getElementById("panel")
给组件起个名字/标识setObjectName("panel") el.id = "panel"
加样式类setProperty("class", …) + QSS el.className = "name big"
子件构造后立刻可见？不会，要 addWidget 之后才进布局 不会，要 append 之后才进文档
一处不同：Qt 有独立的 layout，DOM 没有

Qt 里 addWidget 是加在 layout 上， widget 自己不管怎么摆孩子。DOM 里没有 layout 这个角色 —— 元素自己既是 widget，又是容器，摆放交给 CSS（flex / grid）。

所以 Qt 那句是 panel->layout()->addWidget(x)， DOM 这句是 panel.append(x)。少了一层，但意思一样： 「把这个子件交给这个容器」。

一个对应不上的地方：生命周期

Qt 里 addWidget 之后，widget 归父控件所有（父子对象树）， 父对象析构时会一起 delete。DOM 里把节点 append 进去， 它也只是「挂在文档上」—— 想移除要显式 remove()， 没有自动回收那一套。

「谁来释放」这件事，两边答案不同。 类比能帮你快速上手，但别把它当成完全等价。

7多行代码里常见的写法

把「造 + 填 + 放」写成一个小函数，是实际项目里最常见的整理方式：

makeRow.js复制
// 造一个 <p class="row">文字</p> 并放进 parent
function addRow(parent, text) {
    var p = document.createElement("p");
    p.className = "row";
    p.textContent = text;
    parent.append(p);
    return p;              // 返回它，方便以后再改
}

var panel = document.getElementById("panel");
addRow(panel, "忘情牛肉面");
addRow(panel, "奶蛙");
为什么把 parent 当参数传

这样这个函数不关心父元素是谁 —— 同一个 addRow 可以往任何容器里加行。和 Qt 里写 void addRow(QWidget *parent, …) 是一个思路。

8一页速查

三个函数

写法返回说明
document.getElementById("panel") 元素 或 null按 id 找，区分大小写
document.createElement("p") 新元素只在内存里，还没显示
parent.append(child) undefined放进去，这才显示；是移动

三句话

① DOM 树 = 浏览器心里的结构 —— 每个标签是一个节点，节点之间有父子关系，每个节点最多一个父亲。
② 找父 → 造子 → append —— 造出来不等于显示出来，append 之后才在页面上。
③ 元素就是 Widget —— parent.append(child) 与 Qt 的 addWidget 是同一个动作：把子件交给容器。

最容易踩的三个坑

现象原因
造了元素但页面没变化 忘了 append（或 append 给了错的父元素）
循环加了很多行，却只看到一行 在循环外只 createElement 了一次 —— append 是移动，要每轮造新的
TypeError: Cannot read properties of null getElementById 没找到，返回了 null； 取到之后要先判空
一句话

页面上的一切都可以用这三个函数造出来。 先找到要往哪儿放，再造出要放的东西，最后 append 进去 —— 和 Qt 里「造控件、addWidget」是同一套动作。

9动手做

五分钟练习
  1. 写一个只含 <div id="panel"></div> 的 HTML， 外加一个空的 demo.js。

  3. 刷新页面确认出现三行。
