这一篇很短。要讲的只有一件事：你天天写的 arr[i]， 其实是一种「语法糖」 —— 编译器会把它翻译成一串不加糖也成立的写法。

理解这一点之后，你再看别的语言里各种「方便的写法」， 就能一眼认出哪些是糖、哪些是真本事。

一句话

语法糖（syntactic sugar）= 不增加任何新能力的、纯为顺手的写法。

它能被翻译掉：把糖去掉，用更朴素的写法表达同一件事， 程序的行为完全不变。

1从 arr[i] 说起

先看一段最普通的代码：

sugar1.cpp —— 两种写法，一个意思复制
#include <iostream>

int main() {
    int arr[5] = {10, 20, 30, 40, 50};

    std::cout << arr[2]       << "\n";   // 30
    std::cout << *(arr + 2)   << "\n";   // 30  ← 完全一样
}
输出
30
30

这两行是等价的。C++ 标准明确规定：

糖 arr[i]
脱糖 *(arr + i)  // 先算地址，再取值

也就是说：arr[i] 只是 *(arr + i) 的简写。 编译器在编译时就把前者换成了后者，机器码里没有任何「下标」这种操作。

右侧那个 i 还能反过来

因为加法可以交换，*(arr + i) 和 *(i + arr) 一样。 所以 arr[2] 和 2[arr] 都能编译通过，结果相同。

这不是技巧，是证据 —— 它证明 [] 真的只是加法加解引用， 没有任何额外的语义。

看地址更直观

sugar2.cpp —— 下标就是地址偏移复制
#include <iostream>

int main() {
    int arr[5] = {10, 20, 30, 40, 50};

    std::cout << "arr     = " << arr       << "\n";
    std::cout << "arr + 2 = " << (arr + 2) << "\n";
    std::cout << "相差字节 = " << (char*)(arr + 2) - (char*)arr << "\n";
}
输出
arr     = 0x7ffd1c2a3b60
arr + 2 = 0x7ffd1c2a3b68
相差字节 = 8      ← 2 个 int，每个 4 字节

arr + 2 不是「地址加 2」，而是往后挪 2 个元素 （这里挪了 8 字节）。这是指针算术的规则，也是 arr[i] 能成立的前提。

小结：arr[i] 和 *(arr + i) 是同一件事的两种写法。 前者是糖，后者是脱糖后的样子。糖让代码短，脱糖让语义清楚。

2二维数组：arr[i][j] 脱糖成什么

一维的规则可以直接套两层。先看结论：

糖 arr[i][j]
先脱一层 (*(arr + i))[j]  // arr[i] 就是 *(arr + i)
再脱一层 *(*(arr + i) + j)

也就是说：两次 [] 等于两次「加偏移 + 取值」。

sugar3.cpp —— 二维的三种等价写法复制
#include <iostream>

int main() {
    int a[2][3] = { {1, 2, 3},
                   {4, 5, 6} };

    std::cout << a[1][2]             << "\n";   // 6
    std::cout << (*(a + 1))[2]       << "\n";   // 6
    std::cout << *(*(a + 1) + 2)     << "\n";   // 6
}
输出
6
6
6

三行完全等价。中间那行是关键 —— 它说明了各部分的角色：

a 不是「二维数组的指针」，而是指向第一行的指针； 它的元素类型是「含 3 个 int 的数组」
a + 1 往后挪一整行（3 个 int = 12 字节），不是挪一个 int
*(a + 1) 拿到第 2 行本身。它的类型退化成 int*， 于是又能套一次一维的规则
(*(a + 1))[2] 在这一行里取下标 2 —— 就是第二层糖
所以「二维数组」在内存里是一维的

int a[2][3] 实际就是连续的 6 个 int，一行挨着一行。 a[i][j] 之所以能定位到正确的格子，靠的正是 「挪 i 整行 + 挪 j 个元素」这两次偏移。

没有「二维」这种东西 —— 只有一维内存 + 两层语法糖。

a[0][0]
1
a[0][1]
2
a[0][2]
3
a[1][0]
4
a[1][1]
5
a[1][2]
6
小结：arr[i][j] = *(*(arr + i) + j)。 两层糖，两次「加偏移 + 取值」。

3为什么要设计语法糖

既然 *(arr + i) 才是真身，为什么还要造一个 arr[i]？

三个理由
  1. 更贴近人的想法。人想的是「第 i 个格子」， 不是「基地址加 i 再取值」。arr[i] 直接对应前者。
  2. 少犯错误。*(arr + i) 里那个 * 和括号都不能漏。 写 *arr + i 意思就完全变了（取第一个元素再加 i）。 arr[i] 没有这个坑。
  3. 把「怎么算」交给编译器。不同机器的指针大小、对齐方式不一样， arr[i] 让编译器按目标平台去算偏移，写代码的人不用管。

第一个理由最重要。语法糖的全部意义在于「让人写起来像他想的那样」， 而不是给机器增加能力。

怎么判断一个语法是不是糖

问一句：能不能用更朴素的写法表达同一件事，而且行为完全一样？

  • 能 → 它是糖（arr[i]、a += 1、for...in）；
  • 不能 → 它带来了新能力，不是糖 （class、template、函数重载 —— 这些朴素写法做不到）。

糖是写法上的发明，不是能力上的发明。

4这是一个跨语言的概念

语法糖不是 C 或 C++ 的特色。只要一门语言想让人写得舒服， 它就一定会造糖。下面是同一件事在不同语言里的糖与脱糖：

语言糖脱糖后大致是什么
C / C++arr[i] *(arr + i)
C / C++a += 1 a = a + 1
C / C++p->x (*p).x
Pythona, b = b, a 用临时变量交换
Python[x*x for x in xs] 建空表 + for + append
Pythond['k'] d.__getitem__('k')
JavaScripta?.b a === null || a === undefined ? undefined : a.b
JavaScript`hi ${n}` 'hi ' + n
Javafor (T x : list) 用迭代器手写 while
Shell$((a + b)) 交给 expr 之类去算
两个共同的规律
  1. 糖只影响「写」，不影响「是什么」。 脱糖之后，语言的能力没有任何损失。
  2. 糖总是把常用的模式打包。 arr[i] 打包「基址 + 偏移」， a += 1 打包「自己加自己」， a, b = b, a 打包「交换」。
反过来说：认出糖，就抓住了语言的骨架

一门语言看起来花哨，往往是因为糖多。把糖一层层脱掉， 剩下的那套东西通常很小 —— 而且各语言之间惊人地相似。

所以「这是糖还是真本事」是个很值的问题： 它决定你是在学一种写法，还是在学一个概念。

5边界：什么时候不能说「这只是糖」

「语法糖」这个词很容易被用过头。有两种情况要区分开。

① 糖可以被重新定义 —— 那时它就不只是糖了

C++ 允许给自定义类型定义 operator[]。 这时 x[i] 不再对应任何「指针加法」，而是调用你自己写的函数：

sugar4.cpp —— 自己定义的 []复制
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> age;

    age["Tom"] = 30;      // 这里的 [] 不是指针加法
    std::cout << age["Tom"] << "\n";   // 30
}
输出
30

age["Tom"] 背后是在树里查找，找不到还会插入一项 —— 和 *(age + i) 毫无关系。

同一对符号，两种身份

[] 用在内置数组上时，它是 *(a + i) 的糖；

[] 用在类类型上时，它是一次函数调用（operator[]）。

看起来一样，本质完全不同。这也是为什么「arr[i] 就是指针加法」 这句话只对数组成立，不能到处套。

② 有些「糖」其实带着额外语义

数组作为参数 函数参数写 void f(int a[5])， 其实等价于 void f(int* a) —— 那个 5 被忽略。 这不是糖，是会误导人的写法
越界不检查 arr[100] 会照常编译、照常算出地址 —— 因为脱糖之后只是一次加法和一次取值，没有任何边界检查。 糖在这里没有保护你
小结：判断是不是糖，要看用在什么类型上。 内置类型上多半是糖，类类型上往往是函数调用。

6一页速查

脱糖表

糖 arr[i]
脱糖 *(arr + i)
糖 arr[i][j]
脱糖 *(*(arr + i) + j)

四句话

① 语法糖 = 不增加能力、纯为顺手的写法，能被翻译成更朴素的等价形式。
② arr[i] 是 *(arr + i) 的糖； arr[i][j] 是 *(*(arr + i) + j) 的糖 —— 两层糖。
③ 设计初衷是让人写起来像他想的那样，同时少犯错、把平台细节交给编译器。
④ 这是跨语言的概念 —— 每门语言都在造糖；认出糖，就抓住了语言的骨架。

判断口诀

三问
  1. 能脱糖吗？能用朴素写法表达同一件事、行为不变 → 是糖。
  2. 用在什么类型上？内置类型 → 多半是糖；类类型 → 多半是函数调用。
  3. 带来新能力了吗？带来了 → 不是糖（class、template）。
